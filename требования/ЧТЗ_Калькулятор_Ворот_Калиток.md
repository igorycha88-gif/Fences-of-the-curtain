## 1. Цели и задачи

### 1.1 Бизнес-цель
Дать клиенту возможность рассчитать стоимость только ворот и/или калиток (с монтажом или без), без необходимости рассчитывать забор.

### 1.2 Пользовательская ценность
- Клиенту, которому нужны только ворота/калитка, не нужно заполнять лишние параметры забора
- Простой и понятный сценарий: выбрал высоту → добавил ворота/калитки → увидел стоимость
- Возможность оценить стоимость с монтажом и без

### 1.3 Метрики успеха
- Новый калькулятор доступен на `/calculator/gates`
- Расчёт корректен — совпадает с результатами ворот/калиток в калькуляторе забора при тех же параметрах
- Можно оформить заявку из результата расчёта

## 2. Функциональные требования

### 2.1 User Stories

**US-1: Выбор калькулятора ворот/калиток**
- GIVEN: Пользователь находится на странице `/calculator`
- WHEN: Видит три карточки калькуляторов
- THEN: Третья карточка «Ворота и калитки» ведёт на `/calculator/gates`

**US-2: Расчёт ворот**
- GIVEN: Пользователь на `/calculator/gates`
- WHEN: Указал высоту, добавил ворота (тип, ширина), нажал «Рассчитать»
- THEN: Видит подобранные ворота из справочника + стоимость + стоимость монтажа (если включён)

**US-3: Расчёт калитки**
- GIVEN: Пользователь на `/calculator/gates`
- WHEN: Указал высоту, добавил калитку (ширина), нажал «Рассчитать»
- THEN: Видит подобранную калитку из справочника + стоимость + стоимость монтажа (если включён)

**US-4: Несколько ворот/калиток**
- GIVEN: Пользователь на `/calculator/gates`
- WHEN: Добавил до 2 ворот и/или до 2 калиток
- THEN: Каждая позиция рассчитывается отдельно, в итоге — сумма всех позиций

**US-5: Монтаж — переключатель**
- GIVEN: Пользователь на `/calculator/gates`
- WHEN: Включает/выключает чекбокс «Нужен монтаж»
- THEN: В результате монтажные работы добавляются/убираются из итога

**US-6: Оформление заявки**
- GIVEN: Расчёт выполнен успешно
- WHEN: Пользователь нажимает «Оформить заявку»
- THEN: Открывается форма заявки (переиспользуется OrderForm), заявка создаётся с привязкой к расчёту

**US-7: Номенклатура не найдена**
- GIVEN: Для указанных параметров нет подходящих ворот/калиток в справочнике
- WHEN: Пользователь нажимает «Рассчитать»
- THEN: Показывается понятное сообщение об ошибке + кнопка «Индивидуальный расчёт»

### 5.3 Валидация формы

| Поле | Правила | Сообщение об ошибке |
|------|---------|-------------------|
| Высота | Обязательное, число, 1.5–3.0, шаг 0.1 | «Укажите высоту от 1.5 до 3.0 м» |
| Ворота: тип | Обязательное при наличии ворот | «Выберите тип ворот» |
| Ворота: ширина | Обязательное, 2.0–6.0 | «Укажите ширину от 2.0 до 6.0 м» |
| Калитка: ширина | Обязательное, 0.8–1.5 | «Укажите ширину от 0.8 до 1.5 м» |
| Автоматика ID | Обязательное если hasAutomation=true | «Выберите тип автоматики» |
| Минимум 1 позиция | Хотя бы 1 ворота или 1 калитка | «Добавьте хотя бы одни ворота или калитку» |

### 5.4 Обработка ошибок

- NO_GATE_FOUND → показать сообщение «Для выбранных параметров ворота не найдены. Попробуйте изменить ширину или тип.» + кнопка «Запросить индивидуальный расчёт»
- NO_WICKET_FOUND → аналогично для калитки
- NO_AUTOMATION_FOUND → показать предупреждение, убрать автоматику из расчёта

#### TASK-BCK-002: Сервис расчёта gateEstimateService

**Направление**: Backend
**Приоритет**: High
**Зависимости**: TASK-BCK-001

**Описание**:
Создать сервис расчёта стоимости ворот и калиток. Переиспользует существующие lookup-сервисы.

**Критерии приёмки**:
- [ ] Файл `src/services/calculator/gateEstimateService.ts` создан
- [ ] Функция `calculateGateEstimateCore(input, metadata)` выполняет расчёт
- [ ] Для каждого элемента gates[] вызывается `findGateByTypeAndLength()` из `gateLookup.ts`
- [ ] Для каждого элемента wickets[] вызывается `findWicketByHeightAndWidth()` из `wicketLookup.ts`
- [ ] Для SLIDING ворот с автоматикой вызывается `findAutomationById()`

- [ ] Если needsInstallation=false: монтажные работы НЕ добавляются
- [ ] Итог items[] содержит: gates, wickets, automation, installation (если включён)
- [ ] Totals: materials = сумма ворот + калиток + автоматики; installation = сумма монтажных работ
- [ ] Результат сохраняется в БД (модель GateEstimate)
- [ ] Корректная обработка ошибок (NO_GATE_FOUND, NO_WICKET_FOUND)

**Технические детали**:
- Файлы: `src/services/calculator/gateEstimateService.ts`
- Переиспользуется: `gateLookup.ts`, `wicketLookup.ts`, `automationLookup.ts`, `workService.ts`
