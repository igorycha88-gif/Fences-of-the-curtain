# ЧТЗ: Оптимизация скорости загрузки страниц

## Проблема
Страницы приложения загружаются медленно (до 928ms TTFB на /faq, 465ms на /blog) из-за:
1. Тройного дублирования `/api/contact-info` на каждой странице
2. Отсутствия кэширования contact-info в Redis
3. Двойного запроса данных FAQ (серверный layout + клиентский fetch)
4. Клиентских водопадов запросов на Blog и FAQ
5. `force-dynamic` на корневом layout

## Критерии приёмки

### AC-1: Contact-info — единственный запрос
- На каждой странице `/api/contact-info` вызывается **ровно 1 раз** (Provider + Context)
- Header, Footer, ContactPhoneBadge используют контекст, а не fetch
- Таймаут — 5 секунд, fallback на статические данные

### AC-2: Contact-info кэшируется в Redis
- Redis-кэш с TTL 300 секунд (5 минут)
- При обновлении через админку — инвалидируется

### AC-3: FAQ — серверный рендеринг без дублирования
- FAQ layout и page используют один источник данных
- TTFB `/faq` < 200ms

### AC-4: Blog — серверный рендеринг
- Blog page — серверный компонент с прямым Prisma-запросом
- TTFB `/blog` < 200ms

### AC-5: Homepage — оптимизированные запросы
- Не более 2 API-вызовов на первой загрузке (yandex-reviews + analytics)
- Contact-info через Provider (не отдельный fetch)

### AC-6: force-dynamic убран из корневого layout
- Только на тех маршрутах, где реально нужен динамический рендеринг
