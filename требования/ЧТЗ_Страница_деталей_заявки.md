## Версия: 1.0
## Дата: 2026-03-17
## Автор: AI-аналитик
## Приоритет: High
## Статус: Draft

---

## 1. Цели и задачи

### 1.1 Бизнес-цель
Создать единую точку входа для просмотра всей информации по заявке. Менеджер должен видеть полную картину: кто клиент, что он хочет, история работы с ним, и полная смета — всё на одной странице без переключений.

### 1.2 Пользовательская ценность
- **Менеджер**: Видит всю информацию в одном месте, не теряет контекст, быстрее принимает решения
- **Руководитель**: Может быстро оценить статус работы с клиентом и качество обслуживания

### 1.3 Метрики успеха
- Время на просмотр полной информации по заявке: < 5 секунд
- Количество переключений между страницами: 0 (всё на одной странице)
- Полнота отображения данных: 100% информации из БД

### 2.2 User Stories

#### US-1: Просмотр данных клиента
**Как** менеджер,  
**Я хочу** видеть все контактные данные клиента в одном блоке,  
**Чтобы** быстро связаться с ним.

**Acceptance Criteria**:
```
Given я нахожусь на странице деталей заявки
Then вижу блок "Данные клиента"
And отображаются: ФИО, Телефон, Email (если есть), Комментарий
And телефон кликабелен (href="tel:...")
And email кликабелен (href="mailto:...")
And если email нет — поле не отображается
```

#### US-2: Просмотр статусов и истории
**Как** менеджер,  
**Я хочу** видеть текущий статус, ключевые поля и полную историю изменений,  
**Чтобы** понимать на каком этапе работа с клиентом.

**Acceptance Criteria**:
```
Given я нахожусь на странице деталей заявки
Then вижу блок "Статусы и история"
And отображается текущий статус с цветным бейджем
And отображаются ключевые поля:
    - Адрес замера (если есть)
    - Дата замера (если есть)
    - Назначенный менеджер (если есть)
    - Причина отмены (если статус CANCELLED)
    - Дата завершения (если статус COMPLETED)
And отображается timeline истории статусов (свернутый, можно развернуть)
And каждая запись истории содержит:
    - Дата и время
    - Автор изменения
    - Переход статуса
    - Заполненные поля при смене
```

#### US-3: Просмотр параметров забора
**Как** менеджер,  
**Я хочу** видеть параметры забора из расчета,  
**Чтобы** понимать что нужно клиенту.

**Acceptance Criteria**:
```
Given я нахожусь на странице деталей заявки
And у заявки есть связанный расчет (estimateId)
Then вижу блок "Параметры забора"
And отображаются:
    - Тип забора (из FenceType.name)
    - Длина и высота
    - Покрытие
    - Количество рядов лаг
    - Ворота (тип и ширина, если есть)
    - Калитка (ширина, если есть)
    - Город (если есть)
When estimateId отсутствует
Then блок "Параметры забора" не отображается
And показывается сообщение "Расчет не найден"
```

#### US-4: Просмотр полной сметы
**Как** менеджер,  
**Я хочу** видеть полную смету в таком же формате как во вкладке "Расчеты",  
**Чтобы** понимать стоимость и состав работ.

**Acceptance Criteria**:
```
Given я нахожусь на странице деталей заявки
And у заявки есть связанный расчет (estimateId)
Then вижу блок "Смета"
And смета отображается в том же формате что и во вкладке "Расчеты":
    - Раздел "Материалы" с позициями
    - Раздел "Работы" с позициями
    - Итоговые суммы
    - Гранд тотал
When estimateId отсутствует
Then блок "Смета" не отображается
```

#### US-5: Просмотр закупочных цен (только ADMIN)
**Как** администратор,  
**Я хочу** видеть закупочные цены и маржу,  
**Чтобы** анализировать рентабельность.

**Acceptance Criteria**:
```
Given я нахожусь на странице деталей заявки
And моя роль = ADMIN
And у заявки есть связанный расчет (estimateId)
Then в блоке "Смета" вижу:
    - Закупочная стоимость (итого)
    - Маржа в рублях
    - Маржа в процентах
When моя роль ≠ ADMIN
Then закупочные цены и маржа не отображаются
```

#### US-6: Просмотр технической информации (только ADMIN)
**Как** администратор,  
**Я хочу** видеть техническую информацию о создании заявки,  
**Чтобы** анализировать источник и отладку.

**Acceptance Criteria**:
```
Given я нахожусь на странице деталей заявки
And моя роль = ADMIN
Then вижу блок "Техническая информация"
And отображаются:
    - ID расчета (estimateId)
    - Кто создал расчет (Клиент / Имя менеджера)
    - IP адрес
    - User Agent (человекочитаемый)
    - Session ID (обрезанный)
When моя роль ≠ ADMIN
Then блок "Техническая информация" не отображается
```

#### US-7: Смена статуса из страницы деталей
**Как** менеджер,  
**Я хочу** изменить статус заявки прямо со страницы деталей,  
**Чтобы** не переходить на другую страницу.

**Acceptance Criteria**:
```
Given я нахожусь на странице деталей заявки
When кликаю на dropdown "Статус"
Then вижу доступные статусы для перехода
When выбираю новый статус
Then открывается модальное окно смены статуса (из ЧТЗ_Управление_статусами_заявок)
When сохраняю
Then статус обновляется
And история обновляется
And страница перезагружается с новыми данными
```

#### US-8: Переход на страницу деталей из списка заявок
**Как** менеджер,  
**Я хочу** кликнуть на ID заявки в списке и попасть на страницу деталей,  
**Чтобы** просмотреть полную информацию по заявке.

**Acceptance Criteria**:
```
Given я нахожусь на странице /admin/orders (список заявок)
When кликаю на ID заявки (например, #clt123abc)
Then открывается страница /admin/orders/{id}
And отображается полная информация по заявке
And ID заявки кликабелен и визуально выделен (синий цвет, подчеркивание при hover)
```

#### US-9: Навигация к смете во вкладке "Расчеты"
**Как** менеджер,  
**Я хочу** открыть смету в отдельной вкладке "Расчеты",  
**Чтобы** работать с ней в контексте всех расчетов.

**Acceptance Criteria**:
```
Given я нахожусь на странице деталей заявки
And у заявки есть estimateId
When кликаю "Открыть в Расчетах"
Then открывается страница /admin/estimates?open={estimateId}
And модальное окно сметы автоматически открывается
```

## 3. Нефункциональные требования

### 3.1 Производительность
- Загрузка страницы: < 500ms
- Загрузка сметы: < 300ms
- Поддержка до 100 записей в истории статусов

### 3.2 Безопасность
- Страница доступна только авторизованным пользователям (ADMIN, MANAGER)
- Закупочные цены и техническая информация — только для ADMIN
- Логирование просмотра заявки

### 3.3 Масштабируемость
- Lazy loading для истории статусов (если > 20 записей)
- Пагинация не требуется (одна заявка)

### 5.4 Адаптивность

- Desktop (> 1024px): блоки в 2 колонки (клиент + статусы, параметры + смета)
- Tablet (768-1024px): блоки в 1 колонку
- Mobile (< 768px): компактный вид, смета сворачивается

### 5.5 Обработка ошибок

- Если estimateId есть, но расчет не найден → сообщение "Расчет не найден" в блоке параметров
- Если заявка не найдена → редирект на /admin/orders с toast "Заявка не найдена"
- При ошибке загрузки → toast "Ошибка загрузки данных" + кнопка "Повторить"
