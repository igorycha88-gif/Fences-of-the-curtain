## 2. Критерии приёмки (Acceptance Criteria)

### AC-1: Бэкап до деплоя
- [ ] Создан бэкап БД перед миграциями
- [ ] Создан бэкап `.env` файла
- [ ] Сохранён текущий коммит для отката

### AC-2: Миграции БД
- [ ] Все 8 новых миграций применены успешно
- [ ] Миграция `20260324233000_add_panel3d_model` выполнена
- [ ] Миграция `20260405000000_add_multi_estimate_tables` выполнена
- [ ] Проверка целостности данных прошла успешно

### AC-3: Полная пересборка Docker
- [ ] Выполнена `docker compose build --no-cache` для ВСЕХ сервисов
- [ ] Выполнен `docker compose up -d --force-recreate` для ВСЕХ сервисов
- [ ] Healthcheck всех сервисов пройден

### AC-4: Доступность приложений
- [ ] Next.js приложение доступно на порту 3000
- [ ] PostgreSQL работает и принимает соединения
- [ ] Redis подключён и работает (проверка через PING)
- [ ] Grafana доступна на порту 3002

### AC-5: Проверка ошибок
- [ ] Логи PM2 не содержат критических ошибок
- [ ] Нет `NOAUTH` ошибок от Redis
- [ ] Нет `ECONNREFUSED` ошибок
- [ ] Нет `fatal` или `panic` ошибок

### AC-6: Функциональные проверки
- [ ] Healthcheck endpoint возвращает 200 OK
- [ ] Авторизация работает
- [ ] Создание заказа работает
- [ ] Админ-панель доступна

### AC-7: План отката
- [ ] Скрипт отката готов к использованию
- [ ] Бэкапы сохранены в `/root/backups/`
- [ ] Инструкция по откату доступна

## 4. План отката (Rollback Plan)

### Триггеры отката:
1. Критическая ошибка при миграции БД
2. Healthcheck не проходит после деплоя
3. Логи содержат критические ошибки
4. Функциональные проверки не проходят

### Шаги отката:
1. Остановка PM2: `pm2 stop fences-app`
2. Восстановление кода: `git reset --hard 7890f4b`
3. Восстановление БД из бэкапа
4. Восстановление `.env`
5. `npm ci` + `npx prisma generate` + `npm run build`
6. `pm2 start fences-app`
7. Проверка здоровья

### Автоматический скрипт отката:
`scripts/rollback-master2-emergency.sh`

## 5. Риски и митигации

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| Ошибка миграции БД | Средняя | Высокое | Бэкап БД, тестовые миграции, проверка схемы |
| Redis NOAUTH ошибка | Низкая | Высокое | Полная пересборка всех контейнеров (Правило 6) |
| Ошибка сборки Docker | Низкая | Среднее | Проверка Dockerfile, --no-cache |
| Сломанные API endpoints | Средняя | Среднее | Тестирование после деплоя |
| Ошибка бэкапа | Низкая | Критическое | Проверка бэкапа перед миграцией |

## 8. Порядок выполнения

1. Проверить sshpass и доступ к VPS
2. Получить текущий коммит на проде
3. Создать бэкапы (БД, .env)
4. Checkout master2
5. npm install --legacy-peer-deps
6. npx prisma generate
7. npx prisma migrate deploy
8. npm run build
9. ПОЛНАЯ пересборка Docker (--no-cache + --force-recreate)
10. pm2 restart fences-app
11. Проверить PM2 статус
12. Проверить логи на ошибки
13. Проверить healthcheck
14. Создать скрипт отката

## 9. Команды проверки после деплоя

```bash
# PM2 статус
pm2 status

# Логи (последние 50 строк)
pm2 logs fences-app --lines 50

# Docker статус
docker compose ps

# Проверка ошибок в логах
docker compose logs --tail=50 | grep -E "error|fatal|NOAUTH|ECONNREFUSED|panic"

# HTTP healthcheck
curl -f http://localhost:3000/api/health

# Redis ping
redis-cli -a "g3xVlty76Op1vIbTuwy+8M+0ZUXx4XgtQX2+YrTtbLY" ping
```

## 12. Успех деплоя

Деплой считается успешным, если:
1. Все критерии приёмки (AC) выполнены
2. Нет критических ошибок в логах
3. Healthcheck возвращает 200 OK
4. Все сервисы Docker в состоянии healthy
5. PM2 статус: online

При несоответствии — автоматический откат.
