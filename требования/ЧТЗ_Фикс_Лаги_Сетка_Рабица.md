# ЧТЗ: Убрать лаги из расчёта забора «Сетка-рабица»

**Тип:** баг-фикс (малая задача)
**Маршрут:** Аналитик → Разработчик → Тестировщик → DevOps
**Дата:** 2026-09-22

## 1. Описание проблемы

При расчёте забора типа **«Сетка-рабица»** в смету включаются **лаги** (поперечные трубы).
Для данного типа забора лаги конструктивно не нужны: сетка натягивается между столбами
(крепится к столбам и натяжной проволоке/крючкам), поперечные лаги не используются.

Логи не должны попадать ни в items сметы, ни в итоговую стоимость. Дополнительно:

- В калькуляторе на фронте для рабицы показывается селектор «Количество лаг» — лишний параметр.
- В API `lagRows` является обязательным для всех типов, кроме 3D-панелей — для рабицы должен быть необязательным.
- В админке (карточка заказа, `FenceParameters`) строка «Лаги: N ряда» показывается и для рабицы.

## 2. Что меняем

### Backend — `src/services/calculator/fenceEstimateService.ts`

1. **Валидация** (строка ~175): `lagRows` не требуется для `3D-панели` И `Сетки-рабицы`.
2. **Расчёт лаг** (строка ~380): `lagsResult = null` для `Сетки-рабицы` (как для `3D-панели`).
3. **Монтажная фурнитура, ветка mesh** (строка ~410): передавать `lagTypeId` только если
   `lagsResult` существует (иначе краш на `lagsResult!.nomenclatureId`).
   Фурнитура по ссылкам POST и MESH продолжает считаться как раньше.
4. Логирование: зафиксировать в логе, что для рабицы лаги пропущены.

### Frontend — `src/app/(public)/calculator/fence/page.tsx`

1. Селектор «Количество лаг» скрывается для `Сетка-рабица` (как для `3D-панели`).
2. В `calculateSingle` и `calculateAll` `lagRows` НЕ отправляется для `Сетка-рабица`.

### Admin — `src/components/admin/Orders/FenceParameters.tsx`

1. Блок «Лаги: N ряда» скрывается, если тип забора — `Сетка-рабица`.

## 3. Критерии приёмки

- [ ] `POST /api/calculator/fence/estimate` с типом «Сетка-рабица»: в `items` НЕТ элемента с `category === 'lags'`; `lagsTotal = 0`.
- [ ] Запрос рабицы БЕЗ поля `lagRows` не возвращает `MISSING_LAG_ROWS` (200/успешный расчёт).
- [ ] Запрос рабицы С полем `lagRows` (старые клиенты) — лаги всё равно не считаются (обратная совместимость).
- [ ] Расчёты профнастила, евроштакетника, 3D-панелей не изменились (лаги считаются как раньше для первых двух).
- [ ] Монтажная фурнитура для рабицы (POST/MESH) считается без ошибок.
- [ ] UI калькулятора: для рабицы нет селектора «Количество лаг»; для остальных типов — есть.
- [ ] Админка: в параметрах заказа-рабицы нет строки «Лаги».
- [ ] Автотесты: happy path (рабица без лагов) + регрессия (профнастил с лагами) + валидация (рабица без lagRows).
