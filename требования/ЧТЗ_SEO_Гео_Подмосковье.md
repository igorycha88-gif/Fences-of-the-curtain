## 1. Цели и задачи

### 1.1 Бизнес-цель

Вывести сайт zabor-i-naves.ru в топ-3 Яндекса по гео-запросам востока, юго-востока и юга Московской области («забор из профнастила в Балашихе», «навес для машины в Раменском» и т.п.) и закрыть главный коммерческий кластер «навес под ключ цена». Сейчас гео-запросов в топе — 0, кликов — 0.

### 1.2 Пользовательская ценность

Житель города МО заходит из поиска на страницу своего города: видит цены с логистикой, районы выезда, сроки монтажа, FAQ и сразу уходит в калькулятор/заявку.

### 1.3 Метрики успеха (из анализа, раздел 6)

- 30+ гео-запросов в топе Вебмастера за 3 мес; индексация гео-страниц 100% за 2 нед
- Клики 5–10/нед через 3 мес
- Технически: все гео-URL отдают 200, в sitemap, с корректным JSON-LD

## 3. Нефункциональные требования

### 3.1 Производительность

- Гео-страницы — ISR (`revalidate = 86400`), без запросов к БД кроме блока портфолио (3–6 свежих, один Prisma-запрос с `active: true`, `take: 6`)
- Справочник городов — статический TS-модуль, импортируется напрямую (0 запросов)
- Метрики Core Web Vitals не деградируют: текстовые секции, без новых тяжёлых клиентских скриптов (единственный client-компонент — FAQ-аккордеон)

### 3.2 Безопасность

- Никаких секретов; телефон/email — только уже публичные из BUSINESS_INFO
- Служебные страницы не индексируются (не требуется — всё публичное)
- Slug валидируется по справочнику (unknown → 404, никакого fallback-рендера)

### 3.3 SEO (анти-дорвей — критично!)

- ≥30% уникального текста на город: `localContext` (2–3 абзаца: расстояние, шоссе, время выезда, местные реалии) + уникальные `districts` + город-специфичные FAQ
- Шаблонный текст варьируется через поля (направление, шоссе, дачность) — не «голая» подстановка названия
- Одна богатая страница на город, БЕЗ матрицы услуга×город
- canonical на саму страницу (через generatePageMetadata)
- Хлебные крошки + FAQPage + Service schema на каждой

### 3.4 Масштабируемость

- Добавление города волны N = одна запись в справочник `src/lib/geo/cities.ts` (страница, sitemap, перелинковка хаба подхватываются автоматически)

### 4.5 Ключевые архитектурные решения (ADR)

| # | Решение | Альтернатива | Почему |
|---|---------|--------------|--------|
| ADR-1 | Города в TS-справочнике `src/lib/geo/cities.ts` | Prisma-модель GeoPage | Контент волн определяется маркетингом, не админкой; версионирование в git; нулевая нагрузка на БД; добавление города = 1 запись |
| ADR-2 | Склонения `nameIn/nameAcc` вручную в данных | Библиотека склонений | 32 города — конечный контролируемый набор; библиотека (petrovich и пр.) = зависимость ради 64 строк |
| ADR-3 | Хабы и города в одном роуте `[slug]` с ветвлением | Отдельные роуты | Единый sitemap/404-паттерн, меньше дублей |
| ADR-4 | Страница «Навесы под ключ» статическая | PageContent + seed | SEO-страница не должна зависеть от состояния БД/сида; контент фиксирован |
| ADR-5 | Блок «Наши объекты» = свежие работы без привязки к городу | Миграция PortfolioItem.city | Миграция без данных бессмысленна; вынести в след. итерацию |
| ADR-6 | FAQ-аккордеон — новый лёгкий client-компонент | Переиспользовать FaqClient | FaqClient тащит H1 «Вопросы и ответы» + CTA — не встраивается в страницу |

## 8. Риски

| Риск | Митигация |
|------|-----------|
| Краулинговый бюджет мал (1–38 стр/сут) | Все URL в sitemap + индексная-хаб; переобход вручную после деплоя |
| Похожесть страниц → риск «дорвея» | ≥30% уникального localContext, вариативность шаблонов через поля, честные districts/FAQ |
| Локальный контент — стартовый черновик от ИИ | Владелец дополняет фактами (объекты, отзывы, реальные сроки) по мере появления — правка одного поля в справочнике |
