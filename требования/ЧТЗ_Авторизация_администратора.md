## 2. Цели и задачи

### 2.1 Бизнес-цель
Обеспечить безопасный доступ администраторов к административной панели через удобную кнопку входа, размещенную в футере главной страницы сайта.

### 2.2 Пользовательская ценность
Администраторы получают простой и быстрый способ авторизации для управления контентом и заявками на сайте.

### 2.3 Ключевые метрики успеха
- Время входа в систему < 3 секунд
- Успешная авторизация с валидными данными 100%
- Безопасность сессий (JWT)
- Удобный UI для входа

## 3. Требования к продукту

### 3.1 Функциональные требования

#### Публичная часть: Кнопка входа и форма авторизации

**User Story 1: Кнопка "Войти" в футере главной страницы**
*Как посетитель сайта, я хочу видеть кнопку "Войти" в футере главной страницы, чтобы получить доступ к административной панели.*

**Acceptance Criteria:**
- Кнопка "Войти" размещена в футере главной страницы (`/src/app/page.tsx`)
- Кнопка стилизована согласно дизайну сайта (серый фон футера, белый текст)
- При клике на кнопку выполняется переход на страницу входа `/admin/login`
- Кнопка видна на всех устройствах (адаптивная верстка)
- Кнопка имеет hover-эффект
- Кнопка доступна для всех посетителей

**User Story 2: Форма входа в систему**
*Как администратор, я хочу войти в систему используя email и пароль, чтобы получить доступ к административной панели.*

**Acceptance Criteria:**
- Форма входа содержит поля:
  - Email (тип email, обязательное)
  - Пароль (тип password, обязательное)
- Валидация на клиенте:
  - Email: проверка формата email
  - Пароль: минимум 6 символов
- При вводе некорректных данных показывается ошибка "Неверный email или пароль"
- При успешном входе перенаправляется на `/admin/dashboard`
- Пароль не отображается (masked input)
- Есть кнопка "Войти" с индикатором загрузки
- Отображаются тестовые данные для проверки:
  - admin@fences.ru / admin123
  - manager@fences.ru / manager123

**User Story 3: Защита маршрутов админки**
*Как администратор, я хочу чтобы защищенные маршруты были доступны только после авторизации, чтобы обеспечить безопасность.*

**Acceptance Criteria:**
- Все маршруты `/admin/*` защищены middleware или проверкой сессии
- При попытке доступа без авторизации перенаправляется на `/admin/login`
- Проверка сессии через NextAuth.js JWT strategy
- Сессия хранится в httpOnly cookies
- Время жизни сессии: 24 часа (настраиваемо)

**User Story 4: Выход из системы (Logout)**
*Как авторизованный администратор, я хочу выйти из системы, чтобы завершить работу.*

**Acceptance Criteria:**
- В админ-панели есть кнопка "Выйти"
- При клике выполняется `signOut()` из NextAuth.js
- После выхода перенаправляется на главную страницу или страницу входа
- Сессия удаляется из cookies
- Все защищенные маршруты становятся недоступны

### 3.2 Нефункциональные требования

#### Безопасность
- Пароли хешируются (в текущей реализации хранение в plaintext для MVP - требует улучшения)
- Сессии защищены JWT токенами
- httpOnly cookies для защиты от XSS
- CSRF защита (встроена в NextAuth.js)
- Rate limiting на endpoint `/api/auth/[...nextauth]` (10 запросов/мин)
- Логирование попыток входа (успешных и неудачных)
- Блокировка пользователя после 5 неудачных попыток входа

#### Производительность
- Время отклика на вход < 2 секунд
- Время перенаправления после входа < 1 секунда
- Размер cookies < 4KB

#### Масштабируемость
- Поддержка множества одновременных сессий
- Redis для хранения сессий (опционально в будущих итерациях)

#### Доступность
- Поддержка keyboard navigation
- ARIA labels для элементов формы
- Адаптивная верстка для мобильных устройств

### 4.3 Схема данных (использование существующих моделей)

Существующая модель User из Prisma Schema:
```prisma
model User {
  id        String   @id @default(cuid())
  email     String   @unique
  name      String?
  password  String   // В текущей реализации plaintext - требует улучшения
  role      Role     @default(MANAGER)
  phone     String?
  active    Boolean  @default(true)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  ordersAssigned Order[] @relation("AssignedOrders")
}

enum Role {
  ADMIN
  MANAGER
  CONTENT_MANAGER
}
```

**Примечание:** Пароли в текущей реализации хранятся в plaintext. Это временное решение для MVP. В будущих итерациях требуется внедрение хеширования паролей (bcrypt/argon2).

## 5. API спецификация

### 5.1 Авторизация (NextAuth.js)

#### POST /api/auth/signin
Вход в систему (обрабатывается NextAuth.js)

**Request (credentials provider):**
```json
{
  "email": "admin@fences.ru",
  "password": "admin123",
  "csrfToken": "..."
}
```

**Response 200 (успешный вход):**
```json
{
  "url": "/admin/dashboard"
}
```

**Response 401 (неверные данные):**
```json
{
  "error": "CredentialsSignin",
  "code": null,
  "status": 401
}
```

#### POST /api/auth/signout
Выход из системы

**Request:**
```json
{
  "csrfToken": "..."
}
```

**Response 200:**
```json
{
  "url": "/"
}
```

#### GET /api/auth/session
Получение текущей сессии

**Response 200 (авторизован):**
```json
{
  "user": {
    "id": "...",
    "email": "admin@fences.ru",
    "name": "Администратор"
  },
  "expires": "2026-03-04T10:00:00.000Z"
}
```

**Response 200 (не авторизован):**
```json
null
```

### 5.2 Валидация

#### Обязательные поля
- email: string, required, email format
- password: string, required, min 6 chars

#### Ограничения
- Email должен быть уникален (Prisma @unique)
- Пароль минимум 6 символов
- Пользователь должен быть активным (active = true)

2. Кликает на кнопку "Войти" в футере
3. Переходит на страницу входа `/admin/login`

1. Авторизованный пользователь в админ-панели
2. Кликает на кнопку "Выйти"
3. Выполняется выход

## Приложение А: Конфигурация NextAuth.js

### A.1 Переменные окружения

```bash
# .env.local
NEXTAUTH_URL="http://localhost:3000"
NEXTAUTH_SECRET="your-super-secret-key-min-32-chars"

# Production
NEXTAUTH_URL="https://yourdomain.com"
NEXTAUTH_SECRET="production-secret-key-min-32-chars"
```

**Примечание:** NEXTAUTH_SECRET должен быть сгенерирован с помощью `openssl rand -base64 32`

### A.2 Конфигурация authOptions

Существующая конфигурация в `/src/lib/auth.ts`:

```typescript
import { NextAuthOptions } from 'next-auth';
import CredentialsProvider from 'next-auth/providers/credentials';

export const authOptions: NextAuthOptions = {
  providers: [
    CredentialsProvider({
      name: 'Credentials',
      credentials: {
        email: { label: 'Email', type: 'email' },
        password: { label: 'Password', type: 'password' },
      },
      async authorize(credentials) {
        // Логика проверки пользователя
      },
    }),
  ],
  callbacks: {
    async jwt({ token, user }) {
      // Добавление user.id в token
    },
    async session({ session, token }) {
      // Добавление user.id в session
    },
  },
  pages: {
    signIn: '/admin/login',
  },
  session: {
    strategy: 'jwt',
  },
};
```

### A.3 Защита маршрутов

**Middleware (опционально):**
```typescript
// middleware.ts
import { withAuth } from "next-auth/middleware";

export default withAuth({
  pages: {
    signIn: "/admin/login",
  },
});

export const config = {
  matcher: ["/admin/:path*"],
};
```

**Или проверка в component/server component:**
```typescript
import { getServerSession } from "next-auth";
import { authOptions } from "@/lib/auth";

export default async function AdminLayout({ children }) {
  const session = await getServerSession(authOptions);

  if (!session || session.user.role !== 'ADMIN') {
    redirect('/admin/login');
  }

  return <>{children}</>;
}
```
