# ЧТЗ: Экспорт сметы в Word и UI правки кнопки редактирования

## Версия: 1.0
## Дата: 2026-04-09
## Приоритет: High
## Статус: Согласовано

---

## 1. Цели и задачи

### 1.1 Бизнес-цель
Обеспечить формирование и выгрузку сметы по заявке в формате Word (.docx) для передачи заказчику, а также привести UI кнопки редактирования смет к компактному виду.

### 1.2 Пользовательская ценность
- Менеджер получает готовый документ сметы по ГОСТ/законодательству РФ для отправки клиенту
- Компактный UI: кнопка редактирования не занимает лишнее место в карточке сметы

### 1.3 Метрики успеха
- Успешная генерация .docx для заявок с 1 и несколькими сметами
- Кнопка редактирования — только иконка-карандаш, без текста

## 2. Функциональные требования

### US-1: Кнопка редактирования в виде карандаша
**Given** заявка открыта в админ-панели (вкладка «Расчет»)
**When** отображается исходная или скорректированная смета
**Then** кнопка «Редактировать» / «Редактировать корректировку» заменяется на иконку карандаша (Pencil) без текста, располагается в правом верхнем углу карточки после ссылки на смету

**Дополнительные требования:**
- Позиция: в той же строке, что и ссылка на смету («Открыть смету» / «Скорректированная» / «Исходный расчет»), справа от ссылки
- Tooltip при наведении: «Редактировать» (исходная) / «Редактировать корректировку» (скорректированная)
- Цвет: blue-600 для исходной, orange-600 для скорректированной (как текущие кнопки)

### US-2: Экспорт сметы в Word
**Given** заявка содержит минимум одну смету
**When** менеджер нажимает кнопку «Сохранить смету в Word»
**Then** система формирует .docx документ и скачивает его

**Правила выбора данных для экспорта:**
- При наличии скорректированной сметы (adminEstimate) → использовать её данные
- При отсутствии корректировки → использовать исходную смету (estimate)
- Для мульти-смет (multiEstimates): по каждому расчёту — отдельный блок таблиц, в конце — «Итого по заявке»

**Правила отображения скорректированных данных в Word:**
- НЕ отображать цветовую схему и маркеры корректировок (DiffBadge, подсветка строк)
- Брать финальное количество позиций из скорректированной сметы
- Включать добавленные номенклатуры (added)
- Исключать удалённые номенклатуры (deleted)
- Маржу НЕ отображать в итоговом документе

### US-3: Шаблон сметы по законодательству РФ
**Шаблон формируется на основе требований:**
- МДС 81-35.2004 (Методика определения стоимости строительной продукции)
- ГОСТ 21.1101-2013 (СПДС. Основные требования к проектной и рабочей документации)
- Градостроительный кодекс РФ (ст. 52 — требования к сметной документации)

**Структура документа:**

```
[Шапка]
ООО «Заборы и Навесы»                          Дата: ДД.ММ.ГГГГ
ИНН: _______________                            Кому: {clientName}

[Заголовок]
СМЕТА № {номер}
на выполнение работ по устройству ограждения

[Основание]
Основание: Заявка #{orderId} от {createdAt}
Объект: {measurementAddress или «по адресу Заказчика»}

[Таблица для каждого расчёта]
Расчет №{N}: {fenceTypeName}
Длина: {length} м | Высота: {height} м | Покрытие: {coatingLabel}
Лаги: {lagRows} | Ворота: {да/нет, тип} | Калитка: {да/нет}

| № | Наименование работ и материалов | Ед. изм. | Кол-во | Цена, руб. | Сумма, руб. |
|---|--------------------------------|----------|--------|------------|-------------|
|   | Материалы                       |          |        |            |             |
| 1 | {name}                         | {unit}   | {qty}  | {price}    | {total}     |
|...|                                 |          |        |            |             |
|   | Итого материалы:                |          |        |            | {sum}       |
|   | Работы                          |          |        |            |             |
| N | {name}                         | {unit}   | {qty}  | {price}    | {total}     |
|   | Итого работы:                   |          |        |            | {sum}       |
|   | ВСЕГО по расчету №{N}:          |          |        |            | {grandTotal}|

[Итого по заявке (при мульти)]
| Показатель          | Сумма, руб. |
|---------------------|-------------|
| Итого материалы:    | {sum}       |
| Итого работы:       | {sum}       |
| ВСЕГО ПО СМЕТЕ:     | {grandTotal}|

[Подписи]
Подрядчик: __________ / __________/
М.П.                     Заказчик: __________ / __________/
```

### US-4: Кнопка экспорта в Word в UI
**Given** заявка открыта, содержит смету
**When** менеджер видит блок сметы
**Then** в верхней части блока (рядом с заголовком «Смета» / «Расчет отредактирован администратором») отображается кнопка «Сохранить в Word» с иконкой Download
**When** экспорт выполняется — кнопка показывает Loader2 спиннер
**When** произошла ошибка — alert с описанием ошибки

### 3.1 Производительность
- Генерация .docx для заявки с 1 сметой: < 3 сек
- Генерация .docx для заявки с 5 сметами: < 5 сек

## 4. Техническая архитектура

### 4.1 Изменения в БД
Нет. Существующая схема полностью покрывает потребности.

### 4.2 API спецификация

**Endpoint:** `GET /api/admin/orders/[id]/export-estimate-word`

**Auth:** Cookie session (role: ADMIN, MANAGER)

**Response 200:**
- Content-Type: `application/vnd.openxmlformats-officedocument.wordprocessingml.document`
- Content-Disposition: `attachment; filename="смета_заявка_{orderId}.docx"`
- Body: binary .docx

**Response 404:**
```json
{ "error": "ORDER_NOT_FOUND", "message": "Заявка не найдена" }
```

**Response 400:**
```json
{ "error": "NO_ESTIMATE", "message": "В заявке нет сметы для экспорта" }
```

## 5. UI/UX требования

### 5.1 Кнопка редактирования (карандаш)
- Иконка: `Pencil` из lucide-react, размер `w-4 h-4`
- Без текста, без border, без background — только hover-эффект
- Tooltip: `title="Редактировать"` / `title="Редактировать корректировку"`
- Расположение: inline после ссылки на смету, в правом верхнем углу карточки

### 5.2 Кнопка экспорта Word
- Иконка: `Download` из lucide-react
- Текст: «Сохранить в Word»
- Цвет: primary (как основные кнопки)
- Расположение: в заголовке блока сметы (рядом с «Смета» / «Расчет отредактирован»)
- Состояние loading: spinner + неактивна

### 5.3 Обработка ошибок
- Нет сметы: кнопка не отображается
- Ошибка генерации: alert с текстом ошибки
- Заявка-индивидуальный расчёт: кнопка не отображается

#### TASK-BCK-002: Создать сервис генерации Word-сметы
**Направление**: Backend
**Приоритет**: High
**Оценка**: 3 часа
**Зависимости**: TASK-BCK-001

**Описание**:
Создать `src/services/word/estimateWordGenerator.ts` — сервис, принимающий `WordEstimateData` и возвращающий `Buffer` с .docx файлом.

Шаблон документа:
1. Шапка: «ООО "Заборы и Навесы"», дата, заказчик
2. Заголовок: «СМЕТА № ... на выполнение работ по устройству ограждения»
3. Основание: заявка, объект
4. Для каждого расчёта: параметры забора + таблица материалов и работ с итогами
5. При мульти: сводная таблица «Итого по заявке»
6. Подписи: подрядчик / заказчик

**Правила формирования данных:**
- Скорректированная смета → берём финальные позиции (без удалённых, с добавленными)
- Без цветовых маркеров и DiffBadge
- Маржа НЕ включается
- Все суммы в рублях с разделителем пробел (ru-RU)

**Критерии приемки**:
- [ ] Функция `generateEstimateWord(data: WordEstimateData): Buffer` создана
- [ ] Документ содержит шапку, заголовок, основание
- [ ] Таблицы с колонками: №, Наименование, Ед.изм., Кол-во, Цена, Сумма
- [ ] Итого материалы + Итого работы + ВСЕГО для каждого расчёта
- [ ] Сводная таблица «Итого по заявке» при нескольких расчётах
- [ ] Блок подписей внизу
- [ ] Удалённые позиции исключены, добавленные включены
- [ ] Маржа отсутствует

**Технические детали**:
- Файл: `src/services/word/estimateWordGenerator.ts`
- Библиотека: `docx` (Document, Packer, Paragraph, Table, TableRow, TableCell, TextRun, AlignmentType, WidthType, BorderStyle)
- Тип: `WordEstimateData` (определён в ЧТЗ)

#### TASK-BCK-003: API route для экспорта сметы в Word
**Направление**: Backend
**Приоритет**: High
**Оценка**: 2 часа
**Зависимости**: TASK-BCK-002

**Описание**:
Создать `GET /api/admin/orders/[id]/export-estimate-word` — endpoint, который:
1. Проверяет авторизацию (requireAdmin)
2. Получает данные заявки (через ordersService.getOrderFull)
3. Формирует WordEstimateData, выбирая скорректированную или исходную смету
4. Для мульти-смет — агрегирует данные из всех расчётов
5. Фильтрует удалённые позиции из скорректированных смет
6. Вызывает generateEstimateWord и возвращает .docx

**Критерии приемки**:
- [ ] Файл `src/app/api/admin/orders/[id]/export-estimate-word/route.ts` создан
- [ ] Защита requireAdmin
- [ ] 404 если заявка не найдена
- [ ] 400 если нет сметы
- [ ] 200 с .docx blob
- [ ] Для заявок с 1 сметой — 1 блок таблиц
- [ ] Для заявок с мульти-сметами — N блоков + итого
- [ ] Скорректированная смета используется при наличии
- [ ] Фильтрация удалённых позиций

**Технические детали**:
- Файл: `src/app/api/admin/orders/[id]/export-estimate-word/route.ts`
- Использует: `ordersService.getOrderFull`, `generateEstimateWord`
