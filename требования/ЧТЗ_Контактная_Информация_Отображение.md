# ЧТЗ: Контактная информация — корректное отображение на публичном сайте

## Проблема

Данные контактной информации, сохранённые через админ-панель (`/admin/references/contact-info`), не отображаются на публичных страницах:
- **Страница контактов** (`/contacts`) — показывает «Данные не указаны»
- **HomeFooter** (главная) — email показывает «Данные не указаны», часы работы захардкожены
- **Footer** — использует дефолтный телефон вместо данных из БД

### Корневая причина

1. **Страница `/contacts`** делает независимый `fetch('/api/contact-info')` в `useEffect` вместо использования `ContactInfoProvider`. При SSR `contactInfoData = null` → все поля показывают «Данные не указаны».

2. **ContactInfoProvider** загружает данные только через `useEffect` (клиент-side), поэтому при SSR все компоненты получают дефолтные значения: `phone = '+74993901595'`, `email = ''`.

3. **HomeFooter** — строка 49: `Пн-Сб: 9:00 - 18:00` захардкожена, не использует `contactInfo.workHours`.

4. **Provider** при `hasData: false` не обновляет state, оставляя дефолтный телефон `+74993901595`, но пустой email.

## Изменяемые файлы

1. `src/components/providers/ContactInfoProvider.tsx` — исправить логику: показывать данные из БД даже если `hasData: false` (пустые строки — тоже данные)
2. `src/app/(public)/contacts/page.tsx` — использовать `useContactInfo()` вместо независимого fetch
3. `src/components/layout/HomeFooter.tsx` — использовать динамические `workHours` из provider

## Критерии приёмки

1. Страница `/contacts` отображает данные из БД: адрес, телефон, email, часы работы
2. HomeFooter отображает динамические часы работы из БД
3. Footer отображает телефон и email из БД
4. ContactInfoProvider корректно обрабатывает ответ API (и `hasData: true`, и `hasData: false`)
5. Нет дублирования fetch-запросов (страница контактов использует provider, а не делает свой запрос)
6. SSR корректно отдаёт дефолтные значения, клиент-side обновляет их из API
