## 2. Цели и задачи

### 2.1 Бизнес-цель
Создать справочник профнастила для централизованного управления номенклатурой листового материала с возможностью указания цен закупки и розничных цен, контроля сроков действия цен и автоматического расчета маржинальности.

### 2.2 Пользовательская ценность
- Централизованное управление номенклатурой профнастила
- Контроль актуальности цен по срокам действия
- Автоматический расчет маржинальности для принятия решений о ценообразовании
- Фильтрация по статусу активности и срокам действия
- Быстрый поиск нужной номенклатуры

### 2.3 Ключевые метрики успеха
- 100% новых номенклатур создаются корректно
- Корректный автоматический расчет цен за единицу и маржи
- Доступ к ценам закупки только у ADMIN роли
- Корректная фильтрация по срокам действия

#### 3.1.3 Автоматический расчет цен и маржи

**User Story 4: Автоматический расчет цен за единицу**
*Как администратор, я хочу видеть автоматически рассчитанные цены за лист на основе метра погонного.*

**Формулы расчета:**

```
Цена закупки за ед. (₽) = (Полезная ширина / 1000) × (Длина / 1000) × Цена за м.п. закупка
```

```
Розничная стоимость за ед. (₽) = (Полезная ширина / 1000) × (Длина / 1000) × Розничная стоимость за м.п.
```

**Примечание:** Используется полезная ширина, т.к. она отражает реальную покрываемую площадь с учетом нахлеста.

**Acceptance Criteria:**
- Расчет происходит в реальном времени при изменении любого из полей
- Поля отображаются как readonly (серый фон)
- Формат: "1 500 ₽" с разделителем тысяч
- Если цена за м.п. закупка не указана - показывается "Не указана"
- Расчетные поля находятся под соответствующими полями ввода цен за м.п.

**User Story 5: Расчет и отображение маржи**
*Как администратор, я хочу видеть маржинальность номенклатуры для оценки прибыльности.*

**Формулы расчета маржи:**

```
Маржа за м.п. (%) = ((Розничная за м.п. - Закупка за м.п.) / Розничная за м.п.) × 100
```

```
Маржа за м.п. (₽) = Розничная за м.п. - Закупка за м.п.
```

```
Маржа за ед. (%) = ((Розничная за ед. - Закупка за ед.) / Розничная за ед.) × 100
```

```
Маржа за ед. (₽) = Розничная за ед. - Закупка за ед.
```

**Секция маржи (аналогично справочнику Лаги):**

```
┌─────────────────────────────────────────────────────────┐
│ Расчет маржи (только для ADMIN)                    ℹ️   │
├─────────────────────────────────────────────────────────┤
│                                                         │
│ За метр погонный:                                       │
│   Маржа: 28.6%  🟢                                      │
│   Абсолютная маржа: 200 ₽/м.п.                          │
│                                                         │
│ За единицу (лист):                                      │
│   Маржа: 28.6%  🟢                                      │
│   Абсолютная маржа: 460 ₽/лист                          │
│                                                         │
│ ℹ️ 🟢 Маржа ≥ 30% | 🟡 10-30% | 🔴 < 10% | ⚪ Не указана │
└─────────────────────────────────────────────────────────┘
```

**Цветовая индикация маржи:**
- 🟢 Зеленый: ≥ 30%
- 🟡 Желтый: 10-30%
- 🔴 Красный: < 10%
- ⚪ Серый: цена закупки не указана

**Acceptance Criteria:**
- Секция маржи видна только для ADMIN
- Расчет происходит в реальном времени при изменении цен
- Цветовая индикация обновляется мгновенно
- Tooltip объясняет пороги маржи
- Если цена закупки не указана - показывается "Не указана" (серый цвет)

#### 3.1.6 Контроль доступа

**User Story 9: Ограничение доступа к ценам закупки**
*Как система, я хочу скрыть цены закупки от пользователей с ролью MANAGER.*

**Acceptance Criteria:**
- **Роль ADMIN:**
  - Видит колонку "Цена закупки за ед." в таблице
  - Видит секцию "Расчет маржи" в форме
  - Может редактировать "Цена за м.п. закупка"
- **Роль MANAGER:**
  - НЕ видит колонку "Цена закупки за ед." в таблице
  - НЕ видит секцию "Расчет маржи" в форме
  - НЕ видит поле "Цена за м.п. закупка"
  - Видит только розничные цены
  - НЕ видит кнопку "Удалить"
- **API:**
  - GET запросы возвращают поля purchasePricePerMeter только для ADMIN
  - POST/PUT запросы с purchasePricePerMeter отклоняются для MANAGER (403 Forbidden)
  - DELETE запросы отклоняются для MANAGER (403 Forbidden)

#### 4.2.1 Модель ProfnastilType

```prisma
model ProfnastilType {
  id                      String   @id @default(cuid())
  name                    String              // Название
  description             String?             // Описание
  metalThickness          Float               // Толщина металла (мм)
  fullWidth               Int                 // Полная ширина (мм)
  usefulWidth             Int                 // Полезная ширина (мм)
  length                  Int                 // Длина (мм)
  coating                 String              // Покрытие
  color                   String?             // Цвет
  purchasePricePerMeter   Float?              // Цена закупки за м.п. (₽)
  retailPricePerMeter     Float               // Розничная стоимость за м.п. (₽)
  validFrom               DateTime?           // Дата начала действия
  validUntil              DateTime?           // Срок действия (дата окончания)
  active                  Boolean  @default(true)
  image                   String?             // URL изображения
  sortOrder               Int      @default(0)
  createdAt               DateTime @default(now())
  updatedAt               DateTime @updatedAt
  
  @@index([active])
  @@index([validUntil])
  @@index([coating])
  @@index([name])
  @@unique([name, metalThickness, coating, color], name: "profnastil_unique_combination")
}
```

**Примечание:** Поля ширин и длины хранятся в мм (Int) для единообразия с другими справочниками.

### 6.3 Обработка ошибок

**Сценарий 1: Дублирующая комбинация**
- Валидация на сервере при создании/редактировании
- Error toast: "Номенклатура с такими параметрами уже существует"
- Подсветка полей, участвующих в уникальности

**Сценарий 2: Некорректная цена закупки**
- Валидация на клиенте: warning если purchasePricePerMeter ≥ retailPricePerMeter
- "⚠️ Цена закупки превышает или равна розничной стоимости"
- Можно сохранить, но показывается warning

**Сценарий 3: Некорректные даты**
- validFrom не может быть раньше сегодня (при создании)
- validUntil должен быть позднее validFrom
- Error: "Проверьте корректность дат"

**Сценарий 4: Некорректные размеры**
- usefulWidth не может быть больше fullWidth
- Error: "Полезная ширина не может превышать полную"

## 10. Риски и зависимости

### 10.1 Технические риски

**Risk 1: Несовместимость единиц измерения с существующими справочниками**

**Category:** Technical  
**Probability:** Medium  
**Impact:** Low

**Description:**
В данном ЧТЗ указано хранить размеры в мм для единообразия. Существующие справочники (Лаги, Столбы) могут использовать другие единицы.

**Mitigation Strategies:**
- Документировать принятое решение
- При необходимости - создать отдельную задачу на унификацию единиц измерения в других справочниках

---

### 10.2 Бизнес риски

**Risk 2: Изменение списка покрытий**

**Category:** Business  
**Probability:** Medium  
**Impact:** Low

**Description:**
Список покрытий (Полимерное (одностороннее), Полимерное (двустороннее), Оцинковка) может потребовать расширения в будущем.

**Mitigation Strategies:**
- Реализовать покрытие как enum в коде, но с возможностью легкого расширения
- Рассмотреть создание отдельного справочника покрытий в будущем

## 12. Решённые вопросы

### Вопрос 1: Типы покрытий ✅ РЕШЕНО
**Решение:** Полимерное (одностороннее), Полимерное (двустороннее), Оцинковка

**Обоснование:** Стандартные типы покрытий для профлиста, покрывающие большинство вариантов использования.

---

### Вопрос 2: Поля ширины ✅ РЕШЕНО
**Решение:** Два поля - Полная ширина и Полезная ширина

**Обоснование:** Для корректного расчета цен используется полезная ширина (с учетом нахлеста), но полная ширина нужна для информации и закупки.

---

### Вопрос 3: Единицы измерения ✅ РЕШЕНО
**Решение:** Все размеры хранить в мм для единообразия

**Обоснование:** Упрощает расчеты и предотвращает ошибки при конвертации единиц.

---

### Вопрос 4: Уникальность номенклатуры ✅ РЕШЕНО
**Решение:** Уникальная комбинация: название + толщина + покрытие + цвет

**Обоснование:** Позволяет иметь номенклатуры с одинаковым названием, но разными характеристиками.
