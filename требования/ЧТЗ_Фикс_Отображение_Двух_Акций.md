## 1. Описание проблемы

При активации двух акций (для разных типов заборов) на главной странице отображается только одна. Пользователь ожидает увидеть обе акции в карусели баннера.

## 2. Корневые причины

### 2.1. Redis-кэш не инвалидируется надёжно (promotionService.ts:212)

Метод `invalidateCache` завёрнут в `try/catch` с молчаливым проглатыванием ошибок. Если Redis недоступен — кэш `PROMOTIONS_ALL_ACTIVE` не очищается, устаревшие данные отдаются до 5 минут (TTL = 300 сек).

### 2.2. Форма админки всегда отправляет `active: false` (PromotionSection.tsx:121)

При сохранении через форму (как создание, так и редактирование) payload всегда содержит `active: false`. При создании — promotion создаётся неактивным, требуется дополнительный клик «Активировать». При редактировании — `active` игнорируется в PUT handler (там нет этого поля), но это запутывает логику.

### 2.3. Нет визуального перехода между акциями (PromotionBanner.tsx)

Карусель меняет контент мгновенно без анимации — пользователь может не заметить переключение.

## 3. Функциональные требования

### User Story

**Как** администратор сайта
**Я хочу** создавать и активировать несколько акций для разных типов заборов
**Чтобы** все активные акции отображались на главной странице в баннере-карусели

### Acceptance Criteria

- Given две активные акции с заполненным bannerTitle, When пользователь открывает главную страницу, Then видна карусель с двумя акциями и точками навигации
- Given две активные акции, When карусель переключается, Then происходит плавная анимация перехода
- Given администратор создаёт акцию через форму, When нажимает «Создать», Then promotion создаётся с корректным статусом active
- Given администратор редактирует существующую активную акцию, When нажимает «Обновить», Then статус active сохраняется
- Given кэш Redis устарел или недоступен, When запрашиваются активные акции, Then данные корректно возвращаются из БД

## 4. Технические детали

### 4.1. TASK-BCK-001: Надёжная инвалидация кэша в promotionService

**Файлы:** `src/services/calculator/promotionService.ts`

**Что сделать:**

1. В методе `invalidateCache` (строка 212) — после `try/catch` с Redis `del`, добавить **принудительную инвалидацию через SET** вместо `del`. Записать в кэш `__stale__` маркер или сразу обновить кэш из БД.

**Или (рекомендуемый вариант):** убрать кэширование из `getActivePromotionsForBanner` — метод вызывается редко (только при загрузке главной), а промоций всегда мало (1-5 штук). Прямой запрос к БД без кэша надёжнее.

**Критерии приёмки:**
- [ ] После активации второй акции она появляется на главной при следующем запросе
- [ ] Кэш не может содержать устаревшие данные
