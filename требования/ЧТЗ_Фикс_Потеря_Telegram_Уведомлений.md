## 1. Инцидент и результаты диагностики

**Симптом (2026-09-02 ~13:20–13:26 МСК):** пользователь на проде кликнул по телефону и
сделал расчёт в калькуляторе забора (Профнастил). В Telegram пришёл только «Клик по
номеру телефона»; «Расчёт калькулятора» — нет. По словам пользователя, метрики не
отразились и на дашборде мониторинга.

**Диагностика (прод, VPS 37.143.13.196):**

| № | Проверка | Результат |
|---|----------|-----------|
| 1 | Redis `analytics:daily:2026-09-02` | `calculator_calculate=1`, `phone_click=1` — события ДОШЛИ до сервера |
| 2 | Бакеты `analytics:tracking:b:202609021320` | `ev:calculator_calculate=1`, `svc:Профнастил=1` — записаны корректно |
| 3 | Логи `fences-app` | `10:25:38 calculator_calculate` записан → `10:25:44 Telegram analytics notification error: DOMException [AbortError]` (единственная ошибка за 6 ч) |
| 4 | `phone_click` в `10:25:55` | Telegram-уведомление доставлено успешно (та же сессия, тот же код) |
| 5 | `/api/metrics/tracking` (прод) | 200, отдаёт `business_events_24h{event_type="calculator_calculate"} 1` и `phone_click 1` |
| 6 | nginx → центральный мониторинг | `130.49.129.241` скрейпит `/metrics/tracking` каждые ~15 с, все 200 |

**Корневые причины:**

- **BUG-001 (Telegram, подтверждён):** `sendAnalyticsNotification` делает ОДИН fetch к
  `api.telegram.org` с жёстким таймаутом 5 с и БЕЗ ретраев. Транзиентная сетевая
  деградация (>5 с ответ Telegram API) → AbortError → уведомление теряется навсегда.
  Именно это произошло с `calculator_calculate`; через 17 секунд `phone_click` прошёл.
- **BUG-002 (дашборд — НЕ баг, задержка конвейера):** событие зафиксировано и отдаётся
  в метриках. Конвейер данных: кэш tracking-метрик 60 с → scrape Prometheus ~15 с →
  refresh панели Grafana. Итоговая задержка до появления на дашборде — 1–2 мин.
  Пользователь проверил раньше. Доработка не требуется; проверка отображения — в
  регрессии (критерий приёмки №7).
- **BUG-003 (нарушение Правила 8):** в `analytics-notifier.ts` ошибки логируются
  «голым» `console.error` вместо структурированного `src/lib/logger.ts`.

## 2. Что делаем

Файлы: `src/services/telegram/analytics-notifier.ts` + `__tests__/services/telegram/analytics-notifier.test.ts`. Больше ничего не трогаем.

### TASK-BCK-001 — Ретраи отправки в Telegram

В `sendAnalyticsNotification` вынести отправку в helper с ретраями:

- до **3 попыток** всего;
- таймаут запроса — **8 с** на попытку (сейчас 5 с);
- пауза между попытками: **1 с** после 1-й, **3 с** после 2-й (настраиваемый параметр
  для тестов — injectable delay, чтобы тесты не ждали реально);
- ретраить ТОЛЬКО: сетевые ошибки/таймауты (AbortError, fetch reject) и HTTP
  **429 / 5xx**;
- HTTP **4xx** (кроме 429) — НЕ ретраить (ошибка запроса, повтор бессмысленен);
- при окончательной неудаче — `logger.error` с контекстом: eventName, sessionId,
  attempts, последняя ошибка;
- при успехе после ретрая — `logger.warn` (событие дошло не с первой попытки, attempts).

### TASK-BCK-002 — Структурированное логирование

Заменить оба `console.error` на `logger` (`src/lib/logger.ts`):
- `module: 'telegram/analytics-notifier'`, `operation: 'sendAnalyticsNotification'`;
- ошибки API (`!response.ok`) — `logger.error` с текстом ответа и attempt.

Дедуп (`shouldDedup`), форматирование сообщений, список NOTIFIABLE_EVENTS — НЕ менять.

## 3. Критерии приёмки

1. При транзиентном сбое (таймаут/AbortError/сетевая ошибка/429/5xx) отправка
   повторяется; при успехе со 2-й/3-й попытки уведомление доставляется.
2. При исчерпании попыток — `logger.error` (не console.error) с eventName/sessionId/attempts;
   функция резолвится без throw (текущий контракт fire-and-forget сохранён).
3. 4xx (кроме 429) — ровно 1 попытка, `logger.error`.
4. Поведение дедупа не изменилось (тесты `shouldDedup` зелёные без правок).
5. Новые тесты: retry-успех со 2-й попытки; retry-исчерпание; 4xx без ретрая;
   happy path; логирование ошибок. Все существующие тесты — зелёные.
6. Quality gate: `npm test && npm run lint && npx tsc --noEmit`.
7. Регрессия (после деплоя): повторить сценарий (расчёт в калькуляторе + клик по
   телефону) — оба уведомления в Telegram, оба события на дашборде «Бизнес сайта»
   (допустимая задержка до 2 мин).
