## 1. Описание задачи

Два связанных изменения в калькуляторе ферм:

### 1.1. Убрать радиус углов с чертежа
В SVG-чертеже фермы все компоненты (пояса, стойки, раскосы) отображаются с закруглёнными концами линий (`stroke-linecap="round"`). Нужно убрать скругление — оставить прямые концы (`stroke-linecap="butt"`).

**Важно:** Только визуальное изменение в SVG-генераторе. Не трогать расчёты.

### 1.2. Разделить поле «Перекладины» на два
Сейчас в калькуляторе одно поле `crossbeamProfileId` («Перекладины») используется для:
- Нижнего пояса фермы (bottom_chord)
- Верхнего пояса фермы (top_chord) — для неарочных типов
- Прогонов (purlins)

Нужно разделить на два поля:
- **Нижняя перекладина (Нижний пояс)** — `crossbeamProfileId` (оставить, переименовать label)
- **Верхняя перекладина (Верхний пояс)** — `topChordProfileId` (новое поле)

Оба поля используют справочник `CROSSBEAM`. Это позволит задавать разные профили для верхнего и нижнего поясов и корректно рассчитывать нагрузку и прочность.

## 3. Детализация изменений

### 3.1. SVG — убрать скругление (TASK-DRAW)

**Файл:** `src/services/truss/svgGenerator.ts:145`

```diff
- stroke-linecap="round"
+ stroke-linecap="butt"
```

Заменить `stroke-linecap="round"` на `stroke-linecap="butt"` в строке генерации `<line>` элементов для конструктивных элементов фермы.

### 3.2. Prisma Schema — новое поле (TASK-DB)

**Файл:** `prisma/schema.prisma` → модель `TrussCalculation`

Добавить поле:
```prisma
topChordProfileId   String?
```

Добавить relation:
```prisma
topChordProfile   TrussProfileType?  @relation("CalcTopChord", fields: [topChordProfileId], references: [id])
```

**Обратная совместимость:** `topChordProfileId` — nullable. Для существующих расчётов поле = `null` (будет использоваться `crossbeamProfileId` как fallback).

### 3.3. TypeScript типы (TASK-TYPES)

**Файл:** `src/services/truss/types.ts` → `TrussCalculationInput`

Добавить поля (аналогично arch*):
```typescript
topChordProfileId?: string;
topChordSectionArea?: number;
topChordSectionModulusX?: number;
topChordRadiusOfGyrationX?: number;
topChordWeightPerMeter?: number;
topChordRetailPricePerMeter?: number;
topChordProfileName?: string;
```

### 3.4. UI форма — разделить dropdown (TASK-FORM)

**Файл:** `src/components/admin/TrussCalculator/TrussCalculatorForm.tsx`

Заменить один dropdown «Перекладины» на два:
1. **«Нижняя перекладина (Нижний пояс)»** — `crossbeamProfileId`, фильтр `CROSSBEAM`, обязательное
2. **«Верхняя перекладина (Верхний пояс)»** — `topChordProfileId`, фильтр `CROSSBEAM`, обязательное для SINGLE_SLOPE и DOUBLE_SLOPE

Условия видимости:
- SINGLE_SLOPE / DOUBLE_SLOPE: видны оба поля
- ARCH / SINGLE_SLOPE_CURVED: поле «Верхняя перекладина» скрыто (верхний пояс = арочная дуга)

### 3.5. Валидация (TASK-VALIDATE)


### 3.6. Калькулятор — разделить профили (TASK-CALC)

**Файл:** `src/services/truss/trussCalculator.ts`

Изменить логику `topChordProfile`:
- **Было:** topChord = arch (для ARCH/CURVED) или crossbeam (для остальных)
- **Стало:** topChord = arch (для ARCH/CURVED) или **topChord** (для остальных)

В функции `calculateTruss`:
- `bottomChordProfile` продолжает использовать `crossbeam*` поля
- `topChordProfile` использует `topChord*` поля (с fallback на `crossbeam*` если не задан)

Аналогично обновить:
- `getProfileForType()` — для `top_chord` вернуть `topChordProfileName` вместо `crossbeamProfileName`
- `calculateMaterials()` — для верхнего пояса использовать `topChord*` данные
- `buildElementDetails()` — использовать корректное имя профиля
