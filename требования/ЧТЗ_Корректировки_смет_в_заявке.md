# ЧТЗ: Корректировки смет в заявке — исправление и доработка

## 1. Описание проблемы

В админ-панели при работе с заявками, содержащими несколько смет (multi-estimate), и корректировками смет администратором существует ряд критических багов и недоработок.

## 2. Требования

### ТР-1: Итоговая стоимость заявки в правом верхнем углу

**Сейчас:** Отображается `order.calculatedCost` — одна цифра, не учитывающая индивидуальные корректировки каждой сметы.

**Должно быть:** Сумма по всем сметам заявки. Для каждой сметы: если есть скорректированная версия — берётся `grandTotal` скорректированной сметы, иначе — `grandTotal` исходной сметы.

### ТР-2: Переключатель между исходной и скорректированной сметой

**Сейчас:** В multi-estimate режиме при наличии корректировки отображается только скорректированная смета, исходная недоступна для просмотра. Ссылка на исходную смету в Расчеты отсутствует.

**Должно быть:**
- На экране каждой сметы — переключатель (табы): «Исходная смета» / «Скорректированная смета»
- Ссылка на исходную смету в разделе Расчеты
- Ссылка на скорректированную смету в разделе Расчеты

### ТР-3: Цветовая индикация изменений в скорректированной смете

**Сейчас:** Diff-индикация частично реализована (DiffBadge), но не применяется корректно в multi-estimate режиме.

**Должно быть:**
- Добавленные позиции — зелёный фон (`bg-green-50`), бейдж «Добавлено»
- Удалённые позиции — красный зачёркнутый текст (`line-through text-red-500`), бейдж «Удалено»
- Скорректированные позиции — оранжевый фон (`bg-amber-50`), стрелка с изменением количества

### ТР-4: Кнопка «Редактировать корректировку» — исправление бага

**Сейчас:** При нажатии «Редактировать корректировку» в multi-estimate режиме ничего не происходит.

**Причина:** В `OrderDetailPage.tsx` при определении `editingEstimate`, `adminEstimate.id` ищется в массиве `multiEstimates`, но его там нет (т.к. adminEstimate — отдельная сущность). `editingEstimate` = null → редактор не открывается.

**Должно быть:** Кнопка открывает EstimateEditor с правильными данными текущей скорректированной сметы.

### ТР-5: Сохранение корректировки для каждой сметы отдельно

**Сейчас:** `Order.adminEstimateId` — одно поле, хранит ссылку на ОДНУ корректировку. При редактировании второй сметы — первая корректировка теряется.

**Должно быть:** Каждая смета (FenceEstimate) в multi-estimate может иметь свою корректировку. Поиск корректировок через `FenceEstimate.sourceEstimateId` + `isEditedByAdmin = true`, привязанных к оценкам конкретного заказа.

### ТР-6: Пересчёт итогов по всем типам заборов

**Сейчас:** Блок «Итого по всем типам заборов» суммирует только исходные сметы.

**Должно быть:** Если у сметы есть корректировка — используется сумма скорректированной сметы.

### ТР-7: Корректный расчёт маржи в блоке «Итого»

**Сейчас:** Маржа считается как `grandTotal - purchaseTotal` (разница между продажной и закупочной ценой всех позиций включая работы).

**Должно быть:** Маржа по материалам из Расчетов — сумма маржи (`retailPrice - purchasePrice`) только по позициям материалов (исключая работы), по всем сметам. Берётся `materialMarginRub` из расчетов каждой сметы.

## 3. Критерии приёмки

- [ ] AC-1: В правом верхнем углу заявки отображается корректная итоговая сумма, учитывающая все корректировки
- [ ] AC-2: В multi-estimate режиме для каждой сметы с корректировкой есть табы переключения между исходной и скорректированной версиями
- [ ] AC-3: Для каждой сметы есть ссылки на исходную и скорректированную версию в разделе Расчеты
- [ ] AC-4: В скорректированной смете добавленные позиции выделены зелёным, удалённые — красный зачёркнутый, изменённые — оранжевый
- [ ] AC-5: Кнопка «Редактировать корректировку» открывает редактор с данными текущей сметы
- [ ] AC-6: При редактировании двух разных смет в одной заявке обе корректировки сохраняются независимо
- [ ] AC-7: Блок «Итого по всем типам заборов» пересчитывается с учётом корректировок
- [ ] AC-8: Маржа в блоке «Итого» считается как сумма маржи по материалам из каждой сметы (исключая работы)
- [ ] AC-9: `npm test && npm run lint && npx tsc --noEmit` проходят без ошибок
