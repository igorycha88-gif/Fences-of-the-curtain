# ЧТЗ (упрощённое): Ретраи отправки Telegram-сообщений (заявки, дайджест, контактные формы)

**Дата:** 2026-11-02
**Маршрут:** Аналитик → Разработчик → Тестировщик → (деплой — отдельным решением)
**Тип:** Улучшение надёжности (малая задача: 1 файл + тесты)

## Проблема

`src/services/telegram/bot.ts → sendTelegramMessage` отправляет сообщения (новые заявки, контактные формы, дайджесты) **одной попыткой** без таймаута и ретраев. Сеть хостера VPS рвёт TCP волнами (RST, инцидент 02.11: уведомление о деплое ушло только с 3-й попытки) → заявки и дайджесты периодически теряются молча (`return false`). Аналитика-уведомления (`analytics-notifier`) уже имеют 3×8с ретраев — заявки остались без защиты.

## Решение

### TASK-BCK-1: `src/services/telegram/bot.ts`
- `sendTelegramMessage`: **3 попытки × таймаут 8с**, backoff 1с/3с (паритет с `analytics-notifier`), ретраи на сетевые ошибки/429/5xx; не-ретраебельные HTTP (4xx кроме 429) — сразу false.
- Сигнатура не меняется: `sendTelegramMessage(message: string): Promise<boolean>`.
- Dispatcher (`getTelegramDispatcher`) используется как раньше на каждой попытке.
- `console.*` → структурированный `logger` (Правило 8: модуль `telegram/bot`, операция `sendTelegramMessage`, attempt/status/duration).

## Критерии приёмки

1. 3 попытки, таймаут 8с, backoff 1с/3с; 4xx (кроме 429) не ретраится.
2. Публичный API (`sendOrderNotification`, `sendContactForm`, `sendTelegramMessage`) не изменился.
3. Автотесты: happy path; сетевая ошибка → ретрай → успех; все попытки падают → false; 400 → без ретрая; логирование попыток.
4. Quality Gate: `npm test && npm run lint && npx tsc --noEmit` — зелёные.

## Out of scope

- Деплой на прод (следующий плановый деплой включит изменение)
- Дайджест-логика (`cron.ts`) — не меняется, получает ретраи через `sendTelegramMessage`
