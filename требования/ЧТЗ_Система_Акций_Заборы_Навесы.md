**Дата:** 2026-05-27
**Статус:** Approved

## 1. Бизнес-требование

Реализовать систему акционных скидок на заборы и навесы с управлением из админ-панели. Менеджер должен иметь возможность:
- Создавать акцию для конкретного типа забора
- Выбирать, на что распространяется скидка: материалы, работы, или всё вместе
- Указывать процент скидки от финальной стоимости (включая удорожание по длине)
- Задавать текст для баннера на главной странице
- Активировать/деактивировать акцию

При активной акции:
- На главной странице появляется красивый баннер с описанием акции
- В калькуляторе отображается перечёркнутая старая цена и цена по акции
- Смета формируется с учётом скидки, с отображением информации об акции

## 2. Функциональные требования

### 2.1. Модель акции (Promotion)

Каждая акция привязана к одному типу забора (FenceType). Один тип забора может иметь только одну активную акцию.

**Поля акции:**
- `fenceTypeId` — связь с типом забора (обязательное)
- `name` — название акции для внутреннего использования (обязательное)
- `discountType` — тип скидки: MATERIALS (только материалы), WORKS (только работы), BOTH (всё вместе)
- `discountPercent` — процент скидки (1-50%)
- `bannerTitle` — заголовок для баннера на главной (обязательное при активации)
- `bannerText` — описание для баннера (опциональное)
- `active` — флаг активности
- `startDate` — дата начала акции (опционально)
- `endDate` — дата окончания акции (опционально)

### 2.2. Управление акциями в админ-панели

**Размещение:** Справочник «Типы заборов» — при редактировании типа забора отображается секция «Акция».

**CRUD операции:**
- Создание акции для типа забора
- Редактирование параметров акции
- Активация/деактивация акции
- Удаление акции

**Валидация:**
- При активации `bannerTitle` обязателен
- `discountPercent` от 1 до 50
- Нельзя активировать акцию, если у этого типа забора уже есть активная акция
- При `endDate` в прошлом — акция автоматически деактивируется (cron)

### 2.3. Применение скидки в калькуляторе

**Порядок расчёта:**
1. Рассчитывается полная стоимость (материалы + работы + удорожание по длине)
2. Применяется удорожание по длине (markup) — как сейчас
3. **Затем** применяется акционная скидка к соответствующим позициям

**Формула скидки:**
- Если `discountType = MATERIALS`: скидка применяется к позициям с `category !== 'installation'`
- Если `discountType = WORKS`: скидка применяется к позициям с `category === 'installation'`
- Если `discountType = BOTH`: скидка применяется ко всем позициям

**Расчёт:**
```
discountedPrice = originalPrice * (1 - discountPercent / 100)
```

**Важно:** Скидка применяется ПОСЛЕ удорожания. Порядок: basePrice → markup → promotion discount.

### 2.4. Отображение в калькуляторе (публичный)

При наличии активной акции для выбранного типа забора:

1. **В результатах расчёта (смета):**
   - Каждая позиция, попадающая под скидку, отображается:
     - Старая цена — перечёркнута красной линией (`line-through`)
     - Рядом — цена по акции (зелёным/акцентным цветом)
   - В блоке итогов:
     - «Без скидки: X ₽» (перечёркнуто)
     - «Со скидкой: Y ₽» (крупно, акцентный цвет)
     - «Экономия: Z ₽» (зелёным)
   - Блок «Акция! [bannerTitle]» — плашка с описанием

2. **Бейдж «Акция»** на селекторе типа забора (если есть активная акция)

### 2.5. Баннер на главной странице

**Компонент:** `PromotionBanner`
**Размещение:** Секция после hero-блока (аналогично `GarageBanner`)

**Отображение:**
- Загружает все активные акции через API
- Если акций несколько — карусель (автопрокрутка) или слайдер
- Если одна — статичный баннер

**Стиль баннера:**
- Яркий градиентный фон (оранжево-красный или другой привлекающий внимание)
- Заголовок `bannerTitle` (крупно)
- Текст `bannerText`
- Бейдж «-X%»
- Кнопка «Рассчитать со скидкой» → переход в калькулятор на нужный тип забора
- Тип забора с акцией указан в баннере

**Если нет активных акций:** баннер не отображается (условный рендеринг).

### 2.6. Смета (Word-документ)

В Word-документе сметы:
- Перед таблицей — плашка «Акция: [name] — скидка X% на [материалы/работы/всё]»
- В таблице: колонка «Скидка» рядом с «Сумма» — показывает сумму скидки по каждой позиции
- Итоговая строка «Скидка по акции: -Z ₽»
- «ИТОГО со скидкой: Y ₽»

### 2.7. Сохранение в БД

В модели `FenceEstimate` добавляются поля:
- `promotionId` — ID применённой акции (nullable)
- `promotionName` — название акции (для истории, если акция будет удалена)
- `promotionDiscountType` — тип скидки
- `promotionDiscountPercent` — процент скидки
- `promotionDiscountTotal` — сумма скидки в рублях
- `totalBeforeDiscount` — стоимость до скидки (grandTotal без акции)
- `grandTotal` — итоговая стоимость (уже со скидкой)

## 3. Критерии приёмки

1. В админ-панели на странице типа забора есть секция «Акция» с CRUD
2. Можно создать акцию с параметрами: название, тип скидки, процент, текст баннера
3. Акцию можно активировать/деактивировать
4. При расчёте забора с активной акцией — скидка корректно применяется к нужным позициям
5. Скидка считается от финальной стоимости (ПОСЛЕ удорожания)
6. На главной странице появляется баннер с информацией об акции
7. Баннер исчезает, если нет активных акций
8. В калькуляторе перечёркнутая старая цена + цена по акции
9. В Word-смете отражена скидка по акции
10. В БД (FenceEstimate) сохраняются данные о применённой акции
11. `npm test && npm run lint && npx tsc --noEmit` проходят

## 4. Техническая реализация

### 4.1. БД (prisma/schema.prisma)

```prisma
enum PromotionDiscountType {
  MATERIALS
  WORKS
  BOTH
}

model Promotion {
  id              String                @id @default(cuid())
  fenceTypeId     String
  name            String
  discountType    PromotionDiscountType @default(BOTH)
  discountPercent Float
  bannerTitle     String?
  bannerText      String?
  active          Boolean               @default(false)
  startDate       DateTime?
  endDate         DateTime?
  createdAt       DateTime              @default(now())
  updatedAt       DateTime              @updatedAt
  fenceType       FenceType             @relation(fields: [fenceTypeId], references: [id], onDelete: Cascade)

  @@index([fenceTypeId])
  @@index([active])
  @@index([endDate])
}
```

Изменения в `FenceType`:
```prisma
model FenceType {
  // ... существующие поля ...
  promotion Promotion?
}
```

Изменения в `FenceEstimate`:
```prisma
model FenceEstimate {
  // ... существующие поля ...
  promotionId              String?
  promotionName            String?
  promotionDiscountType    String?
  promotionDiscountPercent Float              @default(0)
  promotionDiscountTotal   Float              @default(0)
  totalBeforeDiscount      Float?
}
```

### 4.2. Backend

#### Сервис: `src/services/calculator/promotionService.ts`
- `getActivePromotion(fenceTypeId)` — получить активную акцию для типа забора
- `applyPromotionDiscount(items, promotion)` — применить скидку к позициям

#### API маршруты:

**Admin (CRUD):**
- `GET /api/admin/promotions?fenceTypeId=xxx` — список акций для типа забора

## 7. Риски и ограничения

1. **Обратная совместимость:** Старые сметы (без акции) продолжают работать корректно. Новые поля в FenceEstimate — nullable/default
2. **Производительность:** Запрос акции при каждом расчёте — добавить кеширование (Redis) как для других справочников
3. **Множественные акции:** Один тип забора = максимум одна активная акция. Валидация на уровне API
4. **Навесы:** В текущей версии акции только для заборов (FenceType). Навесы (CanopyType) — в будущей итерации
