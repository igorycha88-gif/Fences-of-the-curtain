# ЧТЗ: Подбор ворот по высоте забора

## Описание проблемы
При установке высоты забора 1.5м в калькуляторе подбираются ворота высотой 2000мм, а должны подбираться 1500мм (или ближайшие большие, если 1500мм нет в справочнике).

**Корневая причина:** `gateLookup.ts` — функция `findGateByTypeAndLength` не учитывает высоту забора при подборе ворот. Фильтрация только по типу и ширине.

## Маршрутизация
- **Маршрут:** 1 (Стандартная задача)
- **Исполнитель:** Разработчик
- **Этапы:** Аналитик → Разработчик → Тестировщик → DevOps

## Затрагиваемые файлы
1. `src/services/calculator/gateLookup.ts` — основная логика подбора
2. `src/services/calculator/fenceEstimateService.ts` — вызов gate lookup с height
3. `__tests__/services/fenceEstimateService.test.ts` — обновление тестов

## Критерии приёмки

### AC-1: Фильтрация ворот по высоте
- Функция `findGateByTypeAndLength` переименована в `findGateByTypeHeightAndLength` (или добавлен параметр `fenceHeightMm`)
- Ворота фильтруются: `gateHeight >= fenceHeightMm`
- Предпочтение точному совпадению по высоте (как в `wicketLookup.ts`)

### AC-2: Передача высоты из fenceEstimateService
- `fenceEstimateService.ts` передаёт `height * 1000` в gate lookup
-GateHeight возвращается в `GateLookupResult` и `GateInfo`

### AC-3: Обратная совместимость
- Существующие тесты проходят
- Если ворот с нужной высотой нет — понятная ошибка

### AC-4: Алгоритм подбора (по аналогии с wicketLookup)
1. Фильтр по типу (Распашные/Откатные)
2. Фильтр по ширине: `gateLength >= gateWidthMm`
3. Предпочтение точному совпадению по ширине
4. Фильтр по высоте: `gateHeight >= fenceHeightMm`
5. Предпочтение точному совпадению по высоте
6. Сортировка по priority
