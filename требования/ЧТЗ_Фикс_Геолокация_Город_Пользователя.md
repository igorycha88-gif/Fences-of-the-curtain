# ЧТЗ: Фикс определения города пользователя (админка + телеграм-уведомления)

**Дата:** 2026-11-02
**Маршрут:** Аналитик → Разработчик → Тестировщик → DevOps
**Тип:** Баг-фикс (постдеплойный рестарт, Правило 7)

## Проблема

С ~23.10.2026 на проде перестал определяться город пользователя:
- в админке у новых расчётов/заявок город пустой;
- в телеграм-уведомлениях аналитики строка «📍 Локация» пропадает (не всегда), изредка теряются сами уведомления.

## Диагностика (проведена на проде)

1. **БД подтверждает остановку:** `FenceEstimate` — до 22.10 город заполнен в 100% записей, с 23.10 — в 0% записей.
2. **Логи приложения:** за 10 дней — 25 ошибок `[ipLookup] Error fetching city: TimeoutError`.
3. **Замеры из контейнера:** `fetch('http://ip-api.com/...')` — 5.7–5.9 s (curl и Node). Сам API после резолва отвечает за 0.1 s.
4. **DNS — первопричина:** upstream-резолверы systemd-resolved на VPS `46.254.22.138`, `46.254.23.138` (хостер) деградировали: резолв `ip-api.com` из Node — 40 s / 24 s ETIMEOUT, `api.telegram.org` — 27 s ETIMEOUT. После разового успеха кеш даёт 42 ms.
5. **Код неустойчив к этому:** `src/services/admin/ipLookupService.ts:50` — `AbortSignal.timeout(3000)` на весь запрос включая DNS, без ретрая и фолбэк-провайдера. DNS > 3s → abort → `city = null`.
6. Телеграм-сообщения в основном доставляются, т.к. для `api.telegram.org` включён Direct-IP (`TELEGRAM_API_IP`) + ретраи (3 попытки); но локация в сообщении резолвится тем же падающим `getCityByIP` ДО отправки → строки «📍 Локация» нет.

**Вывод: деплой v1.23.0 совпадение, не причина. Причина — деградация DNS хостера + жёсткий 3s-таймаут без ретраев/фолбэка в коде.**

## Решение

### TASK-INF-1 (DevOps, немедленно): починить DNS на VPS
- Переключить upstream systemd-resolved (интерфейс venet0) с резолверов хостера на публичные: `1.1.1.1`, `8.8.8.8`, `77.88.8.8` (runtime: `resolvectl dns venet0 ...`; persist: drop-in `/etc/systemd/resolved.conf.d/dns.conf`).
- Верификация: `dns.promises.resolve4('ip-api.com')` из контейнера стабильно < 500 ms, 5 замеров подряд без ETIMEOUT.

### TASK-BCK-1 (Разработчик): устойчивость ipLookupService
- Файл: `src/services/admin/ipLookupService.ts`
- Изменения:
  - таймаут 3000 → **6000 ms**;
  - **2 попытки** на провайдера (вторая — после паузы 500 ms);
  - **фолбэк-провайдер** `https://ipwho.is/{ip}?fields=success,city,region,country` (бесплатный, без ключа, HTTPS, 0.15 s с VPS; формат ответа совместим по полям);
  - негативный результат НЕ кэшировать (как сейчас), успешный — в Redis `geo:{ip}` TTL 24h (как сейчас);
  - заменить `console.*` на структурированный `logger` (модуль `ipLookup`, операция `getCityByIP`: успех с провайдером и длительностью, ошибки с контекстом — Правило 8);
  - ретраи/фолбэк не должны менять публичный API: сигнатура `getCityByIP(ip): Promise<string | null>` сохраняется.

### TASK-BCK-2 (Разработчик): бэкфилл города за период сбоя
- Новый скрипт `prisma/scripts/backfill-estimate-city.ts` (по образцу `backfill-portfolio-slug.ts`, запуск через tsx):
  - выбирает `FenceEstimate`/`MultiFenceEstimate`/`GateEstimate` с `createdAt >= 2026-10-23` и `city IS NULL` и непустым `ipAddress`;
  - для каждой записи вызывает `getCityByIP` (кэш Redis делает повторы IP дешёвыми), пауза 300 ms между записями (лимиты бесплатных провайдеров);
  - логирует: обработано/обновлено/без результата;
  - идемпотентен (перезапуск безопасен).
- На проде запускает DevOps после TASK-INF-1/деплоя.

## Критерии приёмки

1. `ipLookupService`: таймаут 6000 ms, 2 попытки, фолбэк ipwho.is, logger вместо console (Правило 8).
2. Автотесты (`__tests__/`): happy path основной провайдер; таймаут основного → фолбэк успешен; оба провайдера падают → `null`; Redis-кэш hit/miss; формат локации «City, Region» (Russia) / «City, Region, Country» (не Russia) сохранён.
3. Публичный API не изменён (`getCityByIP` сигнатура та же) — существующие вызовы не требуют правок.
4. Бэкфилл-скрипт: идемпотентность, паузы между запросами, логирование.
5. Quality Gate: `npm test && npm run lint && npx tsc --noEmit` — зелёные.
6. На проде после деплоя: DNS-резолв < 500 ms; новые расчёты получают город (проверка по свежей записи в БД); в телеграм-уведомлении есть «📍 Локация»; бэкфилл восстановил город у записей с 23.10 (где IP резолвится).
