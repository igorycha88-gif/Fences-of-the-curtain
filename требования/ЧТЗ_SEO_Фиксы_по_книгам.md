# ЧТЗ: SEO-фиксы по итогам аудита по книгам (Косарев, Молочков, Бардин, «SEO в эпоху ИИ»)

**Дата:** 2026-10-20
**Источник:** SEO-аудит zabor-i-naves.ru по 4 PDF-книгам (флешка KINGSTON) — см. отчёт в сессии
**Маршрут:** Стандартный (Аналитик → Разработчик → Тестировщик → DevOps)
**Исполнитель:** Разработчик (fullstack)
**Архитектор:** Не привлекается — нет новых сущностей БД, нет новых API, нет интеграций. Решение согласовано с пользователем: гео-уникализация БЕЗ изменения БД.

---

## 1. Контекст

Аудит по книгам выявил 5 исправимых кодом проблем (остальное — организационные меры, см. §6):

1. Шаблонные гео-страницы (39 городов): базовые FAQ и прайс идентичны, меняется только название города — риск Panda/Omitted results (Косарев, стр. 69–73, 150–151).
2. `<img>` вместо next/image в публичных компонентах — нет lazy/оптимизации (Бардин стр. 33; Молчков гл. 10).
3. alt-тексты-шаблоны «фото 1», «миниатюра 2» — Бардин: alt 4–6 слов с описанием.
4. Перегрузка метатегов: 6 title > 74 симв., 9 description > 160 симв. — обрезаются в сниппете (Молчков гл. 6: «заголовки не делать слишком длинными»).
5. Фиктивный lastModified в sitemap (`new Date()` для всей статики) — поисковики перестают доверять lastmod.

### TASK-BCK-002: Честный lastmod в sitemap + robots

**Файлы:** `src/app/sitemap.ts`, `src/lib/seo/constants.ts`, `src/app/robots.ts`

- Добавить в `SEO_CONFIG` константу `CONTENT_LAST_UPDATED: '2026-10-20'` — дата последнего контентного релиза (обновляется вручную при контентных изменениях).
- В `sitemap.ts` заменить `currentDate = new Date()...` на:
  - для статических/гео/посадочных страниц — `SEO_CONFIG.CONTENT_LAST_UPDATED`;

- В `robots.ts` добавить `Disallow: /api/` целиком (API не должен индексироваться; `/api/health` роботам не нужен). Итоговые disallow: `['/admin', '/api']`.

### TASK-FRT-002: Уникализация гео-страниц (без БД)

**Файл:** `src/lib/geo/content.ts` (+ при необходимости чтение полей из `src/lib/geo/cities.ts`)

Цель: снизить попарную схожесть страниц городов одного направления. Использовать ТОЛЬКО существующие данные GeoCity: `districts`, `localContext`, `highway`, `distanceKm`, `driveTime`, `isDacha`, `direction`, `wave`, `faqExtra`.

1. `generateCityFaq`: варьировать формулировки вопросов/ответов между городами:
   - вопрос про срок монтажа: подставлять `driveTime` и расчёт из `distanceKm` (например, «бригада приезжает со склада в Раменском, N км»);
   - для `isDacha` — дачная формулировка (СНТ, межа, соседи), для остальных — городская (коттедж, таунхаус);
   - вопрос про доставку: уникальная строка доставки по `distanceKm` (интервалы км → цена/условия: до 20 км / 20–50 / 50+);
   - как минимум 2 из 5 базовых вопросов должны иметь 2–3 варианта формулировок, выбираемых детерминированно (например, по хэшу slug или индексу в массиве городов) — не случайно между рендерами.
2. `generateCityPriceTable`: добавить строку «Доставка материалов» с расчётом по `distanceKm`; варьировать примечания (note) для 2–3 строк по `direction`/`isDacha`.
3. Новый экспорт `generateCityLocalBlock(city)`: абзац 2–4 предложения из `localContext` + `districts` (окрестности, чем уникальна локация). Вывести на странице города отдельной секцией после прайса (в `src/app/(public)/zabory-navesy/[slug]/page.tsx`).
4. `generateCityDescription`: 3 варианта шаблона (по `direction`: east / southeast / south уже есть regionWord — усилить: подставлять шоссе и ближайший хаб из `getHubByDirection(city.direction)`).
5. `generateCityTitle`: варьировать вторую часть («от 2 600 ₽/м под ключ» / «монтаж от 1 дня» / «замер бесплатно») детерминированно по slug. Лимит title ≤ 74 соблюдать.
6. Запрещено: `Math.random()` (нестабильный рендер при ISR `revalidate = 86400`), новые поля в GeoCity (только если заполнить их для ВСЕХ 39 городов в этом же ЧТЗ).

### TASK-TST-001: Автотесты (Правило 8)

**Файл:** `__tests__/seo/seo-books-fixes.test.ts` (или рядом с существующими seo-тестами — найти по `__tests__`)

1. Метатеги: перебор всех записей `PAGE_METADATA` → `title.length <= 74`, `description.length <= 160`.
2. Sitemap-константа: `CONTENT_LAST_UPDATED` — валидная ISO-дата, не «сегодня» (сравнить с `new Date()`).
3. Robots: содержит `Disallow: /api` (проверка результата `robots()`).
4. Гео-уникальность: для пар городов одного направления (≥ 3 пар) — тексты FAQ (`JSON.stringify(generateCityFaq(city))`) различаются, совпадение < 80%; description городов различаются; title городов различаются.
5. Детерминированность: повторный вызов генераторов для одного города возвращает идентичный результат.
6. Логирование: sitemap error-ветка логирует через logger (уже есть — не сломать).
