# ЧТЗ: Оптимизация скорости production-сборки

## 1. Контекст

Текущее время полного деплоя: **12-22 минуты**. Целевое: **до 5 минут** (без учёта CI-проверок).

### Основные проблемы (выявлены при анализе):

| # | Проблема | Файл | Влияние |
|---|----------|------|---------|
| P1 | `--no-cache` при каждом деплое — инвалидирует весь Docker-кэш | `deploy-production.yml:139` | +5-10 мин |
| P2 | `npx prisma generate` без версии — скачивает Prisma 7.x, ломает сборку | `docker/Dockerfile:19` | Сборка падает |
| P3 | Двойной `npm ci` — на хосте для миграций + в Docker | `deploy-production.yml:108`, `Dockerfile:14` | +2-4 мин |
| P4 | Пересборка monitoring-стека вместе с app | `deploy-production.yml:139` | +1-2 мин |
| P5 | Нет entrypoint для миграций из контейнера | `docker/Dockerfile` | Застой архитектуры |
| P6 | Раздутый build context (скрипты, SQL-дампы, .venv) | `.dockerignore` | +30-60 сек |

## 2. Цель

Сократить время деплоя с 12-22 мин до ≤5 мин, сохранив blue-green стратегию и все проверки здоровья.

## 3. Критерии приёмки

| ID | Критерий | Проверка |
|----|----------|----------|
| AC-1 | `docker compose build app` использует кэш слоёв при отсутствии изменений в package.json | Пересборка занимает <1 мин если изменён только src/ |
| AC-2 | Prisma generate в Dockerfile использует pinned версию 5.22.0 | В логах нет скачивания prisma@7.x |
| AC-3 | Миграции выполняются из контейнера при старте (entrypoint.sh) | Нет `npm ci` на хосте в deploy-скрипте |
| AC-4 | Monitoring-сервисы не пересобираются при деплое app | В команде build участвует только сервис `app` |
| AC-5 | Blue-green деплой сохранён и работает | GREEN healthcheck → switch → BLUE remove |
| AC-6 | `.dockerignore` исключает .venv, *.sql, *.sh-скрипты | `docker build` context < 5MB |
| AC-7 | `--no-cache` опционален — только при ручном запуске с параметром | Автодеплой использует кэш |
| AC-8 | Общее время деплоя (без CI) ≤ 5 мин | Замер по логам |

## 4. Список файлов для изменения

| Файл | Изменение |
|------|-----------|
| `docker/Dockerfile` | Зафиксировать prisma@5.22.0, добавить entrypoint |
| `docker/entrypoint.sh` | **Новый**: prisma migrate deploy → node server.js |
| `.github/workflows/deploy-production.yml` | Убрать npm ci на хосте, build только app, кэш по умолчанию |
| `.dockerignore` | Добавить .venv, *.sql, *.sh, dumps, coverage, тесты |
| `docker-compose.yml` | Пробросить entrypoint, volumes для миграций |

## 6. Риски

| Риск | Митигация |
|------|-----------|
| prisma migrate deploy внутри контейнера может зависеть от сети | network_mode: host уже используется |
| Кэш Docker слоёв может устареть при обновлении зависимостей | Параметр `--no-cache` доступен при ручном деплое |
| entrypoint.sh может завершиться с ошибкой миграции — контейнер не стартует | Логировать ошибку, exit 1 — healthcheck покажет проблему |
