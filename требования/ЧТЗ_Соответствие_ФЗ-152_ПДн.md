## 2. Обзор законодательства

### 2.1 Основные нормативные акты

**Федеральный закон № 152-ФЗ "О персональных данных" (27.07.2006)**
- Определяет понятие персональных данных
- Устанавливает права субъектов ПДн
- Регламентирует обязанности операторов ПДн
- Определяет требования к защите ПДн

**Постановление Правительства РФ № 1119 (01.11.2012)**
- Утверждает требования к защите ПДн
- Устанавливает уровни защищенности информации
- Определяет состав мер защиты

**Приказ ФСТЭК № 21 (18.02.2013)**
- Состав мер по обеспечению безопасности ПДн
- Организационные и технические меры защиты

**Приказ ФСБ № 378 (10.07.2014)**
- Методические определения угроз безопасности информации

### 2.2 Уровень защищенности информации

Согласно Постановлению Правительства РФ № 1119 и оценке угроз безопасности:

**Уровень защищенности: 4 (базовый)**

Обоснование:
- Объем ПДн: менее 1000 субъектов
- Тип ПДн: общие и специальные (телефоны)
- Нет биометрических ПДн
- Нет специальных категорий ПДн (расовая, национальная принадлежность и т.д.)
- Нет публичного доступа к ПДн
- Данные не обрабатываются в интересах безопасности государства

**Меры защиты для 4-го уровня:**
- Идентификация и аутентификация пользователей
- Контроль доступа к ПДн
- Антивирусная защита
- Защита от НСД (несанкционированного доступа)
- Логирование событий безопасности
- Шифрование ПДн при хранении и передаче

## 3. Анализ обрабатываемых ПДн

### 3.1 Классификация ПДн по источникам

#### 3.1.1 Персональные данные пользователей (сотрудников компании)

**Таблица:** User
| Поле | Тип данных | Категория ПДн | Назначение |
|------|------------|---------------|------------|
| email | string | Общие | Авторизация в админ-панели |
| name | string? | Общие | Идентификация пользователя |
| phone | string? | Специальные | Контакты для связи |
| lastLoginAt | timestamp | Общие | Аудит активности |

#### 3.1.2 Персональные данные клиентов (заявки)

**Таблица:** Order
| Поле | Тип данных | Категория ПДн | Назначение |
|------|------------|---------------|------------|
| clientName | string | Общие | Идентификация клиента |
| phone | string | Специальные | Связь с клиентом |
| email | string? | Общие | Отправка смет и документов |
| measurementAddress | string? | Общие | Выезд на замер |
| measurementDate | timestamp? | Общие | Планирование выезда |

#### 3.1.3 Технические данные (IP-адреса, User Agent)

**Таблицы:** AuditLog, FenceEstimate
| Поле | Тип данных | Категория ПДн | Назначение |
|------|------------|---------------|------------|
| ipAddress | string | Общие | Аудит и безопасность |
| userAgent | string | Общие | Логирование действий |

### 3.2 Операции обработки ПДн

| Операция | Субъект | ПДн | Основание |
|----------|---------|-----|-----------|
| Сбор | Клиенты | clientName, phone, email | Согласие на обработку (ст. 9 ФЗ-152) |
| Хранение | Клиенты | Все ПДн из Order | Необходимость исполнения договора |
| Использование | Сотрудники | Все ПДн | Трудовой договор |
| Передача | Сотрудники | ПДн клиентов | Трудовой договор |
| Удаление | Клиенты | Все ПДн | По запросу субъекта (ст. 17 ФЗ-152) |

### 3.3 Условия обработки ПДн

**Освобождение от уведомления Роскомнадзора (ст. 22 п. 2 ФЗ-152):**
Компания освобождена от уведомления Роскомнадзора об обработке ПДн, так как:
- Обработка ПДн осуществляется исключительно для достижения целей, предусмотренных законом (исполнение договора)
- ПДн не распространяются через СМИ
- ПДн были получены от субъекта ПДн

**Локализация БД (ст. 16 ФЗ-152):**
- Все ПДн хранятся на серверах, расположенных на территории РФ
- Передача ПДн за пределы РФ не осуществляется
- Резервные копии БД также хранятся на серверах в РФ
- При необходимости передаче ПДн за рубеж обеспечиваются все меры защиты в соответствии с ФЗ-152

## 4. Функциональные требования

### 4.1 Политика конфиденциальности

#### FR-001: Страница с Политикой конфиденциальности
**Описание:** Создание публичной страницы с текстом Политики конфиденциальности согласно ФЗ-152

**Acceptance Criteria:**
- [ ] Страница доступна по URL `/privacy-policy`
- [ ] Политика содержит все обязательные разделы согласно ФЗ-152:
  - Сведения об операторе
  - Состав обрабатываемых ПДн
  - Цели обработки ПДн
  - Права субъектов ПДн
  - Третьи лица, которым передаются ПДн
  - Сроки обработки и хранения ПДн
  - Меры защиты ПДн
- [ ] Дата последнего обновления политики
- [ ] Политика оптимизирована для SEO
- [ ] Адаптивная верстка для мобильных устройств

#### FR-002: Согласие на обработку ПДн
**Описание:** Реализация механизма получения согласия на обработку ПДн

**Acceptance Criteria:**
- [ ] Галочка "Я даю согласие на обработку персональных данных" во всех формах:
  - Форма создания заявки
  - Форма обратной связи
  - Форма авторизации (для сотрудников)
- [ ] Согласие явное и осознанное (предустановлено FALSE)
- [ ] Текст согласия содержит ссылку на Политику конфиденциальности
- [ ] Реализована возможность отзыва согласия (через обращение)
- [ ] Согласие хранится в БД с датой и временем получения

### 4.2 Обработка запросов субъектов ПДн

#### FR-003: Форма для отзыва согласия
**Описание:** Форма для отзыва согласия на обработку ПДн

**Acceptance Criteria:**
- [ ] Страница доступна по URL `/data-withdrawal`
- [ ] Форма содержит поля:
  - Email (для идентификации)
  - Текст запроса (опционально)
  - CAPTCHA для защиты от спама
- [ ] После отправки уведомление администратору
- [ ] Автоматическая отправка подтверждения на email пользователя

#### FR-004: Форма запроса на удаление ПДн
**Описание:** Форма для запроса на удаление ПДн (право на забвение)

**Acceptance Criteria:**
- [ ] Страница доступна по URL `/data-deletion`
- [ ] Форма содержит поля:
  - Email или телефон
  - Текст запроса
  - CAPTCHA
- [ ] После отправки запрос поступает на рассмотрение
- [ ] Администратор может:
  - Удалить ПДн клиента (анонимизация)
  - Отклонить запрос (с указанием причины)
- [ ] Логирование всех действий по обработке запроса

#### FR-005: Форма запроса на изменение ПДн
**Описание:** Форма для запроса на изменение/дополнение ПДн

**Acceptance Criteria:**
- [ ] Страница доступна по URL `/data-correction`
- [ ] Форма содержит поля:
  - Текущие ПДн
  - Новые значения
  - Причина изменения
  - CAPTCHA
- [ ] Администратор может принять или отклонить запрос
- [ ] При принятии изменения вносятся в БД
- [ ] Отправка уведомления пользователю

### 4.3 Аудит и логирование

#### FR-006: Логирование операций с ПДн
**Описание:** Логирование всех операций обработки ПДн

**Acceptance Criteria:**
- [ ] Логируются следующие операции:
  - Создание записи с ПДн
  - Чтение ПДн
  - Изменение ПДн
  - Удаление ПДн
  - Экспорт ПДн
  - Передача ПДн третьим лицам
- [ ] Каждая запись содержит:
  - Тип операции
  - ID пользователя, выполнившего операцию
  - ID записи с ПДн
  - Старые и новые значения
  - Дата и время
  - IP-адрес
  - User Agent
- [ ] Логи хранятся не менее 1 года
- [ ] Логи доступны только администраторам

#### FR-007: Уведомления о нарушениях
**Описание:** Уведомления о несанкционированном доступе к ПДн

**Acceptance Criteria:**
- [ ] Автоматическое уведомление администратора при:
  - Неудачных попытках авторизации (5+ подряд)
  - Доступе к ПДн с подозрительного IP
  - Массовом экспорте ПДн
  - Изменении прав доступа к ПДн
- [ ] Уведомления отправляются по email и Telegram
- [ ] Логирование всех инцидентов

## 5. Нефункциональные требования

### 5.1 Безопасность

#### NFR-001: Шифрование ПДн при хранении
**Требование:** Шифрование чувствительных ПДн в БД

**Критерии приемки:**
- [ ] Пароли хешируются с использованием bcrypt (минимум 12 rounds)
- [ ] Телефоны хешируются (односторонний хеш для поиска)
- [ ] Email хешируются или шифруются
- [ ] Ключи шифрования хранятся в секретах (environment variables)
- [ ] Используется алгоритм AES-256 для шифрования

#### NFR-002: Шифрование при передаче
**Требование:** Шифрование всех соединений с передачей ПДн

**Критерии приемки:**
- [ ] Сайт работает только по HTTPS (TLS 1.2+)
- [ ] Настроен HSTS (Strict-Transport-Security)
- [ ] SSL-сертификат валидный
- [ ] Перенаправление с HTTP на HTTPS

#### NFR-003: Контроль доступа к ПДн
**Требование:** RBAC для доступа к ПДн

**Критерии приемки:**
- [ ] Реализована система ролей:
  - ADMIN: полный доступ ко всем ПДн
  - MANAGER: доступ к ПДн только назначенных заказов
  - CONTENT_MANAGER: нет доступа к ПДн
- [ ] JWT токены с временем жизни 24 часа
- [ ] Ротация токенов при изменении прав доступа
- [ ] Логирование всех доступов к ПДн

#### NFR-004: Валидация и санитизация входных данных
**Требование:** Защита от инъекций при вводе ПДн

**Критерии приемки:**
- [ ] Все поля с ПДн валидируются через Zod схемы
- [ ] SQL-инъекции защищены через Prisma ORM
- [ ] XSS-защита (санитизация пользовательского ввода)
- [ ] CSRF-защита на всех формах
- [ ] Rate limiting на API endpoints с ПДн

### 5.2 Сроки хранения

#### NFR-005: Хранение ПДн по срокам
**Требование:** Хранение ПДн не дольше установленного срока

**Критерии приемки:**
- [ ] ПДн клиентов хранятся до истечения срока исковой давности (3 года)
- [ ] По истечении срока автоматическая анонимизация или удаление
- [ ] ПДн сотрудников хранятся в течение 75 дней после увольнения
- [ ] Аудит логи хранятся 1 год
- [ ] Реализован механизм очистки старых данных

#### NFR-006: Архивирование и резервное копирование
**Требование:** Безопасное резервное копирование ПДн

**Критерии приемки:**
- [ ] Ежедневное полное резервное копирование БД
- [ ] Шифрование резервных копий
- [ ] Хранение резервных копий:
  - Локально: 7 дней
  - В облаке: 30 дней
  - Офлайн: 1 месяц
- [ ] Тестирование восстановления из резервных копий (ежемесячно)
- [ ] Логирование операций резервного копирования

### 5.3 Доступность и целостность

#### NFR-007: Отказоустойчивость
**Требование:** Обеспечение доступности системы обработки ПДн

**Критерии приемки:**
- [ ] Время доступности ≥ 99.9%
- [ ] Кластеризация БД (PostgreSQL streaming replication)
- [ ] Балансировка нагрузки (Nginx)
- [ ] Health checks для всех сервисов
- [ ] Мониторинг системы (UptimeRobot + Sentry)

#### NFR-008: Целостность ПДн
**Требование:** Обеспечение неизменности ПДн без ведома оператора

**Критерии приемки:**
- [ ] Все изменения ПДн логируются
- [ ] Цифровая подпись критических операций
- [ ] Регулярные проверки целостности БД
- [ ] Версионирование изменений ПДн

#### NFR-009: Локализация БД в РФ
**Требование:** Хранение ПДн только на серверах в РФ

**Критерии приемки:**
- [ ] Основной сервер БД находится в РФ
- [ ] Резервные копии хранятся в РФ
- [ ] Нет передачи ПДн в зарубежные облачные сервисы
- [ ] При необходимости использования CDN для статики - исключить ПДн
- [ ] Документальное подтверждение локализации серверов

#### NFR-010: WebSocket-уведомления субъектов ПДн
**Требование:** Реалтайм уведомления субъектов ПДн об операциях с их данными через WebSocket

**Критерии приемки:**
- [ ] WebSocket-сервер на базе socket.io или ws
- [ ] Уведомления для клиентов при:
  - Создании заявки (отправляется менеджерам, не клиентам)
  - Изменении статуса заявки (отправляется клиентам)
  - Обработке запроса субъекта на удаление ПДн
  - Обработке запроса субъекта на изменение ПДн
  - Обработке запроса на отзыв согласия
- [ ] Уведомления для менеджеров при:
  - Создании новой заявки
  - Создании запроса субъекта ПДн
  - Подозрительной активности
- [ ] Аутентификация WebSocket соединений через JWT
- [ ] Логирование всех WebSocket событий
- [ ] Rate limiting для WebSocket соединений
- [ ] Визуальные уведомления в браузере (toast/badge)
- [ ] История уведомлений для пользователей

## 6. Техническая архитектура

### 6.1 Изменения в БД

#### Миграция: Добавление таблицы для согласий

```sql
-- Создание таблицы для согласий на обработку ПДн
CREATE TABLE data_consent (
  id VARCHAR(255) PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id VARCHAR(255),
  email VARCHAR(255),
  phone VARCHAR(255),
  consent_type VARCHAR(50) NOT NULL, -- ORDER, CONTACT, AUTH
  consent_text TEXT NOT NULL,
  consent_given_at TIMESTAMP NOT NULL DEFAULT NOW(),
  consent_revoked_at TIMESTAMP,
  ip_address VARCHAR(45),
  user_agent TEXT,
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_data_consent_user_id ON data_consent(user_id);
CREATE INDEX idx_data_consent_email ON data_consent(email);
CREATE INDEX idx_data_consent_phone ON data_consent(phone);
```

#### Миграция: Добавление таблицы для запросов субъектов

```sql
-- Создание таблицы для запросов субъектов ПДн
CREATE TABLE data_subject_request (
  id VARCHAR(255) PRIMARY KEY DEFAULT gen_random_uuid(),
  request_type VARCHAR(50) NOT NULL, -- WITHDRAWAL, DELETION, CORRECTION, ACCESS
  identifier VARCHAR(255) NOT NULL, -- email или телефон
  request_text TEXT,
  status VARCHAR(50) DEFAULT 'PENDING', -- PENDING, APPROVED, REJECTED
  processed_at TIMESTAMP,
  processed_by VARCHAR(255),
  rejection_reason TEXT,
  ip_address VARCHAR(45),
  user_agent TEXT,
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_data_subject_request_status ON data_subject_request(status);
CREATE INDEX idx_data_subject_request_type ON data_subject_request(request_type);
```

### 6.2 API спецификация

#### POST /api/data-consent
**Описание:** Регистрация согласия на обработку ПДн

**Request:**
```json
{
  "consentType": "ORDER",
  "email": "user@example.com",
  "phone": "+79991234567",
  "consentText": "Я даю согласие на обработку персональных данных..."
}
```

**Response 201:**
```json
{
  "id": "clxxx",
  "consentGivenAt": "2026-03-23T12:00:00Z",
  "status": "ACTIVE"
}
```

#### POST /api/data-subject-request
**Описание:** Создание запроса субъекта ПДн

**Request:**
```json
{
  "requestType": "DELETION",
  "identifier": "user@example.com",
  "requestText": "Прошу удалить мои персональные данные"
}
```

**Response 201:**
```json
{
  "id": "clxxx",
  "status": "PENDING",
  "message": "Ваш запрос принят на рассмотрение"
}
```

#### GET /api/admin/data-subject-requests
**Описание:** Получение списка запросов субъектов ПДн (для администраторов)

**Response 200:**
```json
{
  "requests": [
    {
      "id": "clxxx",
      "requestType": "DELETION",
      "identifier": "user@example.com",
      "status": "PENDING",
      "createdAt": "2026-03-23T12:00:00Z"
    }
  ]
}
```

#### PUT /api/admin/data-subject-requests/[id]
**Описание:** Обработка запроса субъекта ПДн

**Request:**
```json
{
  "status": "APPROVED",
  "rejectionReason": null
}
```

**Response 200:**
```json
{
  "id": "clxxx",
  "status": "APPROVED",
  "processedAt": "2026-03-23T14:00:00Z"
}
```

## 11. WebSocket-уведомления для субъектов ПДн

### 11.1 Зачем нужны WebSocket-уведомления?

**Проблема:** Email-уведомления не реализованы, необходим реалтайм канал для уведомлений субъектов ПДн.

**Решение:** WebSocket позволяет отправлять уведомления в реальном времени без задержек и без попадания в спам.

### 11.2 Сценарии использования

| Сценарий | Кому уведомление | Содержание |
|----------|------------------|------------|
| Создание заявки | Менеджеры | "Новая заявка от Иван Иванов (+79991234567)" |
| Изменение статуса заявки | Клиент | "Вашей заявке присвоен статус: Выезд на замер" |
| Обработка запроса на удаление ПДн | Клиент | "Ваши персональные данные были удалены по вашему запросу" |
| Обработка запроса на изменение ПДн | Клиент | "Ваши персональные данные были изменены по вашему запросу" |
| Обработка запроса на отзыв согласия | Клиент | "Ваше согласие на обработку ПДн было отозвано" |
| Подозрительная активность | Администратор | "Обнаружено 5 неудачных попыток входа с IP 1.2.3.4" |

### 11.3 Архитектура

```
┌─────────────┐
│   Client    │ (Browser)
└──────┬──────┘
       │ WebSocket
       ▼
┌─────────────────────────────┐
│   WebSocket Server         │ (Node.js + socket.io)
│   Port: 3002            │
└──────┬──────────────────┘
       │ Redis Adapter
       ▼
┌─────────────────────────────┐
│   Redis Pub/Sub          │ (для масштабирования)
└──────┬──────────────────┘
       │ HTTP API
       ▼
┌─────────────────────────────┐
│   Next.js API            │
│   /api/orders            │
│   /api/data-subject...   │
└─────────────────────────────┘
```

### 11.5 Реализация

**WebSocket Server:**
```typescript
// src/lib/websocket/server.ts
import { Server } from 'socket.io';
import { createAdapter } from '@socket.io/redis-adapter';
import { createClient } from 'redis';

const io = new Server(3002, {
  cors: { origin: process.env.NEXTAUTH_URL }
});

const pubClient = createClient({ url: process.env.REDIS_URL });
const subClient = pubClient.duplicate();

io.adapter(createAdapter({ pubClient, subClient }));

io.use(async (socket, next) => {
  const token = socket.handshake.auth.token;
  // Валидация JWT
  const user = await validateJWT(token);
  socket.data.user = user;
  next();
});

io.on('connection', (socket) => {
  const userId = socket.data.user.id;
  const role = socket.data.user.role;

  // Подписка на персональные уведомления
  socket.join(`user:${userId}`);

  // Подписка по роли
  if (role === 'MANAGER' || role === 'ADMIN') {
    socket.join('managers');
  }

  if (role === 'ADMIN') {
    socket.join('admins');
  }
});

export { io };
```

**Уведомления в API:**

**Notification Provider:**
```typescript
// src/components/notifications/NotificationProvider.tsx
'use client';

import { useEffect } from 'react';
import { useNotificationStore } from '@/stores/notifications';
import { getSocket } from '@/lib/socket';

export default function NotificationProvider({ userId, role }) {
  const addNotification = useNotificationStore(state => state.add);

  useEffect(() => {
    const socket = getSocket();
    if (!socket) return;

    // Уведомления для клиентов
    socket.on('order-status-changed', (data) => {
      addNotification({
        type: 'info',
        title: 'Статус заявки изменен',
        message: data.message,
        read: false
      });
    });

    socket.on('data-deleted', (data) => {
      addNotification({
        type: 'success',
        title: 'Данные удалены',
        message: data.message,
        read: false
      });
    });

    // Уведомления для менеджеров
    if (role === 'MANAGER' || role === 'ADMIN') {
      socket.on('new-order', (data) => {
        addNotification({
          type: 'info',
          title: 'Новая заявка',
          message: `Заявка от ${data.clientName}`,
          read: false
        });
      });
    }

    // Уведомления для админов
    if (role === 'ADMIN') {
      socket.on('security-alert', (data) => {
        addNotification({
          type: 'warning',
          title: 'Предупреждение безопасности',
          message: data.message,
          read: false
        });
      });
    }

    return () => {
      socket.off('order-status-changed');
      socket.off('data-deleted');
      socket.off('new-order');
      socket.off('security-alert');
    };
  }, [userId, role, addNotification]);

  return null;
}
```

### 11.8 Декоратор для уведомлений

Для упрощения использования уведомлений в API:

```typescript
// src/lib/websocket/decorator.ts
export function withNotification<T extends (...args: any[]) => any>(
  handler: T,
  notificationConfig: {
    event: string;
    recipient: (result: ReturnType<T>) => string | string[];
    getData: (result: ReturnType<T>) => any;
  }
): T {
  return (async (...args: Parameters<T>) => {
    const result = await handler(...args);

    // Отправка уведомлений
    const recipients = notificationConfig.recipient(result);
    const data = notificationConfig.getData(result);

    if (Array.isArray(recipients)) {
      recipients.forEach(r => notifyUser(r, notificationConfig.event, data));
    } else {
      notifyUser(recipients, notificationConfig.event, data);
    }

    return result;
  }) as T;
}

// Использование
export const createOrder = withNotification(
  async (data: OrderCreateInput) => {
    return await prisma.order.create({ data });
  },
  {
    event: 'new-order',
    recipient: () => 'managers', // всем менеджерам
    getData: (order) => ({ orderId: order.id, clientName: order.clientName })
  }
);
```
