## 1. Цели и задачи

### 1.1 Бизнес-цель
Посчитанная в калькуляторе навеса итоговая стоимость должна попадать в заявку (Order) и отображаться менеджеру в админ-панели (список + детали). Сейчас стоимость теряется (захардкожен `calculatedCost: 0`), и менеджер видит «Индивидуальный расчёт (0 ₽)».

### 1.2 Пользовательская ценность
- Клиент: заявка отправляется с реальной посчитанной суммой.
- Менеджер: сразу видит стоимость навеса в списке и в деталях, без уточнения у клиента.

### 1.3 Критерии успеха
- Стоимость навеса сохраняется в `Order.calculatedCost` (а не 0).
- В списке заявок навес показывает сумму в формате `N ₽` (как забор).
- В деталях заявки навес показывает сумму (а не «Индивидуальный расчёт»).
- Существующие заявки забора/ворот/multi работают без регрессии.

## 2. Корневая причина (по результатам исследования)

1. Клиент `CanopyNomenclatureNotFoundModal.tsx:141-147` отправляет на `POST /api/orders` тело с `totalCost` и `pricePerSqm` (флаг `isIndividualRequest: true`).
2. `individualOrderSchema` (`src/lib/validators/order.ts:89-101`) **не содержит** `totalCost`/`pricePerSqm` → Zod их отбрасывает ещё до серверной логики.
3. `createIndividualOrder` (`src/app/api/orders/route.ts:415`) пишет `calculatedCost: 0` захардкожено.
4. Админка список (`src/app/(admin)/admin/orders/page.tsx:331-337`) и детали (`OrderDetailPage.tsx:419-425`) при `calculatedCost===0 && !estimateId` показывают «Индивидуальный расчёт (0 ₽)» / «Индивидуальный расчёт».

Доп. баг: в деталях навеса UI читает `parameters.roofMaterialLabel` (`OrderDetailPage.tsx:991-996`), а клиент шлёт `roofCoveringName` (`canopy/page.tsx:174`) → кровля не отображается.

## 3. Функциональные требования

### 3.1 User Stories

#### US-1: Сохранение стоимости навеса
**Given** клиент посчитал навес в калькуляторе (длина×ширина×8500 ₽/м²)
**When** нажимает «Оформить заявку», заполняет форму и отправляет
**Then** создаётся Order с `calculatedCost` = посчитанной сумме
**And** `parameters` сохраняет `pricePerSqm` (для контекста менеджеру)

#### US-2: Список заявок
**Given** менеджер открыт список `/admin/orders`
**When** есть заявка-навес с ненулевой `calculatedCost`
**Then** в колонке «Сумма» отображается `formatCurrency(calculatedCost)` (например `127 500 ₽`)
**And** NOT отображается «Индивидуальный расчёт (0 ₽)»

#### US-3: Детали заявки
**Given** менеджер открыт детали заявки-навеса
**When** `calculatedCost > 0` и это навес
**Then** в шапке отображается сумма `formatCurrency(effectiveGrandTotal)`
**And** NOT отображается «Индивидуальный расчёт»
**And** секция параметров навеса отображается корректно (включая кровлю)

## 4. Технические требования

### 4.1 Без миграции БД
Поле `Order.calculatedCost Float` уже существует. Новых таблиц/связей НЕ заводим (scope = «только итоговая сумма»).

### 4.2 Изменения

#### TASK-BCK-001: Валидатор `individualOrderSchema`
Файл: `src/lib/validators/order.ts`
- Добавить опциональные поля `totalCost: z.number().nonnegative().optional()` и `pricePerSqm: z.number().nonnegative().optional()` в `individualOrderSchema`.
- Эти поля прокидываются в `validatedData` для серверной логики.

#### TASK-BCK-002: Сохранение стоимости в `createIndividualOrder`
Файл: `src/app/api/orders/route.ts` (ветка `createIndividualOrder`, ~`route.ts:385-471`)
- Заменить `calculatedCost: 0` на `calculatedCost: validatedData.totalCost ?? 0`.
- В `parameters` сохранить `pricePerSqm` (если пришёл) — для контекста.
- В ответе возвращать реальную `calculatedCost`, а не `0`.
- **Не сломать** гараж и индивидуальные заявки без `totalCost` (для них остаётся 0).

#### TASK-FRT-001: Список заявок — показ стоимости навеса
Файл: `src/app/(admin)/admin/orders/page.tsx` (~`:331-337` desktop, `:454-457` mobile)
- Условие «индивидуальный расчёт / 0 ₽» уточнить: показывать сумму, если `calculatedCost > 0` (даже без `estimateId`).
- Если `calculatedCost === 0` — оставить текущий текст.

#### TASK-FRT-002: Детали заявки — показ суммы для навеса
Файл: `src/components/admin/Orders/OrderDetailPage.tsx` (~`:319-320, 419-425`)
- Уточнить `isIndividualRequest`: если `calculatedCost > 0` — НЕ считать «индивидуальным расчётом» для блока стоимости (показать `effectiveGrandTotal`).
- Сохранить текущее поведение для гаража и заявок с 0.

#### TASK-FRT-003: Фикс отображения кровли в деталях навеса (бонус, по дороге)
Файл: `src/components/admin/Orders/OrderDetailPage.tsx` (~`:991-996`)
- Читать `roofCoveringName` в дополнение к `roofMaterialLabel` (маппинг поля, которое реально шлёт клиент).

### 4.3 Логирование (Правило 8)
- В `createIndividualOrder` добавить логирование: `logger.info` при создании заявки-навеса с указанием `totalCost`, `calculatedCost`, `serviceType`. `logger.error` в catch-блоке (если уже есть — проверить контекст).

### 4.4 Автотесты (Правило 8, покрытие ≥ 60%)
- `__tests__/api/orders/canopy-cost.test.ts` (или расширить существующий тест orders):
  - Happy path: POST `/api/orders` с `isIndividualRequest + canopyParameters + totalCost` → Order создан с `calculatedCost = totalCost`.
  - Без `totalCost` (гараж/индивидуалка) → `calculatedCost = 0` (регрессия).
  - Валидация: отрицательный/невалидный `totalCost` отсекается.
- При необходимости — снапшот/юнит на изменённые UI-условия админки.
