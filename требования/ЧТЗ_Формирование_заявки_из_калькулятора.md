## 1. Цели и задачи

### 1.1 Бизнес-цель
Обеспечить конверсию посетителей сайта в заявки через калькулятор. Клиент получает расчет стоимости и может оформить заявку, которая попадает менеджеру с полной информацией о потребностях клиента.

### 1.2 Пользовательская ценность
Клиент может быстро оформить заявку на расчетанный забор без повторного ввода параметров. Менеджер получает заявку с готовой сметой и может связаться с клиентом.

### 1.3 Ключевые метрики успеха
- Конверсия из расчета в заявку: целевой показатель
- Время оформления заявки: < 30 секунд
- Корректность связи заявки с расчетом: 100%

## 2. Функциональные требования

### 2.1 User Stories

#### US-1: Оформление заявки клиентом
**Как** клиент,  
**Я хочу** оформить заявку на забор после расчета в калькуляторе,  
**Чтобы** менеджер связался со мной для обсуждения заказа.

**Acceptance Criteria**:
```
Given я выполнил расчет в калькуляторе
When нажимаю "Оформить заявку"
Then открывается форма с полями: Имя, Телефон, Email, Сообщение
And поля Имя и Телефон обязательны
And телефон валидируется по формату +7 (XXX) XXX-XX-XX
When заполняю форму и нажимаю "Отправить заявку"
Then заявка создается со статусом "Новая"
And заявка содержит ссылку на расчет
And показывается сообщение об успешной отправке
```

#### US-2: Просмотр заявки в админ-панели
**Как** менеджер,  
**Я хочу** видеть заявки в админ-панели,  
**Чтобы** обрабатывать их и связываться с клиентами.

**Acceptance Criteria**:
```
Given я нахожусь в админ-панели
When открываю вкладку "Заявки"
Then вижу список заявок
And колонки: ID, Дата, Клиент, Телефон, Сумма, Статус
And новые заявки отображаются со статусом "Новая"
And есть ссылка на смету расчета
```

#### US-3: Просмотр сметы из заявки
**Как** менеджер,  
**Я хочу** открыть смету расчета из заявки,  
**Чтобы** видеть все параметры и стоимость.

**Acceptance Criteria**:
```
Given я нахожусь в деталях заявки
When кликаю на ссылку сметы
Then открывается страница с полной детализацией расчета
And вижу все параметры: тип забора, размеры, материалы, работы
And вижу детализацию стоимости по категориям
And вижу итоговую сумму
```

#### US-4: Изменение статуса заявки
**Как** менеджер,  
**Я хочу** менять статус заявки,  
**Чтобы** отслеживать этапы работы с клиентом.

**Acceptance Criteria**:
```
Given я нахожусь в деталях заявки
When выбираю новый статус из списка
Then статус сохраняется
And история статусов записывается

Статусы: Новая → Согласование сметы → Замер → Производство → Монтаж → Выполнена
Также доступен статус "Отменена" из любого состояния
```

### 2.2 Статусная модель заявок

| Код | Статус | Описание | Переходы |
|-----|--------|----------|----------|
| NEW | Новая | Заявка создана, не обработана | → ESTIMATE_APPROVAL, CANCELLED |
| ESTIMATE_APPROVAL | Согласование сметы | Менеджер обсуждает смету с клиентом | → MEASUREMENT, CANCELLED |
| MEASUREMENT | Замер | Назначен выезд на замер | → PRODUCTION, CANCELLED |
| PRODUCTION | Производство | Материалы в производстве | → INSTALLATION, CANCELLED |
| INSTALLATION | Монтаж | Установка забора | → COMPLETED |
| COMPLETED | Выполнена | Заказ завершен | — |
| CANCELLED | Отменена | Клиент отказался | — |

### 2.3 Решение проблемы параллельных сессий

**Проблема**: Несколько пользователей одновременно используют калькулятор. Нужно гарантировать, что заявка свяжется с правильным расчетом.

**Решение**: Session ID в httpOnly cookies сроком на 1 час.

```typescript
// src/lib/session.ts

// При первом визите генерируем sessionId
sessionId = crypto.randomUUID()

// Сохраняем в httpOnly cookie сроком на 1 час
Set-Cookie: session_id=<uuid>; HttpOnly; SameSite=Strict; Max-Age=3600; Path=/

// При сохранении расчета в FenceEstimate сохраняем sessionId
// При создании заявки берем sessionId из cookie и находим расчет
```

**Почему 1 час**:
- Пользователь успеет заполнить форму и отправить заявку
- Минимальный риск путаницы при нескольких вкладках
- При истечении сессии пользователь увидит сообщение и сможет пересчитать

**Обработка истекшей сессии**:
```
If sessionId не найден в БД (истек или не существует):
  - Показать сообщение: "Время сессии истекло. Пожалуйста, выполните расчет заново."
  - Перенаправить на калькулятор
```

## 4. Техническая архитектура

### 4.1 Изменения в схеме БД

```sql
-- Создать новый enum OrderStatus с расширенными статусами
CREATE TYPE "OrderStatus_new" AS ENUM (
  'NEW',
  'ESTIMATE_APPROVAL',
  'MEASUREMENT',
  'PRODUCTION',
  'INSTALLATION',
  'COMPLETED',
  'CANCELLED'
);

-- Добавить связь с FenceEstimate
ALTER TABLE "Order" ADD COLUMN "estimateId" TEXT;
ALTER TABLE "Order" ADD CONSTRAINT "Order_estimateId_fkey" 
  FOREIGN KEY ("estimateId") REFERENCES "FenceEstimate"("id") ON DELETE SET NULL;

-- Добавить индекс для быстрого поиска
CREATE INDEX "Order_estimateId_idx" ON "Order"("estimateId");
CREATE INDEX "Order_status_idx" ON "Order"("status");

-- Удалить старый enum и переименовать новый
ALTER TABLE "Order" ALTER COLUMN status TYPE "OrderStatus_new" USING status::text::"OrderStatus_new";
DROP TYPE "OrderStatus_old";
```

### 4.2 API спецификация

#### POST /api/orders
Создание заявки из калькулятора.

**Request**:
```json
{
  "clientName": "Иван Петров",
  "phone": "+7 (900) 123-45-67",
  "email": "ivan@example.com",
  "message": "Интересует монтаж в выходные"
}
```

**Response (201)**:
```json
{
  "id": "clt123abc",
  "status": "NEW",
  "statusLabel": "Новая",
  "estimateId": "est456def",
  "calculatedCost": 165000,
  "createdAt": "2026-03-15T10:30:00Z"
}
```

**Response (400 - сессия истекла)**:
```json
{
  "error": "SESSION_EXPIRED",
  "message": "Время сессии истекло. Пожалуйста, выполните расчет заново."
}
```

| page | number | Страница (default: 1) |

| status | string | Фильтр по статусу |
| dateFrom | string | Дата с |

**Response**:
