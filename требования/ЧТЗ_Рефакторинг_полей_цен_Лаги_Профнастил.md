## 2. Цели и задачи

### 2.1 Бизнес-цель
Устранить несоответствие между названием полей `retailPricePerMeter` / `purchasePricePerMeter` (цена за погонный метр) и фактическим содержимым — администраторы вводят цену за единицу (целую лагу/лист). Названия полей должны соответствовать хранимым данным.

### 2.2 Пользовательская ценность
- Устранение путаницы при вводе цен администраторами
- Понятные названия полей в интерфейсе
- Корректное отображение tooltip-подсказок

### 2.3 Ключевые метрики успеха
- Названия полей соответствуют хранимым данным
- Калькулятор корректно считает: `totalPrice = quantity × pricePerUnit`
- Все тесты проходят

## 3. Анализ текущей ситуации

### 3.1 Проблема

| Справочник | Поле в БД | Что хранится фактически |
|------------|-----------|------------------------|
| LagType | `retailPricePerMeter` | Цена за целую лагу |
| LagType | `purchasePricePerMeter` | Цена за целую лагу |
| ProfnastilType | `retailPricePerMeter` | Цена за целый лист |
| ProfnastilType | `purchasePricePerMeter` | Цена за целый лист |

### 3.2 Пример данных (Лаги)

| Название | Длина | retailPricePerMeter | Реальный смысл |
|----------|-------|---------------------|----------------|
| ЛАГА 40x20 1.5мм | 3 м | 520 руб | 520 руб за 3-метровую лагу |
| ЛАГА 40x20 1.5мм | 6 м | 1040 руб | 1040 руб за 6-метровую лагу |

### 3.3 Ошибка в калькуляторах

**lagCalculator.ts:63** (неверно):
```typescript
const pricePerUnit = selectedLag.retailPricePerMeter * (lagLengthMm / 1000);
// 520 × 3 = 1560 ← неверно! Должно быть просто 520
```

**profnastilCalculator.ts:63** (неверно):
```typescript
const pricePerUnit = selectedProfnastil.retailPricePerMeter * (selectedProfnastil.length / 1000);
// 550 × 2 = 1100 ← неверно! Должно быть просто 550
```

## 4. Решение

### 4.1 Переименование полей

| Таблица | Было | Станет |
|---------|------|--------|
| LagType | `retailPricePerMeter` | `retailPricePerUnit` |
| LagType | `purchasePricePerMeter` | `purchasePricePerUnit` |
| ProfnastilType | `retailPricePerMeter` | `retailPricePerUnit` |
| ProfnastilType | `purchasePricePerMeter` | `purchasePricePerUnit` |

### 4.2 Изменение формулы расчета

**Было:**
```typescript
const pricePerUnit = retailPricePerMeter * (length / 1000);
const totalPrice = quantity * pricePerUnit;
```

**Станет:**
```typescript
const totalPrice = quantity * retailPricePerUnit;
```

### 4.3 Миграция данных

Значения остаются без изменений (перенос 1:1), т.к. в поле уже хранится цена за единицу:

```sql
-- Данные не пересчитываются, просто переименовываются колонки
ALTER TABLE "LagType" RENAME COLUMN "retailPricePerMeter" TO "retailPricePerUnit";
ALTER TABLE "LagType" RENAME COLUMN "purchasePricePerMeter" TO "purchasePricePerUnit";
ALTER TABLE "ProfnastilType" RENAME COLUMN "retailPricePerMeter" TO "retailPricePerUnit";
ALTER TABLE "ProfnastilType" RENAME COLUMN "purchasePricePerMeter" TO "purchasePricePerUnit";
```

## 6. Детальные изменения

### 6.1 Калькулятор Лаг (lagCalculator.ts)

**Было:**
```typescript
const pricePerUnit = selectedLag.retailPricePerMeter * (lagLengthMm / 1000);
const totalPrice = totalLags * pricePerUnit;
```

**Станет:**
```typescript
const pricePerUnit = selectedLag.retailPricePerUnit;
const totalPrice = totalLags * pricePerUnit;
```

### 6.2 Калькулятор Профнастила (profnastilCalculator.ts)

**Было:**
```typescript
const pricePerUnit = selectedProfnastil.retailPricePerMeter * (selectedProfnastil.length / 1000);
const totalPrice = sheetsCount * pricePerUnit;
```

**Станет:**
```typescript
const pricePerUnit = selectedProfnastil.retailPricePerUnit;
const totalPrice = sheetsCount * pricePerUnit;
```

### 6.3 Валидаторы

**lagType.ts:**
```typescript
// БЫЛО
retailPricePerMeter: z.number().min(0, 'Розничная стоимость должна быть не менее 0'),
purchasePricePerMeter: z.number().min(0, 'Цена закупки должна быть не менее 0').nullable().optional(),

// СТАНЕТ
retailPricePerUnit: z.number().min(0, 'Розничная стоимость должна быть не менее 0'),
purchasePricePerUnit: z.number().min(0, 'Цена закупки должна быть не менее 0').nullable().optional(),
```

**profnastilType.ts:**
```typescript
// БЫЛО
purchasePricePerMeter: z.number().min(0, 'Цена закупки должна быть не менее 0').nullable().optional(),
retailPricePerMeter: z.number().min(0, 'Розничная стоимость должна быть не менее 0'),

// СТАНЕТ
purchasePricePerUnit: z.number().min(0, 'Цена закупки должна быть не менее 0').nullable().optional(),
retailPricePerUnit: z.number().min(0, 'Розничная стоимость должна быть не менее 0'),
```

### 6.4 Tooltips (columnTooltips.ts)

**Было:**
```typescript
retailPricePerMeter: 'Розничная цена за один метр погонный в рублях',
purchasePricePerMeter: 'Цена закупки за один метр погонный в рублях (только для ADMIN)',
```

**Станет:**
```typescript
retailPricePerUnit: 'Розничная цена за единицу (целую лагу) в рублях',
purchasePricePerUnit: 'Цена закупки за единицу (целую лагу) в рублях (только для ADMIN)',
```

### 6.5 Утилита priceCalculator.ts

Функция `calculatePricePerUnit` больше не нужна для лаг и профнастила, т.к. цена уже хранится за единицу.

**Решение:** Удалить функцию `calculatePricePerUnit` или оставить для других справочников (евроштакетник), где она используется.

Для евроштакетника и пикета — оставить как есть, т.к. там другая логика (цена за м² × площадь).

## 14. Примечания

### 14.1 Почему не пересчитываем данные

В полях `retailPricePerMeter` и `purchasePricePerMeter` уже хранятся цены за единицу (целую лагу/лист). Менеджеры вводили их как цену за штуку, несмотря на название поля. Поэтому при миграции данные просто переносятся 1:1.

### 14.2 Влияние на другие справочники

Данное изменение **не затрагивает**:
- PostType (столбы) — там цена за метр корректна
- PicketType (евроштакетник) — там своя логика расчета
- GateType (ворота) — там цена за ворота
- WicketType (калитки) — там цена за калитку
