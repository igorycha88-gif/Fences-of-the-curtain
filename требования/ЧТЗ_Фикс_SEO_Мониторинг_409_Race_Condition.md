# ЧТЗ: Фикс 409 Conflict при старте SEO-сбора (Race Condition)

## Описание проблемы

При нажатии кнопки «Собрать сейчас» на странице SEO-мониторинга:
1. POST возвращает 202, запускает `startBatchSession()` fire-and-forget
2. Frontend начинает polling немедленно (5 сек)
3. **Но**: `startBatchSession()` сначала делает DB-запрос, ПОТОМ сохраняет сессию в Redis
4. Первый poll приходит **до** сохранения сессии → видит `{ active: false }` → **останавливает polling**, сбрасывает UI
5. Кнопка снова доступна → повторный клик → **409 Conflict** (сессия уже в Redis)
6. Через 30 сек сессия завершается → уведомление «готово», но в логах ошибка 409

## Корневая причина

**Race condition** между:
- Сохранением сессии в Redis (асинхронный DB-запрос + Redis SET)
- Первым polling-запросом (через 5 сек после 202)

## Маршрут: Разработчик (баг-фикс)

## Изменяемые файлы

1. `src/app/(admin)/admin/seo-monitoring/page.tsx` — защита от преждевременной остановки polling
2. `src/services/seo/positionCollector.ts` — очистка Redis при ошибке в runSessionBatches

## Критерии приёмки

1. После нажатия «Собрать сейчас» polling НЕ останавливается преждевременно
2. 409 НЕ возникает при корректном первом нажатии
3. Если сессия реально уже запущена — 409 работает корректно и polling подхватывает прогресс
4. При ошибке во время сбора Redis-ключ сессии удаляется (предотвращает stuck-сессии)
