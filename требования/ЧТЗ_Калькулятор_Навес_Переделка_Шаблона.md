# ЧТЗ: Переделка шаблона клиентского калькулятора навесов

**Дата:** 2026-06-03
**Маршрут:** Стандартная задача (Маршрут 1): Аналитик → Разработчик → Тестировщик → DevOps
**Исполнитель:** Разработчик (Fullstack)

---

## 1. Описание задачи

Переделать клиентский (публичный) калькулятор навесов (`/calculator/canopy`), чтобы выпадающие списки загружались из справочников БД, а не были захардкожены. Поля «Тип навеса» и «Назначение» остаются на основе существующих справочников (enum/label). Поля «Столбы» и «Материал кровли» — из БД. Тип установки — из текущего справочника.

---

## 2. Требуемые поля формы (по порядку)

| # | Поле | Тип | Источник данных |
|---|------|-----|-----------------|
| 1 | Тип навеса | Выпадающий список | Существующий справочник «Тип крыши» (`CanopyRoofType` enum: SINGLE_SLOPE, DOUBLE_SLOPE, ARCH, SINGLE_SLOPE_CURVED) |
| 2 | Назначение | Выпадающий список | Текущий справочник (hardcoded: car-1, car-2, car-3, gazebo, terrace, storage) |
| 3 | Столбы | Выпадающий список | Справочник «Столбы для навеса» → `TrussProfileType` с `category=POST` (из БД через новый публичный API) |
| 4 | Высота | Числовое поле | min=2, max=6, step=0.1 (м) |
| 5 | Длина | Числовое поле | min=3, max=50 (м) |
| 6 | Ширина | Числовое поле | min=2, max=20 (м) |
| 7 | Материал кровли | Выпадающий список | Справочник «Покрытие крыши» → `TrussRoofCovering` (из БД через новый публичный API) |
| 8 | Тип установки | Выпадающий список | Текущий справочник (hardcoded: ground, wall, base) |
| 9 | Водосточная система | Галочка (checkbox) | boolean |

## 3. Изменения

### 3.1. Новые публичные API-эндпоинты (BCK)

#### `GET /api/calculator/canopy-profiles?category=POST`
- Возвращает активные (`isActive: true`) профили из `TrussProfileType` с фильтром по `category`
- Поля: `id`, `name`, `retailPricePerMeter`, `retailPricePerUnit`
- Кеширование: Redis cache, TTL 300с (по аналогии с `picket-profile-types`)
- Без авторизации (публичный)

#### `GET /api/calculator/canopy-roof-coverings`
- Возвращает активные (`isActive: true`) покрытия из `TrussRoofCovering`
- Поля: `id`, `name`, `retailPricePerSqm`, `thickness`
- Кеширование: Redis cache, TTL 300с
- Без авторизации (публичный)

## 4. Критерии приёмки

1. Калькулятор навесов (`/calculator/canopy`) отображает 9 полей в указанном порядке
2. «Столбы» — выпадающий список из БД (TrussProfileType, category=POST, isActive=true)
3. «Материал кровли» — выпадающий список из БД (TrussRoofCovering, isActive=true)
4. «Тип навеса» — 4 варианта: Односкатная, Двускатная, Арочная, Односкатная в дуге
5. «Назначение» и «Тип установки» — без изменений (hardcoded)
6. Расчёт использует цены из БД (пост и покрытие), а не hardcoded
7. Заявка (индивидуальный запрос) передаёт корректные названия столба и покрытия
8. Все автотесты проходят: `npm test && npm run lint && npx tsc --noEmit`
