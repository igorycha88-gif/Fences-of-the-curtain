## 2. Описание проблемы

Страница справочника "Столбы" (`/admin/references/posts`) периодически зависает при первой загрузке.

**Характеристики проблемы:**
- Зависание происходит при первой загрузке страницы
- Количество записей в справочнике: ~20 (небольшое)
- Ошибок в консоли браузера и логах сервера не наблюдается
- Docker контейнеры работают корректно

**Последствия:**
- Пользователь не может работать со справочником столбов
- Снижение пользовательского опыта
- Потенциальные проблемы при работе с данными

## 3. Диагностика

На основе архитектурного анализа (ADR-001) выявлены следующие проблемы:

### 3.1 Критические проблемы

#### Проблема 1: Ошибка валидации данных (BUG-001)
**Файл:** `/src/lib/validators/postType.ts`

**Описание:**
Схема валидации `postTypeBaseSchema` включает поле `pricePerMeter` (строка 19), но это поле отсутствует в модели Prisma `PostType`.

**Последствия:**
- При сохранении/редактировании столба через API может происходить ошибка валидации
- Серверный валидатор Zod ожидает поле, которого нет в БД
- Потенциальные проблемы при отправке формы

**Исправление:**
Удалить поле `pricePerMeter` из `postTypeBaseSchema`.

---

#### Проблема 2: Некорректная логика фильтрации (BUG-002)
**Файл:** `/src/services/admin/postTypeService.ts` (строки 85-94)

**Описание:**
При `validityFilter === 'active'` используется некорректная логика для добавления условия `activeCondition`:

```typescript
where.AND = where.AND ? [...(Array.isArray(where.AND) ? where.AND : [where.AND]), activeCondition] : [activeCondition];
```

**Последствия:**
- При сложных условиях структура `where` может стать некорректной
- Неожиданные результаты запросов
- Ошибки Prisma при выполнении запроса
- Медленные запросы из-за неправильного планирования

**Исправление:**
Переписать логику фильтрации с упрощённым подходом.

---

### 3.2 Проблемы производительности

#### Проблема 3: Отсутствие мемоизации компонентов (PERF-001)
**Файлы:**
- `/src/components/admin/References/DataTable.tsx`
- `/src/components/admin/References/RelatedMountingHardware.tsx`
- `/src/components/admin/Works/RelatedWorksByReference.tsx`
- `/src/components/admin/References/shared/PriorityColumn.tsx`

**Описание:**
Компоненты ререндерятся при каждом изменении родительского состояния, даже если их props не изменились.

**Последствия:**
- Лишние ререндеры компонентов
- Уменьшение производительности при большом количестве столбов
- Потенциальные зависания UI при медленных операциях

**Исправление:**
- Мемоизировать функцию `renderCell` через `useCallback`
- Мемоизировать компоненты через `React.memo`
- Использовать `useMemo` для вычисляемых значений

---

#### Проблема 4: Отсутствие кэширования запросов (PERF-002)
**Файл:** `/src/app/api/admin/post-types/route.ts`

**Описание:**
API endpoint `/api/admin/post-types` не использует кэширование Redis.

**Последствия:**
- Бессмысленные запросы к БД для одних и тех же данных
- Увеличение нагрузки на БД
- Потенциальные задержки при медленных запросах

**Исправление:**
Добавить кэширование результатов запросов в Redis с TTL = 60 секунд.

---

#### Проблема 5: Отсутствие детального логирования (DIAG-001)
**Файлы:**
- `/src/app/api/admin/post-types/route.ts`
- `/src/services/admin/postTypeService.ts`

**Описание:**
Нет детальных логов для диагностики производительности и проблем.

**Последствия:**
- Сложность диагностики проблем при их возникновении
- Невозможность отследить время выполнения запросов
- Невозможность отследить количество записей

**Исправление:**
Добавить детальное логирование для диагностики производительности.

**Переписать логику фильтрации:**

```typescript
// Вариант 1: Использовать Prisma Query Builder
if (validityFilter === 'active') {
  where.active = true;
  const activeCondition = {
    OR: [
      { expirationDate: null },
      { expirationDate: { gt: now } },

  if (where.OR) {
```

### Изменения в `/src/lib/apiCache.ts` (новый файл)

```typescript
import { redis } from '@/lib/redis';

export async function getCachedData<T>(key: string, fetcher: () => Promise<T>, ttl: number = 60): Promise<T> {
  const cached = await redis.get(key);
  if (cached) {
    return JSON.parse(cached);
  }

  const data = await fetcher();
  await redis.set(key, JSON.stringify(data), 'EX', ttl);
  return data;
}

export async function invalidateCache(pattern: string): Promise<void> {
  const keys = await redis.keys(pattern);
  if (keys.length > 0) {
    await redis.del(...keys);
  }
}
```

## 8. Риски и минимизация

| Риск | Вероятность | Влияние | Меры минимизации |
|-------|--------------|-----------|------------------|
| Кэширование может вернуть устаревшие данные | Низкая | Среднее | Использовать короткий TTL (60 секунд), инвалидировать при изменениях |
| Мемоизация может не дать эффекта | Средняя | Низкое | Проверить через React DevTools, измерить время ререндеров |
| Изменение фильтрации может сломать существующую логику | Низкая | Высокое | Тщательное тестирование всех комбинаций фильтров |
| Удаление `pricePerMeter` может сломать что-то другое | Низкая | Среднее | Проверить все использования `postTypeSchema` и `postTypeUpdateSchema` |
