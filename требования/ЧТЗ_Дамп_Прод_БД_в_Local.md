# ЧТЗ: Полный дамп БД с прода → локальная dev-БД

**Тип:** инфраструктурная задача (Маршрут 3: Аналитик → DevOps)
**Дата:** 2026-09-22

## 1. Цель

Синхронизировать локальную dev-БД с продакшн-данными: полный дамп `fences` с VPS 37.143.13.196 → локальный контейнер `fences-db-dev` (localhost:5433).

## 2. План

1. Pre-flight: SSH-доступ, место на VPS, доступность прод-БД.
2. Бэкап на самом проде: `pg_dump -U postgres -h 127.0.0.1 fences | gzip` → `/root/Fences-of-the-curtain/backups/` (не удалять — это штатный бэкап).
3. Скачивание дампа локально (временная директория вне репозитория — данные персональные).
4. Страховочный дамп текущей локальной БД.
5. Восстановление: `DROP DATABASE fences WITH (FORCE)` → `CREATE DATABASE fences` → `psql < dump.sql`.
6. Пост-шаги: очистка Redis-кеша справочников (`calculator:*`), рестарт `fences-app-dev`.
7. Верификация: счётчики таблиц, `/api/calculator/fence-types` показывает реальные типы, smoke расчёт «Сетка-рабица» без лаг.

## 3. Критерии приёмки

- [ ] Дамп создан на проде (backups/) и скачан локально
- [ ] Локальная БД содержит прод-данные (fenceType ≥ 4, справочники не пустые)
- [ ] Приложение healthy, API отдаёт реальные типы заборов
- [ ] Redis-кеш сброшен (нет устаревших справочников)
- [ ] Smoke: расчёт «Сетка-рабица» через живой API — без лаг

## 4. Ограничения

- Прод НЕ изменяется (только чтение + штатный бэкап-файл).
- Дамп с персональными данными хранится только во временной папке, в git не попадает.
