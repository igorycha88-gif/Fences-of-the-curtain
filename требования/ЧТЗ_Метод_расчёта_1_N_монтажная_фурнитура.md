## 2. Цели и задачи

### 2.1 Бизнес-цель
Добавить интуитивно понятный метод расчёта "1/N", где 1 единица фурнитуры распределяется на N единиц связанной номенклатуры.

### 2.2 Пользовательская ценность
- Интуитивная настройка расчёта без дробных чисел
- Пример: "1 мешок цемента на 4 столба" вместо "коэффициент 0.25"
- Снижение ошибок при настройке фурнитуры

### 2.3 Ключевые метрики успеха
- Новый метод BY_INVERSE_RATIO доступен в выпадающем списке
- Расчёт работает корректно: `ceil(кол-во_номенклатуры / N)`
- Администраторы понимают метод без дополнительных объяснений

---

## 3. Текущее состояние

### 3.1 Существующие методы расчёта

| Метод | Формула | Пример |
|-------|---------|--------|
| BY_QUANTITY | кол-во = кол-во_номенклатуры | 6 столбов → 6 заглушек |
| BY_LENGTH | кол-во = ceil(длина / длина_ед) | 10м / 2м = 5 планок |
| BY_AREA | кол-во = ceil(площадь / площадь_ед) | 20м² / 4м² = 5 планок |
| BY_RATIO | кол-во = ceil(кол-во * коэф) | 8 листов × 8 = 64 самореза |

### 3.2 Проблема
Метод BY_RATIO с коэффициентом < 1 не интуитивен:
- Коэффициент 0.25 = "1 единица фурнитуры на 4 единицы номенклатуры"
- Пользователи ошибаются при вводе дробных чисел
- Требуется обучение

---

## 4. Предлагаемое решение

### 4.1 Новый метод: BY_INVERSE_RATIO (1/N)

**Формула:**
```
количество_фурнитуры = ceil(количество_номенклатуры / N)
```

**Где:**
- N — целое число ≥ 1
- 1 единица фурнитуры распределяется на N единиц номенклатуры

### 4.2 Примеры использования

| Сценарий | N | Кол-во номенклатуры | Расчёт | Результат |
|----------|---|---------------------|--------|-----------|
| 1 мешок цемента на 4 столба | 4 | 6 столбов | ceil(6/4) | 2 мешка |
| 1 заглушка на 2 лаги | 2 | 12 лаг | ceil(12/2) | 6 заглушек |
| 1 пластина на 3 листа | 3 | 8 листов | ceil(8/3) | 3 пластины |
| 1 уплотнитель на 1 лист | 1 | 8 листов | ceil(8/1) | 8 уплотнителей |

### 4.3 Сравнение с BY_RATIO

| BY_RATIO (коэф < 1) | BY_INVERSE_RATIO (1/N) |
|---------------------|------------------------|
| Коэффициент: 0.25 | N: 4 |
| Коэффициент: 0.5 | N: 2 |
| Коэффициент: 0.333... | N: 3 |
| Неинтуитивно | Интуитивно понятно |

## 6. Техническая архитектура

### 6.1 Изменения в валидаторе

```typescript
const CalculationMethodEnum = z.enum([
  'BY_QUANTITY',
  'BY_LENGTH',
  'BY_AREA',
  'BY_RATIO',
  'BY_INVERSE_RATIO'  // НОВЫЙ
]);

const mountingHardwareBaseSchema = z.object({
  // ... существующие поля
  calculationMethod: CalculationMethodEnum.nullable(),
  calculationValue: z.number().positive().nullable().optional(),
  inverseRatioN: z.number().int().min(1).max(10000).nullable().optional(), // НОВОЕ ПОЛЕ
}).refine(
  (data) => {
    if (data.calculationMethod === 'BY_INVERSE_RATIO') {
      return data.inverseRatioN !== null && data.inverseRatioN >= 1;
    }
    return true;
  },
  { message: "Укажите значение N для метода 1/N" }
);
```

### 6.2 Изменения в схеме данных

**Вариант 1: Использовать существующее поле calculationValue**
- `calculationValue` используется для всех методов
- Для BY_INVERSE_RATIO хранит значение N
- Плюс: не требуется миграция БД

**Вариант 2: Добавить новое поле inverseRatioN**
- Отдельное поле для метода BY_INVERSE_RATIO
- Плюс: валидация на уровне типа
- Минус: миграция БД

**Рекомендация:** Вариант 1 (использовать calculationValue)

### 6.3 Изменения в сервисе расчёта

```typescript
function calculateMountingHardwareQuantity(
  method: CalculationMethod,
  value: number | null,
  params: {
    quantity?: number;
    length?: number;
    area?: number;
  }
): number {
  switch (method) {
    case 'BY_QUANTITY':
      return params.quantity || 0;
    case 'BY_LENGTH':
      return Math.ceil((params.length || 0) / (value || 1));
    case 'BY_AREA':
      return Math.ceil((params.area || 0) / (value || 1));
    case 'BY_RATIO':
      return Math.ceil((params.quantity || 0) * (value || 1));
    case 'BY_INVERSE_RATIO':  // НОВЫЙ
      return Math.ceil((params.quantity || 0) / (value || 1));
    default:
      return 0;
  }
}
```
