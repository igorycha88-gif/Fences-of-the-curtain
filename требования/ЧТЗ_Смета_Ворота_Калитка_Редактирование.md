# ЧТЗ: Смета ворот/калиток — отображение и редактирование в админке

> Дата: 2026-05-18
> Маршрут: Стандартный (Маршрут 1)
> Исполнитель: Разработчик

---

## 1. Описание задачи

Заявки из калькулятора ворот и калиток (`GateEstimate`) должны в админке показывать полную смету с номенклатурами (как у заборов) и иметь возможность редактирования: добавление/удаление номенклатур, изменение кол-ва.

Сейчас в админке заявки ворот/калиток отображаются только с JSON-снимком параметров в `order.parameters`. Смета с позициями (ворота, калитки, автоматика, работы) не показывается. Редактирование невозможно.

---

## 2. Контекст

### Существующая реализация для заборов:

- **Модель БД:** `FenceEstimate` с полями `isEditedByAdmin`, `editedByAdminId`, `editedAt`, `editComment`, `manualQuantityOverrides`, `sourceEstimateId`, `active`, `adminEdits`
- **Сервис:** `estimateEditorService` — создание/обновление админ-корректировок, пересчёт параметров
- **API:** `POST/PUT /api/admin/orders/[id]/admin-estimate`
- **UI:** `EstimateEditor` — модалка с параметрами, таблицей номенклатур, добавлением/удалением
- **Админка:** `OrderDetailPage` — отображение сметы с вкладками (клиентская/админская), сравнение, экспорт Word

### Текущее состояние ворот/калиток:

- **Модель БД:** `GateEstimate` — без полей админ-редактирования
- **Сервис:** `gateEstimateService` — только расчёт и сохранение
- **API:** `POST /api/calculator/gates/estimate` — создание
- **Админка:** `getOrderFull` НЕ загружает `GateEstimate` по `gateEstimateId`
- **UI:** Для `serviceType: 'gates'` показывается только `parameters` JSON

## 3. Критерии приёмки

### 3.1. Отображение сметы ворот/калиток в карточке заявки
- [ ] В админке, на странице заявки с `serviceType: 'gates'`, отображается полная смета с номенклатурами (ворота, калитки, автоматика, работы)
- [ ] Смета показывает категории: материалы и работы, с итогами по каждой категории и общим итогом
- [ ] Отображаются закупочные цены и маржинальность (для роли ADMIN)

### 3.2. Редактирование сметы
- [ ] Кнопка редактирования (карандаш) открывает редактор сметы
- [ ] Можно изменять количество каждой номенклатуры
- [ ] Можно удалять номенклатуры из сметы
- [ ] Можно добавлять новые номенклатуры через пикер
- [ ] Итоги пересчитываются автоматически
- [ ] Можно оставить комментарий к корректировке
- [ ] Сохранение создаёт админ-корректировку (по аналогии с заборами)

### 3.3. Параметры ворот/калиток в редакторе
- [ ] В редакторе отображаются параметры: высота, нужен монтаж
- [ ] НЕ нужны параметры забора (длина, лаги, покрытие) — только относящиеся к воротам/калиткам

### 3.4. Сравнение и история
- [ ] Вкладки: исходная смета / с изменениями
- [ ] Сравнение исходной и откорректированной сметы
- [ ] История редактирования

### 3.5. Экспорт в Word
- [ ] Экспорт сметы ворот/калиток в Word (.docx)

## 4. Техническое решение

### 4.1. БД — расширить модель `GateEstimate`

Добавить поля (по аналогии с `FenceEstimate`):

```prisma
model GateEstimate {
  // ... существующие поля ...

  // Админ-редактирование
  isEditedByAdmin        Boolean  @default(false)
  editedByAdminId        String?
  editedAt               DateTime?
  editComment            String?
  manualQuantityOverrides Json?
  sourceEstimateId       String?       // ссылка на исходную смету
  active                 Boolean  @default(true)

  // Связи
  editedByAdmin          User?    @relation(fields: [editedByAdminId], references: [id])
  sourceEstimate         GateEstimate?  @relation("GateAdminEstimateEdit", fields: [sourceEstimateId], references: [id])
  adminEdits             GateEstimate[] @relation("GateAdminEstimateEdit")
  adminOrder             Order?
}
```

### 4.2. Обновить `getOrderFull` в `ordersService`

- Если `order.gateEstimateId` заполнен — загрузить `GateEstimate` с items
- Форматировать items аналогично FenceEstimate (категории, цены, маржинальность)
- Вернуть в том же формате: `{ estimate: { items, materialsTotal, ... }, adminEstimate: null }`

### 4.3. Создать `gateEstimateEditorService`

По аналогии с `estimateEditorService`, но для `GateEstimate`:
- `createAdminEstimate` — создать корректировку
- `updateAdminEstimate` — обновить корректировку
- `getAdminEstimateForOrder` — получить корректировку по orderId
- `getAdminCorrectionForEstimate` — найти корректировку по sourceEstimateId

Отличие от заборов: **нет пересчёта по параметрам** (параметры ворот/калиток простые — только высота и монтаж). Редактор работает только с items (добавление/удаление/изменение кол-ва).

### 4.4. API Routes

Обновить существующий `POST/PUT /api/admin/orders/[id]/admin-estimate`:
- Определять тип заявки по `serviceType`
- Для `gates` — использовать `gateEstimateEditorService`
- Для `fence` — использовать текущий `estimateEditorService`

### 4.5. UI — обновить `OrderDetailPage`

- Определить `isGateOrder = order.serviceType === 'gates'`
- Для gate-заявок: показать смету с items из `gateEstimate`
- Подключить `EstimateEditor` с gate-специфичными параметрами (высота, монтаж)
- Убрать параметры забора (длина, лаги, покрытие) для gate-заявок

### 4.6. UI — обновить `EstimateEditor`

- Добавить режим `estimateType: 'gate' | 'fence'`
- Для gate: показать параметры ворот (высота, монтаж), скрыть параметры забора
- Для gate: отключить пересчёт по параметрам (только редактирование items)

## 7. Ограничения и риски

- **Миграция БД:** Новые nullable-поля, данные не теряются
- **Обратная совместимость:** Существующие gate-заявки продолжат работать (estimate = null для старых)
- **Производительность:** Дополнительный запрос GateEstimate в getOrderFull — минимальное влияние
