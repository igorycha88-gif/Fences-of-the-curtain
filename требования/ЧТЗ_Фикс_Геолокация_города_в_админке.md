# ЧТЗ (упрощённое): Фикс геолокации — город посетителя в админке

**Дата:** 21.09.2026
**Маршрут:** 3 (инфраструктурная задача) → исполнитель: DevOps
**Серьёзность:** High — бизнес-данные (город лида) не собираются ~2 месяца

---

## 1. Проблема

В админке (`/admin/estimates`, `/admin/orders`) перестал отображаться город посетителя, выполнявшего расчёт в калькуляторе. Поле «Город» показывает «-».

**Период поломки:** с ~27.07.2026 по н.в. (0 записей с городом из 110+ расчётов).

## 2. Первопричина (диагностика выполнена)

1. Хост VPS использует `systemd-resolved` (`/etc/resolv.conf` → `127.0.0.53`)
2. Docker подставил контейнеру fallback DNS `8.8.8.8`/`8.8.4.4` (loopback использовать нельзя)
3. Google DNS заблокирован с VPS 37.143.13.196 → DNS-резолв внутри контейнера = 10+ сек
4. `ipLookupService.ts` (fetch таймаут 3с) → всегда `TimeoutError` → `city = NULL`

Проверено: с DNS провайдера (`46.254.23.138`, `46.254.22.138`) fetch из host-mode контейнера отрабатывает за 214мс.

## 3. Что нужно сделать (TASK-INF)

### TASK-INF-1: Явный DNS для app-контейнера на проде
- В `docker-compose.yml` (прод, сервис `app`) добавить:
  ```yaml
  dns:
    - 46.254.23.138
    - 46.254.22.138
  ```
  (работает даже с `network_mode: host` — проверено тестом на VPS)

### TASK-INF-2: Применить на VPS
- Пересоздать app-контейнер (`docker compose up -d app` → force-recreate)
- NB: без полной пересборки образа (infra-изменение compose-файла), мониторинг-стек не трогаем

### TASK-INF-3: Верификация
- `docker exec fences-app node -e "fetch(...ip-api.com...)"` → ответ < 1с
- Совершить тестовый расчёт → в БД `city` заполнен в течение ~минуты
- `docker logs fences-app` — нет `[ipLookup] Error`

### TASK-INF-4 (опционально, по согласованию): Бэкфилл
- Заполнить `city` ретроспективно для расчётов с ~27.07.2026 (есть `ipAddress`, `city IS NULL`, ~110 записей) через повторный lookup по сохранённому IP

## 4. Критерии приёмки

- ✅ Новые расчёты в калькуляторе получают город (в БД `city IS NOT NULL`)
- ✅ В админке `/admin/estimates` колонка «Город» заполнена
- ✅ DNS-резолв в контейнере < 1с
- ✅ Нет ошибок `[ipLookup]` в логах

## 5. Риски

- Пересоздание app-контейнера = короткий даунтайм прода (~30-60 сек)
- DNS провайдера — единственная зависимость; fallback можно добавить позже
