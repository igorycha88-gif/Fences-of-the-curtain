## 2. Цели и задачи

### 2.1 Бизнес-цель
Упростить классификацию профнастила по типу покрытия, выделив три основных вида: полимерное одностороннее, полимерное двустороннее и оцинковка. Это позволит упростить выбор материала для клиентов и улучшить фильтрацию в каталоге.

### 2.2 Пользовательская ценность
- Простая и понятная классификация покрытий
- Быстрый поиск по типу покрытия
- Автоматическое заполнение существующих записей на основе их названий

### 2.3 Ключевые метрики успеха
- 100% существующих записей корректно классифицированы
- Все новые записи создаются с заполненным полем "Покрытие"
- Фильтрация по покрытию работает корректно

---

## 3. Требования к продукту

### 3.1 Функциональные требования

#### 3.1.1 Изменение поля "Покрытие" (coating)

**User Story 1: Выбор типа покрытия при создании/редактировании**
*Как администратор, я хочу выбрать тип покрытия из списка при создании или редактировании номенклатуры профнастила.*

**Новые значения поля coating:**
| Значение | Описание |
|----------|----------|
| Полимерное (одностороннее) | Полимерное покрытие с одной стороны листа |
| Полимерное (двустороннее) | Полимерное покрытие с обеих сторон листа |
| Оцинковка | Оцинкованное покрытие без полимера |

**Acceptance Criteria:**
- Поле "Покрытие" является обязательным при создании
- Выпадающий список содержит 3 значения
- Значение по умолчанию: **нет** (обязательный выбор пользователем)
- При редактировании текущее значение предзаполнено
- Кнопка "Создать" неактивна, пока не выбрано покрытие

---

#### 3.1.2 Автоматическая миграция данных

**User Story 2: Автоматическое заполнение поля для существующих записей**
*Как система, я хочу автоматически заполнить поле "Покрытие" для существующих записей на основе ключевых слов в названии.*

**Правила заполнения:**
| Условие | Значение покрытия |
|---------|-------------------|
| Название содержит "двустороннее" (case-insensitive) | Полимерное (двустороннее) |
| Название содержит "одностороннее" (case-insensitive) | Полимерное (одностороннее) |
| Все остальные записи | Оцинковка |

**Примеры:**
- "Профнастил С8 0.5мм двустороннее RAL 8017" → Полимерное (двустороннее)
- "Профнастил С20 0.7мм одностороннее RAL 6005" → Полимерное (одностороннее)
- "Профнастил НС35 0.8мм оцинкованный" → Оцинковка
- "Профнастил С8 0.5мм" → Оцинковка (по умолчанию)

**Acceptance Criteria:**
- Миграция выполняется один раз при деплое
- Поиск ключевых слов нечувствителен к регистру
- Если оба ключевых слова найдены, приоритет у "двустороннее"
- Лог миграции записывается в консоль
- Rollback скрипт возвращает старые значения

---

#### 3.1.3 Отображение в таблице и формах

**User Story 3: Отображение покрытия в интерфейсе**
*Как администратор, я хочу видеть тип покрытия в таблице справочника и использовать его для фильтрации.*

**Acceptance Criteria:**

- Форма создания/редактирования использует выпадающий список
- Значения отображаются полностью (без сокращений)

## 4. Техническая архитектура

### 4.1 Изменения в Prisma схеме

**До:**
```prisma
model ProfnastilType {
  // ...
  coating  String  // Покрытие (Цинк, Полиэстер, Пурал, Пластизол)
  // ...
}
```

**После:**
```prisma
model ProfnastilType {
  // ...
  coating  String  // Покрытие (Полимерное (одностороннее), Полимерное (двустороннее), Оцинковка)
  // ...
}
```

**Примечание:** Тип поля не меняется (String), меняется только набор допустимых значений. Поле остается обязательным (не nullable).

### 4.2 Миграция базы данных

**Migration Script:**
```sql
-- Migration: update_profnastil_coating_values
-- Date: 2026-03-10

BEGIN;

-- Шаг 1: Обновить записи с "двустороннее" в названии
UPDATE "ProfnastilType"
SET "coating" = 'Полимерное (двустороннее)',
    "updatedAt" = CURRENT_TIMESTAMP
WHERE LOWER("name") LIKE '%двустороннее%';

-- Шаг 2: Обновить записи с "одностороннее" в названии
UPDATE "ProfnastilType"
SET "coating" = 'Полимерное (одностороннее)',
    "updatedAt" = CURRENT_TIMESTAMP
WHERE LOWER("name") LIKE '%одностороннее%'
  AND "coating" != 'Полимерное (двустороннее)';  -- не перезаписывать двустороннее

-- Шаг 3: Остальные записи - Оцинковка
UPDATE "ProfnastilType"
SET "coating" = 'Оцинковка',
    "updatedAt" = CURRENT_TIMESTAMP
WHERE "coating" NOT IN ('Полимерное (одностороннее)', 'Полимерное (двустороннее)');

-- Логирование
DO $$
DECLARE
    cnt_bilateral INTEGER;
    cnt_unilateral INTEGER;
    cnt_galvanized INTEGER;
BEGIN
    SELECT COUNT(*) INTO cnt_bilateral FROM "ProfnastilType" WHERE "coating" = 'Полимерное (двустороннее)';
    SELECT COUNT(*) INTO cnt_unilateral FROM "ProfnastilType" WHERE "coating" = 'Полимерное (одностороннее)';
    SELECT COUNT(*) INTO cnt_galvanized FROM "ProfnastilType" WHERE "coating" = 'Оцинковка';
    
    RAISE NOTICE 'Migration complete: % bilateral, % unilateral, % galvanized', 
                 cnt_bilateral, cnt_unilateral, cnt_galvanized;
END $$;

COMMIT;
```

**Rollback Script:**
```sql
-- Rollback: update_profnastil_coating_values
-- Date: 2026-03-10

BEGIN;

-- Восстановить старые значения на основе предположений
-- Примечание: точное восстановление невозможно без бэкапа

-- Для двустороннего полимера
UPDATE "ProfnastilType"
SET "coating" = 'Полиэстер',
    "updatedAt" = CURRENT_TIMESTAMP
WHERE "coating" = 'Полимерное (двустороннее)';

-- Для одностороннего полимера
UPDATE "ProfnastilType"
SET "coating" = 'Полиэстер',
    "updatedAt" = CURRENT_TIMESTAMP
WHERE "coating" = 'Полимерное (одностороннее)';

-- Для оцинковки
UPDATE "ProfnastilType"
SET "coating" = 'Цинк',
    "updatedAt" = CURRENT_TIMESTAMP
WHERE "coating" = 'Оцинковка';

COMMIT;
```

## 10. Риски и зависимости

### 10.1 Технические риски

**Risk 1: Некорректная классификация существующих записей**

**Category:** Technical  
**Probability:** Medium  
**Impact:** Medium

**Description:**
Записи без ключевых слов "двустороннее"/"одностороннее" в названии будут классифицированы как "Оцинковка", что может быть некорректно.

**Mitigation Strategies:**
1. **Prevent:** Предоставить администратору список записей для проверки после миграции
2. **Mitigate:** Возможность быстрой корректировки через интерфейс редактирования
3. **Accept:** Риск принят, т.к. классификация может быть исправлена вручную

## 11. Определения и сокращения

- **Полимерное (одностороннее)** - покрытие с полимером на одной стороне листа
- **Полимерное (двустороннее)** - покрытие с полимером на обеих сторонах листа
- **Оцинковка** - оцинкованное покрытие без полимерного слоя

## 12. Решённые вопросы

### Вопрос 1: Новые значения покрытия ✅ РЕШЕНО
**Решение:** Полимерное (одностороннее), Полимерное (двустороннее), Оцинковка

**Обоснование:** Упрощенная классификация для удобства клиентов и быстрого поиска.

---

### Вопрос 2: Логика автоматического заполнения ✅ РЕШЕНО
**Решение:** По ключевым словам в названии (case-insensitive)

**Обоснование:** Позволяет автоматически классифицировать существующие записи без ручного ввода.

---

### Вопрос 3: Значение по умолчанию ✅ РЕШЕНО
**Решение:** Нет значения по умолчанию, обязательный выбор пользователем

**Обоснование:** Исключает ошибки при создании, заставляет пользователя осознанно выбрать тип покрытия.

---

### Вопрос 4: Уведомление пользователей ✅ РЕШЕНО
**Решение:** Не уведомлять

**Обоснование:** Изменения прозрачны для пользователей и не требуют действий с их стороны.

---

### Вопрос 5: Сохранение старых данных ✅ РЕШЕНО
**Решение:** Не требуется

**Обоснование:** Старые значения (Цинк, Полиэстер, Пурал, Пластизол) больше не используются и не несут ценности.

---
