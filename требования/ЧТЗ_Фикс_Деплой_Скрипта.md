# ЧТЗ (упрощённое): Фикс багов деплой-скрипта (успешный CI-деплой)

**Дата:** 2026-11-02
**Маршрут:** Аналитик → Разработчик → Тестировщик → DevOps (прод)
**Тип:** Баг-фикс инфраструктуры (малая задача: 2 файла)

## Проблема

CI-деплой v1.23.1 упал на шаге «Deploy to VPS (Blue-Green)» (прод спасён только ручным деплоем):

1. **BUG-D1: `docker pull` из GHCR без ретраев.** Сеть хостера пакетлосит волнами → `connection reset by peer` при скачивании слоёв → деплой сразу падал в фолбэк.
2. **BUG-D2: локальный build-фолбэк падает с `invalid tag ... must be lowercase`.** Workflow экспортирует `GITHUB_REPOSITORY=igorycha88-gif/Fences-of-the-curtain` (uppercase F). Скрипт для pull lowercas'ит (`${GHCR_REPO,,}`), но `docker compose build` в фолбэке наследует переменную как есть → compose пытается тегировать `ghcr.io/igorycha88-gif/Fences-of-the-curtain/app:latest` → invalid tag. Плюс после сборки скрипт подменял `GHCR_IMAGE="fences-of-the-curtain-app:latest"` — имя, которое compose вообще не собирает → даже успешная сборка запустила бы несуществующий образ.
3. **BUG-D3: `DNS_ARGS`/`dns:` принудительно ставят деградировавшие DNS хостера (46.254.23.138/46.254.22.138) во все docker run/compose.** Эти резолверы — первопричина инцидента с геолокацией (23.10–02.11). Следующий CI-деплой откатил бы DNS-фикс. Контейнеры должны наследовать хостовый resolv.conf (127.0.0.53 → systemd-resolved → публичные 1.1.1.1/8.8.8.8/77.88.8.8) — проверено живьём на проде (текущий контейнер без --dns, гео работает).

## Решение

### TASK-INF-1: `scripts/deploy-vps.sh`
- Удалить `DNS_ARGS` и все его вставки в `docker run` (4 места), обновить комментарий.
- Pull: ретрай-цикл 3 попытки с паузой 5с.
- Фолбэк-сборка: `GITHUB_REPOSITORY="${GHCR_REPO}" IMAGE_TAG="${IMAGE_TAG}" docker compose build` (явный lowercase + нужный тег), удалить подмену `GHCR_IMAGE=...` после сборки.

### TASK-INF-2: `docker-compose.yml` (prod)
- Удалить секцию `dns:` (наследует хостовый resolv.conf, network_mode: host).

## Критерии приёмки

1. `bash -n` и `shellcheck` (если доступен) без ошибок.
2. В скрипте/композе не осталось ссылок на 46.254.x.
3. Полный CI-деплой v1.23.2 проходит успешно end-to-end (pull-ретраи либо фолбэк не срабатывает вовсе).
4. После деплоя: контейнер fences-app БЕЗ --dns, health ok, гео-резолв работает.

## Out of scope

- Тикет хостеру по пакетлоссу (наблюдение)
- Переход на публичный реестр/зеркало образов
