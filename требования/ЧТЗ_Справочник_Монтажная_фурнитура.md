## 2. Цели и задачи

### 2.1 Бизнес-цель
Создать централизованный справочник монтажной фурнитуры (саморезы, болты, гайки, кронштейны и т.д.) с возможностью привязки к существующим позициям справочников. Обеспечить учёт цен закупки и розничных цен с автоматическим расчётом маржи.

### 2.2 Пользовательская ценность
- Централизованное управление всей монтажной фурнитурой
- Привязка фурнитуры к конкретным позициям других справочников (лаги, столбы и т.д.)
- Автоматический расчёт маржи по аналогии со справочником Лаги
- Контроль сроков действия цен с автоматической деактивацией

### 2.3 Ключевые метрики успеха
- Справочник создан и доступен в админ-панели
- CRUD операции работают корректно
- Множественные связи с другими справочниками реализованы
- Автоматическая деактивация по сроку действия работает

## 3. Требования к продукту

### 3.1 Функциональные требования

#### 3.1.1 Структура справочника (таблица)

**User Story 1: Просмотр каталога монтажной фурнитуры**

*Как администратор, я хочу видеть таблицу всех позиций монтажной фурнитуры с ключевыми полями.*

**Acceptance Criteria:**
- Таблица отображает столбцы:
  - **Название** - наименование фурнитуры
  - **Принадлежность** - связанные справочники/позиции (через запятую если несколько)
  - **Срок действия** - дата до которой активна запись
  - **Цена закупки за ед. (₽)** - закупочная цена
  - **Розничная стоимость (₽)** - цена для клиента
  - **Активен** - статус (да/нет)
  - **Действия** - кнопки редактирования/удаления
- Сортировка по всем столбцам
- Фильтрация по статусу активности
- Поиск по названию

---

#### 3.1.2 Карточка номенклатуры

**User Story 2: Создание позиции монтажной фурнитуры**

*Как администратор, я хочу создать новую позицию фурнитуры с указанием всех необходимых параметров.*

**Acceptance Criteria:**
- Форма создания содержит поля:
  - **Название** (обязательное) - текст, 2-200 символов
  - **Описание** (опциональное) - многострочный текст
  - **Принадлежность** (обязательное) - множественный выбор:
    - Шаг 1: Выбор типа справочника из списка:
      - Лаги
      - Столбы
      - Профнастил
      - Евроштакетник
      - Ворота
      - Калитки
    - Шаг 2: Выбор конкретной позиции из выбранного справочника
    - Возможность добавить несколько связей
  - **Срок действия** (опциональное) - дата
    - После наступления даты запись автоматически деактивируется
  - **Цена закупки за ед. (₽)** (обязательное) - число ≥ 0
  - **Розничная стоимость (₽)** (обязательное) - число ≥ 0
  - **Активен** - чекбокс, по умолчанию true
  - **Расчёт маржи** - автоматический расчёт:
    - Формула: `(розничная - закупка) / закупка * 100`
    - Цветовая индикация: 🟢 ≥30% | 🟡 10-30% | 🔴 <10%
    - Отображение абсолютной маржи в рублях

---

**User Story 3: Редактирование позиции монтажной фурнитуры**

*Как администратор, я хочу редактировать существующую позицию фурнитуры.*

**Acceptance Criteria:**
- Форма редактирования предзаполнена текущими значениями
- Все поля доступны для редактирования
- При изменении цен маржа пересчитывается автоматически
- Возможность добавить/удалить связи с другими справочниками

---

**User Story 4: Удаление позиции монтажной фурнитуры**

*Как администратор, я хочу удалить позицию фурнитуры.*

**Acceptance Criteria:**
- Подтверждение удаления перед выполнением
- Мягкое удаление (soft delete) или полное удаление
- Если позиция связана с другими сущностями - предупреждение

---

**User Story 5: Автоматическая деактивация по сроку**

*Как система, я хочу автоматически деактивировать записи с истёкшим сроком действия.*

**Acceptance Criteria:**
- Ежедневная проверка сроков действия (cron job или при обращении)
- Если `validUntil < currentDate` → `active = false`
- Логирование автоматических деактиваций
- Возможность ручного продления срока

---

**User Story 5.1: Обработка удаления связанной номенклатуры**

*Как система, я хочу автоматически удалять связи при удалении связанной номенклатуры из других справочников.*

**Acceptance Criteria:**
- При удалении позиции из справочника (Лаги, Столбы и т.д.) проверяются связи в MountingHardwareRelation
- Все записи в MountingHardwareRelation с `referenceId = deletedId` удаляются
- Сама позиция монтажной фурнитуры остаётся (удаляется только связь)
- Если у позиции фурнитуры не остаётся ни одной связи — предупреждение администратору

---

#### 3.1.3 Контроль доступа

**User Story 6: Ограничение доступа к ценам закупки**

*Как система, я хочу скрыть цены закупки от пользователей с ролью MANAGER и CONTENT_MANAGER.*

**Acceptance Criteria:**
- **Роль ADMIN:**
  - Видит колонку "Цена закупки за ед." в таблице
  - Может редактировать цену закупки в форме
  - Видит расчёт маржи
- **Роль MANAGER / CONTENT_MANAGER:**
  - Не видит колонку "Цена закупки за ед." в таблице
  - Не видит поле ввода цены закупки в форме
  - Видит только розничную стоимость

### 4.2 Схема данных

#### 4.2.1 Новая модель MountingHardware

```prisma
model MountingHardware {
  id                String   @id @default(cuid())
  name              String
  description       String?
  purchasePrice     Float
  retailPrice       Float
  validUntil        DateTime?
  active            Boolean  @default(true)
  sortOrder         Int      @default(0)
  createdAt         DateTime @default(now())
  updatedAt         DateTime @updatedAt

  // Связи с другими справочниками
  relations         MountingHardwareRelation[]

  @@index([active])
  @@index([validUntil])
  @@index([sortOrder])
}

// Промежуточная таблица для множественных связей
model MountingHardwareRelation {
  id                    String   @id @default(cuid())
  mountingHardwareId    String
  referenceType         String   // 'LAG', 'POST', 'PROFNASTIL', 'PICKET', 'GATE', 'WICKET'
  referenceId           String   // ID из соответствующего справочника
  createdAt             DateTime @default(now())

  mountingHardware      MountingHardware @relation(fields: [mountingHardwareId], references: [id], onDelete: Cascade)

  @@unique([mountingHardwareId, referenceType, referenceId])
  @@index([referenceType])
  @@index([referenceId])
}
```

### 5.2 POST /api/admin/mounting-hardware

**Описание:** Создать новую позицию монтажной фурнитуры

**Request (ADMIN only):**
```json
{
  "name": "Саморез 4.2x19 мм",
  "description": "Саморез кровельный с EPDM шайбой",
  "purchasePrice": 2.50,
  "retailPrice": 5.00,
  "validUntil": "2026-12-31T00:00:00.000Z",
  "active": true,
  "relations": [
    { "referenceType": "PROFNASTIL", "referenceId": "prof-1" },
    { "referenceType": "PICKET", "referenceId": "picket-1" }
  ]
}
```

**Validation:**
```typescript
const mountingHardwareSchema = z.object({
  name: z.string().min(2).max(200),
  description: z.string().max(1000).optional(),
  purchasePrice: z.number().min(0),
  retailPrice: z.number().min(0),
  validUntil: z.string().datetime().optional().nullable(),
  active: z.boolean().default(true),
  sortOrder: z.number().default(0),
  relations: z.array(z.object({
    referenceType: z.enum(['LAG', 'POST', 'PROFNASTIL', 'PICKET', 'GATE', 'WICKET']),
    referenceId: z.string()
  })).min(1, "Необходимо указать хотя бы одну связь")
});
```

## 9. Риски и зависимости

### Риск 1: Сложность множественных связей
**Category:** Technical  
**Probability:** Medium  
**Impact:** Medium

**Mitigation:**
- Использовать промежуточную таблицу MountingHardwareRelation
- Каскадное удаление связей при удалении фурнитуры

### Риск 2: Производительность при большом количестве связей
**Category:** Technical  
**Probability:** Low  
**Impact:** Medium

**Mitigation:**
- Индексы на referenceType и referenceId
- Пагинация для больших списков

### Риск 3: Потеря связей при удалении справочников
**Category:** Technical  
**Probability:** Medium  
**Impact:** Medium

**Description:** При удалении позиций из связанных справочников могут остаться "висячие" связи.

**Mitigation:**
- Реализовать очистку связей в сервисах удаления каждого справочника
- Добавить индикатор "нет связей" в UI для администратора
