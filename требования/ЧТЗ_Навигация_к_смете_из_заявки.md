## 1. Цели и задачи

### 1.1 Бизнес-цель
Обеспечить удобную навигацию менеджера из заявки клиента к связанной смете расчета. Менеджер должен попадать в контекст вкладки "Расчеты" для работы со сметой.

### 1.2 Пользовательская ценность
Менеджер кликает "Смета" в списке заявок → система переводит его на вкладку "Расчеты" и автоматически открывает нужную смету в модальном окне. Это сохраняет контекст работы с расчетами и позволяет легко вернуться к списку.

### 1.3 Ключевые метрики успеха
- Время перехода от заявки к смете: < 1 сек
- Корректность открытия нужной сметы: 100%

---

## 2. Функциональные требования

### 2.1 User Story

#### US-1: Переход к смете из списка заявок
**Как** менеджер,  
**Я хочу** кликнуть "Смета" в таблице заявок и попасть во вкладку "Расчеты" с открытой нужной сметой,  
**Чтобы** быстро просмотреть детали расчета клиента.

**Acceptance Criteria**:
```
Given я нахожусь на странице /admin/orders
And у заявки есть связанный расчет (estimateId)
When кликаю на кнопку "Смета"
Then происходит переход на вкладку "Расчеты" (/admin/estimates?open={estimateId})
And в боковом меню подсвечивается пункт "Расчеты"
And автоматически открывается модальное окно с деталями нужной сметы
And если estimateId не найден в БД — показывается сообщение "Смета не найдена"
```

#### US-2: Обработка отсутствующей сметы
**Как** менеджер,  
**Я хочу** видеть понятное сообщение, если смета не найдена,  
**Чтобы** понимать, что с заявкой что-то не так.

**Acceptance Criteria**:
```
Given я кликаю "Смета" у заявки
And связанный расчет не существует (удален)
Then открывается страница "Расчеты"
And показывается уведомление "Смета не найдена"
And модальное окно не открывается
```

## 3. Техническая архитектура

### 3.1 Текущее состояние

**Сейчас**:
- Ссылка в таблице заявок: `/admin/estimates/${estimateId}` (отдельная страница деталей)
- Страница `/admin/estimates/[id]/page.tsx` — отдельная страница с деталями расчета

**Проблема**:
- Пользователь попадает на отдельную страницу, а не во вкладку "Расчеты"
- Нет ощущения работы в контексте вкладки "Расчеты"

### 3.2 Решение

**Изменения**:

1. **Изменить ссылку в таблице заявок**:
   ```tsx
   // Было:
   href={`/admin/estimates/${order.estimateId}`}
   
   // Станет:
   href={`/admin/estimates?open=${order.estimateId}`}
   ```

2. **Добавить обработку query-параметра `open` на странице Расчеты**:
   ```tsx
   // src/app/(admin)/admin/estimates/page.tsx
   
   const searchParams = useSearchParams();
   const openEstimateId = searchParams.get('open');
   
   useEffect(() => {
     if (openEstimateId) {
       fetchEstimateDetail(openEstimateId);
     }
   }, [openEstimateId]);
   ```

3. **Обработка ошибки "Смета не найдена"**:
   - Если API возвращает 404 — показать toast-уведомление

### 3.3 Структура файлов

```
src/app/(admin)/admin/
├── orders/
│   └── page.tsx              # ИЗМЕНИТЬ: ссылка на ?open=
└── estimates/
    └── page.tsx              # ИЗМЕНИТЬ: обработка ?open=
```

### 3.4 API спецификация

Используется существующий endpoint:
- `GET /api/admin/estimates/{id}` — получение деталей расчета

## 6. Тестирование

### 6.1 Ручное тестирование
1. Открыть /admin/orders
2. Кликнуть "Смета" у заявки с estimateId
3. Проверить: переход на /admin/estimates?open=XXX
4. Проверить: модальное окно открыто с нужной сметой
