# ЧТЗ: Фикс 500 ошибок на проде — рассинхронизация схемы БД + контактная информация

**Дата:** 2026-04-15
**Приоритет:** CRITICAL
**Маршрут:** Стандартный (Аналитик → Разработчик → Тестировщик → DevOps)

---

## 1. Описание проблемы

На проде (zabor-i-naves.ru) множественные 500 ошибки во всех API `/api/admin/*`.

## 2. Корневая причина

**Единая причина:** Продакшн БД не синхронизирована с `prisma/schema.prisma`. Entrypoint использует `prisma migrate deploy`, но миграций для новых моделей/полей не существует.

**Отсутствующие таблицы:**
- `TrussProfileType`
- `TrussRoofCovering`
- `TrussCalculation`
- `MeshType`

**Отсутствующие поля:**
- `PostType.forMesh`
- `FenceEstimate.active`, `meshId`, `meshInstallationTotal`, `meshNomenclatureName`, `meshTotal`, `multiEstimateId`, `sourceEstimateId`, `isEditedByAdmin`, `editedAt`, `editedByAdminId`, `editComment`, `manualQuantityOverrides`
- `Order.active`, `Order.adminEstimateId`

**Контактная информация:** Admin PUT `/api/admin/contact-info` не инвалидирует Redis-кеш (ключ `contact_info`).

## 3. Задачи

### TASK-001-INF: Исправить entrypoint.sh
- Изменить `prisma migrate deploy` → `prisma db push` (с флагом `--accept-data-loss` только как fallback)
- Это автоматически синхронизирует схему БД с Prisma схемой

### TASK-002-BCK: Инвалидация Redis-кеша при обновлении контактной информации
- В `/api/admin/contact-info/route.ts` PUT handler: добавить `redis?.del('contact_info')` после успешного обновления

## 4. Критерии приёмки

1. Все `/api/admin/*` эндпоинты возвращают 200 на проде
2. Контактная информация отображается на публичном сайте после обновления в админке
3. `npm test && npm run lint && npx tsc --noEmit` проходят

## 5. Файлы для изменения

1. `docker/entrypoint.sh` — заменить migrate deploy на db push
2. `src/app/api/admin/contact-info/route.ts` — добавить инвалидацию кеша

## 6. Риски

- `prisma db push` может потребовать `--accept-data-loss` если есть конфликтующие изменения. Необходимо проверить.
- При первом запуске `prisma db push` на проде создадутся отсутствующие таблицы — это безопасно.
