# ЧТЗ: Калькулятор в админ-панели

## Версия: 1.0
## Дата: 2026-04-21
## Приоритет: High
## Статус: Draft

---

## 1. Цели и задачи

### 1.1 Бизнес-цель
Дать администратору возможность рассчитать стоимость любого забора прямо из админ-панели, скорректировать состав материалов и оформить заявку — без необходимости использовать клиентский калькулятор.

### 1.2 Пользовательская ценность
Админ получает полноценный инструмент для расчёта стоимости забора «с нуля», с доступом к закупочным ценам, марже и возможностью гибко корректировать номенклатуру. Созданные расчёты и заявки проходят стандартный конвейер (статусы, уведомления, экспорт).

### 1.3 Метрики успеха
- Время от открытия калькулятора до создания заявки < 3 минут
- Все созданные расчёты видны во вкладке «Расчеты» с пометкой «Создан администратором»
- Все созданные заявки видны во вкладке «Заявки» с заполненными данными клиента

## 2. Функциональные требования

### 2.1 User Stories

#### US-1: Расчёт забора
**Как** администратор  
**Я хочу** ввести параметры забора (тип, длина, высота, покрытие, ворота, калитка)  
**Чтобы** получить полный расчёт стоимости материалов и работ

**Acceptance Criteria:**
- Given: Админ открыл вкладку «Калькулятор»
- When: Ввёл параметры и нажал «Рассчитать»
- Then: Получает таблицу материалов с розничной ценой, закупочной ценой, маржой, количеством и суммой
- And: Видит итоговую стоимость материалов, стоимость работ и общую стоимость

#### US-2: Корректировка номенклатуры
**Как** администратор  
**Я хочу** удалить предложенные позиции из расчёта и добавить любые другие из справочника  
**Чтобы** состав расчёта соответствовал реальным потребностям

**Acceptance Criteria:**
- Given: Расчёт выполнен, таблица материалов отображается
- When: Админ нажимает «Удалить» на позиции
- Then: Позиция удаляется из расчёта, итоги пересчитываются
- When: Админ нажимает «Добавить номенклатуру»
- Then: Открывается модальное окно выбора из справочника (все категории: столбы, лаги, профнастил, 3D-панели, евроштакетник, сетка, ворота, калитки, монтажная фурнитура, работы)
- When: Админ выбирает позицию
- Then: Система предлагает расчётное количество (если возможно определить), но админ может его скорректировать
- And: Итоги пересчитываются при каждом изменении

#### US-3: Корректировка количества
**Как** администратор  
**Я хочу** изменить количество любой позиции в расчёте  
**Чтобы** уточнить состав материалов

**Acceptance Criteria:**
- Given: В таблице расчёта есть позиция с автоподсчитанным количеством
- When: Админ меняет количество
- Then: Сумма по позиции и итоги пересчитываются
- And: Скорректированное количество подсвечивается (визуальный индикатор)

#### US-4: Создание заявки из расчёта
**Как** администратор  
**Я хочу** заполнить данные клиента и создать заявку из расчёта  
**Чтобы** заявка попала в стандартный конвейер обработки

**Acceptance Criteria:**
- Given: Расчёт выполнен (и при необходимости скорректирован)
- When: Админ нажимает «Оформить заявку»
- Then: Открывается форма с полями: ФИО клиента (обязательное), телефон (обязательное), email (опциональное), комментарий (опциональное)
- When: Админ заполняет форму и подтверждает
- Then: Создаётся Order со статусом NEW
- And: Создаётся FenceEstimate с пометкой `isEditedByAdmin: true`, `editedByAdminId` = ID текущего админа
- And: Order связывается с FenceEstimate через `adminEstimateId`
- And: Расчёт появляется во вкладке «Расчеты» с бейджем «Создан администратором»
- And: Заявка появляется во вкладке «Заявки» с заполненными данными клиента
- And: Статус заявки можно менять по стандартному workflow

#### US-5: Сохранение расчёта без заявки
**Как** администратор  
**Я хочу** сохранить расчёт без создания заявки  
**Чтобы** вернуться к нему позже

**Acceptance Criteria:**
- Given: Расчёт выполнен
- When: Админ нажимает «Сохранить расчёт»
- Then: Создаётся FenceEstimate с пометкой `isEditedByAdmin: true`
- And: Расчёт виден во вкладке «Расчеты»
- And: Позже из вкладки «Расчеты» можно создать заявку на основе этого расчёта

#### US-6: Мульти-забор (несколько типов заборов)
**Как** администратор  
**Я хочу** добавить несколько типов заборов в один расчёт  
**Чтобы** рассчитать комплексный объект с разными участками

**Acceptance Criteria:**
- Given: Админ на странице калькулятора
- When: Нажимает «Добавить ещё забор»
- Then: Появляется дополнительная форма параметров
- When: Нажимает «Рассчитать всё»
- Then: Получает общий итог по всем расчётам
- And: Может создать единую заявку на все расчёты

## 3. Нефункциональные требования

### 3.1 Производительность
- Расчёт < 2 секунд
- Пересчёт при корректировке кол-ва — мгновенный (на клиенте)

### 3.2 Безопасность
- Доступ только для авторизованных пользователей (ADMIN, MANAGER)
- Закупочные цены и маржа видны только ролям ADMIN, MANAGER

### 3.3 Масштабируемость
- Без изменений БД — используются существующие модели FenceEstimate, MultiFenceEstimate, Order

## 4. Техническая архитектура

### 4.1 Изменения в БД
**НЕ ТРЕБУЮТСЯ.** Существующая схема полностью покрывает потребности:

- `FenceEstimate.isEditedByAdmin = true` — пометка «Создан администратором»
- `FenceEstimate.editedByAdminId` — ID админа
- `FenceEstimate.sourceEstimateId = null` — признак что это не корректировка, а новый расчёт (при корректировке существующей сметы это поле заполнено)
- `FenceEstimate.manualQuantityOverrides` — переопределения кол-ва
- `Order.adminEstimateId` — связь заявки с админ-расчётом
- `Order.clientName, phone, email` — данные клиента, заполненные админом

### 5.2 Таблица результатов — колонки
| Колонка | Описание |
|---------|----------|
| Наименование | Название позиции |
| Кол-во | Редактируемое поле (input number) |
| Ед. изм. | шт / м.п. / м² / рулон |
| Розничная цена | За единицу |
| Закупочная цена | За единицу (если есть) |
| Маржа | Разница розница - закупка |
| Сумма (розница) | Кол-во × розничная цена |
| Сумма (закупка) | Кол-во × закупочная цена |
| Сумма (маржа) | Кол-во × маржа |
| Действия | Удалить / Восстановить |

### 5.3 Валидация
- Длина забора: 1-1000 м
- Высота забора: 1.5-3.5 м
- Ширина ворот: не более длины забора
- Сумма ширины ворот + калитки ≤ длина забора
- ФИО клиента: min 2 символа (при создании заявки)
- Телефон: валидный российский номер (при создании заявки)
- Email: валидный email (опционально)

### 5.4 Обработка ошибок
- Нет подходящей номенклатуры → модальное окно с предложением добавить в справочник
- Ошибка расчёта → toast с описанием ошибки
- Ошибка сохранения → toast + предложение повторить

### Backend

#### TASK-BCK-001: Сервис adminCalculatorService
**Приоритет**: High  
**Зависимости**: нет

**Описание**: Создать сервис `adminCalculatorService.ts` с методами:
- `calculateAndSave(input, adminUserId)` — расчёт и сохранение сметы через `fenceEstimateService.calculateFenceEstimate()`, с пометкой `isEditedByAdmin: true`, `editedByAdminId: adminUserId`
- `updateEstimateItems(estimateId, items, comment)` — обновление позиций (добавление, удаление, корректировка кол-ва) с пересчётом итогов и сохранением `manualQuantityOverrides`
- `addNomenclatureItem(estimateId, item)` — добавление позиции, обновление итогов
- `removeNomenclatureItem(estimateId, nomenclatureId)` — удаление позиции, обновление итогов
- `calculateMultiAndSave(inputs, adminUserId)` — мульти-расчёт
- `createOrderFromEstimate(estimateId, clientData, adminUserId)` — создание заявки

**Критерии приемки**:
- [ ] Все методы работают с Prisma-транзакциями
- [ ] Поля `isEditedByAdmin`, `editedByAdminId`, `editedAt` заполняются корректно
- [ ] `manualQuantityOverrides` сохраняет автоподсчитанное и ручное кол-во
- [ ] При создании заявки Order связывается через `adminEstimateId`
- [ ] Создаётся AuditLog для каждого действия

**Файлы**: `src/services/admin/adminCalculatorService.ts`
