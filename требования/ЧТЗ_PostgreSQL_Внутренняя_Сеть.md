## 1. Цели и задачи

### 1.1 Бизнес-цель
Устранить критическую уязвимость информационной безопасности — открытый порт PostgreSQL (5433) на внешнем интерфейсе сервера, доступный для сканирования и атак из сети Интернет.

### 1.2 Пользовательская ценность
- Снижение риска несанкционированного доступа к данным
- Соответствие требованиям безопасности (OWASP, PCI DSS)
- Минимизация поверхности атаки

### 1.3 Метрики успеха
| Метрика | До | После |
|---------|-----|-------|
| Открытые порты БД на внешнем интерфейсе | 1 (5433) | 0 |
| Доступность БД для брутфорса из Интернета | Да | Нет |
| Доступ администратора через SSH-туннель | N/A | Работает |

## 2. Анализ текущего состояния

### 2.1 Проблема

```yaml
# docker-compose.yml (строки 36-47)
db:
  image: postgres:16-alpine
  container_name: fences-db
  ports:
    - "5433:5432"  # <- ПРОБЛЕМА: порт открыт на 0.0.0.0
```

**Риски:**
1. Сканеры портов обнаруживают PostgreSQL снаружи
2. Брутфорс атака на учётные данные postgres

4. SQL-инъекции через прямой доступ к БД

## 3. Функциональные требования

### 3.1 User Story

**US-001: Администратор БД**

```
As администратор системы
I want подключаться к БД только через SSH-туннель
So that БД недоступна из Интернета напрямую
```

**Acceptance Criteria (Given-When-Then):**

```gherkin
Scenario: SSH-туннель к PostgreSQL
  Given сервер доступен по SSH на порту 22
  And PostgreSQL работает в контейнере fences-db на порту 5432
  When администратор выполняет:
    ssh -L 5433:localhost:5432 user@server
  Then подключение к localhost:5433 проксируется в контейнер
  And прямое подключение к server:5433 извне невозможно

Scenario: Проверка закрытого порта
  Given порт 5433 закрыт на внешнем интерфейсе
  When внешний сканер проверяет server:5433
  Then соединение отклоняется (connection refused / timeout)
```

### 3.2 Требования к доступу

| Метод доступа | Статус | Описание |
|---------------|--------|----------|
| SSH-туннель | Основной | `ssh -L 5433:fences-db:5432 user@server` |
| docker exec | Альтернатива | `docker exec -it fences-db psql -U postgres` |
| Прямое подключение | Запрещено | Порт не пробрасывается на хост |

## 4. Нефункциональные требования

### 4.1 Безопасность

| Требование | Критерий |
|------------|----------|
| Порт БД не слушает 0.0.0.0 | `netstat -tlnp | grep 5432` — только 127.0.0.1 или нет вывода |
| Внешний сканер не видит порт | `nmap server_ip -p 5433` — filtered/closed |
| SSH-ключи для доступа | Только авторизация по ключам, пароли отключены |

### 4.2 Производительность

| Требование | Критерий |
|------------|----------|
| Латентность через SSH-туннель | <10ms дополнительной задержки |
| Внутренняя связь app ↔ db | Без изменений (docker network) |

### 4.3 Отказоустойчивость

| Требование | Критерий |
|------------|----------|
| Контейнер БД продолжает работу | После изменения docker-compose.yml |
| Приложение подключается к БД | `DATABASE_URL=postgresql://...@db:5432/...` — без изменений |

```
│  └──────────────┘    └──────────────┘    └──────────────┘   │
│                              docker network (internal)      │
│                                                              │
│  SSH-туннель: ssh -L 5433:fences-db:5432 user@server        │
└─────────────────────────────────────────────────────────────┘
```

### 5.3 Изменения в конфигурации

#### docker-compose.yml

```yaml
# ДО:
db:
  image: postgres:16-alpine
  container_name: fences-db
  restart: unless-stopped
  ports:
    - "5433:5432"
  environment:
    - POSTGRES_USER=postgres
    - POSTGRES_PASSWORD=${POSTGRES_PASSWORD}
    - POSTGRES_DB=fences
  volumes:
    - postgres_data:/var/lib/postgresql/data

# ПОСЛЕ:
db:
  image: postgres:16-alpine
  container_name: fences-db
  restart: unless-stopped
  expose:
    - "5432"
  environment:
    - POSTGRES_USER=postgres
    - POSTGRES_PASSWORD=${POSTGRES_PASSWORD}
    - POSTGRES_DB=fences
  volumes:
    - postgres_data:/var/lib/postgresql/data
```

**Ключевое изменение:** `ports: - "5433:5432"` → `expose: - "5432"`

```bash
#!/bin/bash
# scripts/db-tunnel.sh
# SSH-туннель к PostgreSQL

ssh -L 5433:fences-db:5432 -N "$SERVER"
```

## Приложение A: Команды для администратора

### Подключение через SSH-туннель

```bash
# Вариант 1: Фоновый туннель
ssh -f -N -L 5433:fences-db:5432 user@server

# Вариант 2: Интерактивный туннель (Ctrl+C для закрытия)
ssh -L 5433:fences-db:5432 -N user@server

# Подключение к БД через туннель
psql -h localhost -p 5433 -U postgres -d fences

# DBeaver / pgAdmin: host=localhost, port=5433
```

### Подключение через docker exec

```bash
# Прямой доступ к psql в контейнере
docker exec -it fences-db psql -U postgres -d fences

# Выполнить SQL-файл
docker exec -i fences-db psql -U postgres -d fences < script.sql

# Дамп БД
docker exec fences-db pg_dump -U postgres fences > dump.sql
```
