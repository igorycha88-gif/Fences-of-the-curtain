## 1. Общая информация

### 1.1 Название проекта
Расширение функционала кабинета администратора для управления справочниками: типы заборов, высоты, покрытия, лаги, столбы

## 2. Цели и задачи

### 2.1 Бизнес-цель
Предоставить администраторам полный контроль над параметрами расчета заборов через управление справочниками без участия разработчиков. Обеспечить гибкость настройки калькулятора для работы с нестандартными материалами и размерами.

### 2.2 Пользовательская ценность
Администраторы получают возможность:
- Быстро добавлять новые типы заборов и их параметры
- Управлять стандартными и нестандартными высотами материалов
- Настраивать типы покрытий и их стоимость
- Вести справочники лаг и столбов с полными характеристиками
- Все изменения автоматически применяются в калькуляторе

### 2.3 Ключевые метрики успеха
- Время добавления нового типа забора < 5 минут
- Время добавления новой высоты материала < 2 минуты
- Актуальность справочников 100% (синхронизация с калькулятором)
- Удобство использования (оценка администраторов ≥ 4.5/5)

### 3.1 Функциональные требования

#### 3.1.1 Управление типами заборов

**User Story 1: Добавление нового типа забора**
*Как администратор, я хочу добавить новый тип забора, чтобы он стал доступен в калькуляторе.*

**Acceptance Criteria:**
- Форма создания типа забора с полями:
  - Название (обязательное, 2-100 символов)
  - Описание (опциональное, до 500 символов)
  - Изображение (загрузка файла, WebP, max 2MB)
  - Коэффициент сложности монтажа (float, default 1.0, min 0.5, max 3.0)
  - Активность (boolean, default true)
  - Порядок сортировки (int, default 0)
  - Шаг установки столбов (float, метров, default 2.5, min 1.5, max 4.0)
  - Количество лаг по умолчанию (int, 2 или 3, default 2)
- Валидация всех полей на клиенте (Zod)
- Предпросмотр изображения перед сохранением
- После создания тип появляется в списке и калькуляторе (если active=true)
- Уведомление об успешном создании

**User Story 2: Деактивация типа забора**
*Как администратор, я хочу сделать тип забора неактивным, чтобы он не отображался в калькуляторе, но сохранился в базе.*

**Acceptance Criteria:**
- Кнопка "Деактивировать" в таблице типов заборов
- При деактивации:
  - Поле active устанавливается в false
  - Тип исчезает из калькулятора
  - Тип остается в списке админки с пометкой "Неактивен"
  - Существующие заказы с этим типом остаются без изменений
- Возможность повторной активации
- Подтверждение действия (модальное окно)
- Логирование действия (кто, когда, какой тип)

**User Story 3: Редактирование типа забора**
*Как администратор, я хочу редактировать параметры типа забора.*

**Acceptance Criteria:**
- Редактирование всех полей из User Story 1
- Отображение текущих значений в форме
- Валидация изменений
- Предпросмотр изменений перед сохранением
- История изменений (опционально)
- После сохранения изменения применяются в калькуляторе

**User Story 4: Удаление типа забора**
*Как администратор, я хочу удалить тип забора, если он не используется.*

**Acceptance Criteria:**
- Кнопка "Удалить" только для типов, которые не используются в заказах
- Проверка перед удалением:
  - Если есть заказы с этим типом → показывается ошибка "Невозможно удалить, используется в X заказах"
  - Если нет заказов → разрешается удаление
- Подтверждение удаления (модальное окно с предупреждением)
- Безвозвратное удаление из БД
- Логирование удаления

  - Название материала

  - По активности

- Поиск по названию материала
- Пагинация (20 записей на странице)
- Сортировка по названию, категории

**User Story 6: Добавление стандартной высоты материала**
*Как администратор, я хочу добавить стандартную высоту для материала (например, профнастил 1.8м, 2.0м, 2.5м).*

**Acceptance Criteria:**
- Кнопка "Добавить высоту" для материала
- Форма добавления высоты:
  - Выбор материала (dropdown)
  - Высота (float, метры, обязательное, min 1.0, max 4.0, шаг 0.1)
  - Коэффициент цены (float, default 1.0, опционально)
    - Если 1.0 → цена материала не меняется
    - Если 1.1 → цена увеличивается на 10%
    - Если 0.9 → цена уменьшается на 10%
- Валидация:
  - Высота не должна дублироваться для того же материала
  - Высота должна быть в допустимом диапазоне
- После добавления:
  - Высота появляется в массиве availableHeights материала
  - Высота становится доступна в калькуляторе для выбора
- Автоматический расчет стоимости в калькуляторе с учетом коэффициента

**Анализ стандартных высот материалов:**

**Профнастил:**
- Стандартные высоты: 1.5м, 1.8м, 2.0м, 2.2м, 2.5м, 3.0м
- Стандартная ширина листа: 1.0-1.2м (рабочая ширина)

**Евроштакетник:**
- Стандартные высоты: 1.5м, 1.7м, 1.8м, 2.0м, 2.2м, 2.5м
- Ширина штакетника: 80-120мм

**Сетка-рабица:**
- Стандартные высоты: 1.5м, 1.8м, 2.0м, 2.5м, 3.0м
- Ширина рулона: 1.5м

**3D-панели:**
- Стандартные высоты: 1.53м, 1.73м, 2.03м, 2.43м
- Ширина панели: 2.5м

**User Story 7: Добавление нестандартной высоты вручную**
*Как администратор, я хочу добавить нестандартную высоту материала, которая не предусмотрена справочником.*

**Acceptance Criteria:**
- Форма добавления нестандартной высоты:
  - Выбор материала (dropdown)
  - Высота (float, метры, обязательное, min 1.0, max 5.0, шаг 0.05)
  - Флаг "Нестандартная высота" (автоматически true при вводе нестандартного значения)
  - Коэффициент цены (обязательное для нестандартных, обычно > 1.0)
  - Комментарий (опциональное, до 200 символов, например "Под заказ")
- Валидация:
  - Предупреждение если высота отличается от стандартных значений
  - Проверка на дублирование
- После добавления:
  - Высота помечается как нестандартная (isCustom: true)
  - В калькуляторе показывается с пометкой "Нестандартная"
  - Цена автоматически пересчитывается с учетом коэффициента
- Возможность удаления нестандартных высот

**User Story 8: Редактирование высоты материала**
*Как администратор, я хочу изменить параметры высоты материала.*

**Acceptance Criteria:**
- Редактирование полей:
  - Высота (если не используется в заказах)
  - Коэффициент цены
  - Комментарий (для нестандартных)
- Проверка перед редактированием высоты:
  - Если есть заказы с этой высотой → запрет редактирования высоты
  - Можно редактировать только коэффициент и комментарий
- Валидация изменений
- Логирование изменений

**User Story 9: Удаление высоты материала**
*Как администратор, я хочу удалить высоту материала, если она не используется.*

**Acceptance Criteria:**
- Кнопка "Удалить высоту"
- Проверка перед удалением:
  - Если есть заказы с этой высотой → ошибка "Невозможно удалить, используется в X заказах"

  - Толщина металла (мм)

**User Story 15: Добавление лаги**
*Как администратор, я хочу добавить новый тип лаги с полными характеристиками.*

**Acceptance Criteria:**
- Форма создания лаги:
  - Название (обязательное, 2-100 символов, например "Профиль 40x20")
  - Ширина сечения (float, мм, обязательное, min 20, max 100)
  - Высота сечения (float, мм, обязательное, min 20, max 100)
  - Толщина металла (float, мм, обязательное, min 1.0, max 5.0)
  - Базовая цена за метр погонный (float, руб, обязательное, min 0)
  - Доступные длины (массив float, метры):
    - Стандартные длины: [2.5, 3.0] (зависят от шага столбов)
    - Возможность добавления нестандартных длин
    - Каждая длина может иметь свой коэффициент цены (опционально)
  - Изображение сечения (опциональное, WebP, max 2MB)
  - Описание (опциональное, до 300 символов)
  - Активность (boolean, default true)
  - Порядок сортировки (int, default 0)
- Валидация:
  - Уникальность комбинации ширина + высота + толщина
  - Длины должны быть в диапазоне 1.5 - 6.0 метров
- После создания:
  - Лага появляется в списке
  - Лага доступна в калькуляторе
- Автоматический расчет:
  - Длина лаги = шаг установки столбов (зависит от типа забора)
  - Количество лаг = длина забора * количество рядов лаг

**Acceptance Criteria:**
- При создании/редактировании лаги можно задать массив цен по длинам
- Структура: `[{ length: 2.5, price: 150, coef: 1.0 }, { length: 3.0, price: 180, coef: 1.1 }]`
- В калькуляторе:
  - Пользователь выбирает тип забора → определяется шаг столбов
  - Шаг столбов определяет длину лаги
  - Цена берется из соответствующей записи
- Если для выбранной длины нет цены, используется базовая цена * коэффициент длины

  - Толщина металла (float, мм, обязательное, min 1.5, max 5.0)
  - Базовая цена за метр погонный (float, руб, обязательное, min 0)

    - Зависят от возможной высоты забора + заглубление (обычно +0.5-0.8м)
    - Формула: длина столба = высота забора + 0.7м (заглубление)
    - Возможность добавления нестандартных длин
    - Каждая длина может иметь свой коэффициент цены (опционально)

  - Уникальность комбинации сечение + толщина
  - Длины должны быть в диапазоне 1.5 - 5.0 метров
- После создания:
  - Столб появляется в списке
  - Столб доступен в калькуляторе
- Автоматический расчет:
  - Длина столба = выбранная высота забора + 0.7м
  - Количество столбов = длина забора / шаг установки + 1

- Ограничения:
  - Нельзя изменить сечение если есть заказы с этим столбом
  - Можно изменить цену и доступные длины
- Валидация изменений
- История изменений цен
- После сохранения изменения применяются в калькуляторе

**User Story 22: Удаление столба**
*Как администратор, я хочу удалить тип столба.*

**Acceptance Criteria:**
- Кнопка "Удалить" только для неиспользуемых столбов
- Проверка перед удалением:
  - Если есть заказы → ошибка
  - Если нет заказов → разрешается удаление
- Подтверждение удаления
- Безвозвратное удаление
- Логирование

**User Story 23: Управление ценами по длинам столбов**
*Как администратор, я хочу указывать разные цены для разных длин столбов.*

**Acceptance Criteria:**
- При создании/редактировании столба можно задать массив цен по длинам
- Структура: `[{ length: 2.5, pricePerMeter: 350, priceWithConcrete: 800 }, { length: 3.0, pricePerMeter: 420, priceWithConcrete: 950 }]`
- В калькуляторе:
  - Пользователь выбирает высоту забора → определяется длина столба
  - Цена берется из соответствующей записи
- Если для выбранной длины нет цены, используется базовая цена * коэффициент длины

### 3.2 Нефункциональные требования

#### 3.2.1 Производительность
- Время загрузки страниц справочников < 2 секунд
- Время отклика API CRUD операций < 500 мс
- Время поиска/фильтрации < 300 мс
- Поддержка одновременной работы 5+ администраторов
- Пагинация списков (20-50 записей на странице)
- Lazy loading для изображений
- Кеширование справочников в Redis (TTL 5 минут)

- Авторизация required для всех страниц
- Ролевой доступ (RBAC):
  - ADMIN: полный доступ ко всем операциям

  - CONTENT_MANAGER: только чтение
- Защита от CSRF (встроена в Next.js)
- Валидация всех входных данных (Zod)
- Логирование всех изменений (кто, что, когда, старое значение, новое значение)
- Защита от SQL-инъекций (Prisma)

#### 3.2.3 Масштабируемость
- Поддержка до 100 типов заборов
- Поддержка до 500 материалов
- Поддержка до 50 типов покрытия
- Поддержка до 100 типов лаг
- Поддержка до 100 типов столбов
- Оптимизация SQL запросов с индексами
- Кеширование часто запрашиваемых данных

#### 3.2.4 Доступность
- Поддержка keyboard navigation
- ARIA labels для всех интерактивных элементов
- Адаптивная верстка для планшетов (1024px+)
- Контрастность цветов соответствует WCAG AA
- Подсказки и tooltips для полей

#### 3.2.5 Совместимость
- Поддержка браузеров: Chrome, Firefox, Safari, Edge (последние 2 версии)
- Минимальное разрешение экрана: 1024px
- Рекомендуется desktop для комфортной работы

## Приложение А: Формулы расчета

### А.1 Расчет стоимости с учетом высоты материала

```
// Базовая цена материала
baseMaterialCost = material.basePrice * area

// Цена с учетом коэффициента высоты
heightCoef = material.availableHeights.find(h => h.height === selectedHeight).priceCoef

// Итоговая стоимость материала
finalMaterialCost = baseMaterialCost * heightCoef
```

**Пример:**
- Профнастил С8, базовая цена 450 руб/м²
- Площадь забора 100 м²
- Выбранная высота 2.0м, коэффициент 1.1
- Итоговая стоимость = 450 * 100 * 1.1 = 49,500 руб

### А.2 Расчет стоимости покрытия

```
// Базовая стоимость покрытия
baseCoatingCost = coating.baseCost * area

// Стоимость с учетом коэффициента наценки
coatingCost = baseCoatingCost * coating.markupCoef

// Итоговая стоимость материала с покрытием
totalCost = materialCost + coatingCost
```

**Пример:**
- Полимерное одностороннее покрытие
- Базовая стоимость 50 руб/м²
- Коэффициент наценки 1.15
- Площадь 100 м²
- Стоимость покрытия = 50 * 100 * 1.15 = 5,750 руб

### А.3 Расчет стоимости лаг

```
// Определение длины лаги на основе шага столбов
lagLength = fenceType.postSpacing

// Получение коэффициента цены для длины
lengthCoef = lag.availableLengths.find(l => l.length === lagLength)?.priceCoef || 1.0

// Количество лаг
lagsCount = fenceLength * lagRows

// Итоговая стоимость лаг
totalLagCost = lag.basePricePerMeter * lagsCount * lengthCoef
```

**Пример:**
- Лага "Профиль 40x20x2.0", базовая цена 150 руб/м.п.
- Длина забора 50м, 2 ряда лаг
- Шаг столбов 2.5м → длина лаги 2.5м
- Коэффициент для длины 2.5м = 1.0
- Количество лаг = 50 * 2 = 100 м.п.
- Итоговая стоимость = 150 * 100 * 1.0 = 15,000 руб

### А.4 Расчет стоимости столбов

```
// Определение длины столба на основе высоты забора
postLength = selectedFenceHeight + 0.7 // +0.7м на заглубление

// Получение цены для длины
lengthPrice = post.availableLengths.find(l => l.length === postLength)
if (lengthPrice) {
  pricePerMeter = lengthPrice.pricePerMeter
  priceWithConcrete = lengthPrice.priceWithConcrete
} else {
  // Если нет цены для конкретной длины, используем базовую
  pricePerMeter = post.pricePerMeter * (postLength / 2.5) // пропорционально
  priceWithConcrete = post.priceWithConcrete
}

// Количество столбов
postsCount = Math.ceil(fenceLength / fenceType.postSpacing) + 1

// Итоговая стоимость столбов
totalPostCost = postsCount * postLength * pricePerMeter

// Итоговая стоимость с бетонированием
totalPostWithConcreteCost = postsCount * priceWithConcrete
```

**Пример:**
- Столб "60x60x2.5"
- Высота забора 2.0м → длина столба 2.7м
- Базовая цена 350 руб/м.п., с бетонированием 800 руб/шт
- Длина забора 50м, шаг столбов 2.5м
- Количество столбов = ceil(50 / 2.5) + 1 = 21 шт
- Итоговая стоимость = 21 * 2.7 * 350 = 19,845 руб
- С бетонированием = 21 * 800 = 16,800 руб
