## Статус: Согласовано

## 1. Цели и задачи

### 1.1 Бизнес-цель
Обеспечить полную прослеживаемость работы менеджера с заявкой на каждом этапе. Система должна гарантировать, что менеджер заполняет необходимую информацию при переводе заявки в следующий статус, что позволит анализировать эффективность работы и качество обслуживания клиентов.

### 1.2 Пользовательская ценность
- **Менеджер**: Видит четкие требования к каждому статусу, не забывает заполнить важную информацию (дата замера, адрес и т.д.)
- **Руководитель**: Получает полную историю работы с клиентом, может анализировать причины отказов и время на каждом этапе
- **Клиент**: Получает более качественный сервис (менеджер не забудет про дату замера или адрес)

### 1.3 Метрики успеха
- Полнота заполнения обязательных полей: 100%
- Время обработки заявки на каждом этапе (для анализа эффективности)
- Причины отмен заявок (для улучшения сервиса)
- Возврат заявок из-за некорректных данных: < 5%

## 2. Функциональные требования

### 2.1 Статусная модель с полями

| Переход | Обязательные поля | Опциональные поля |
|---------|------------------|-------------------|
| NEW → ESTIMATE_APPROVAL | - | `contactResult` (результат связи), `preferredContactDate` (предпочтительная дата связи) |
| ESTIMATE_APPROVAL → MEASUREMENT | `measurementAddress` (адрес объекта) | `measurementDate` (дата замера), `measurementComment` (комментарий к замеру) |
| MEASUREMENT → PRODUCTION | - | `measurementConfirmed` (подтверждение сметы), `measurementResult` (результат замера), `adjustedCost` (скорректированная стоимость) |
| PRODUCTION → INSTALLATION | - | `productionReadyDate` (дата готовности), `productionNotes` (примечания) |
| INSTALLATION → COMPLETED | - | `completionDate` (дата завершения), `clientSatisfied` (клиент доволен), `photos` (ссылки на фото), `reviewLink` (ссылка на отзыв) |
| * → CANCELLED | `cancellationReason` (причина отмены), `cancellationComment` (комментарий) | - |

**Примечание**: Большинство полей опциональны, чтобы не блокировать работу менеджеров. Обязательны только критичные поля: адрес замера (для бригады) и причина отмены (для аналитики).

### 2.2 Детализация обязательных полей

#### `contactResult` (результат связи)
```typescript
type ContactResult = 
  | 'REACHED'           // Дозвонились, обсудили
  | 'CALLBACK'          // Перезвонить позже
  | 'NO_ANSWER'         // Не ответили
  | 'LEFT_MESSAGE'      // Оставили сообщение
```

#### `cancellationReason` (причина отмены)
```typescript
type CancellationReason =
  | 'PRICE_TOO_HIGH'        // Цена слишком высокая
  | 'FOUND_OTHER_CONTRACTOR' // Выбрали другого подрядчика
  | 'CHANGED_MIND'          // Передумал
  | 'NOT_RESPONSIVE'        // Клиент не выходит на связь
  | 'PROJECT_POSTPONED'     // Проект отложен
  | 'OTHER'                 // Другое
```

### 2.3 User Stories

#### US-1: Перевод заявки в статус "Согласование сметы"
**Как** менеджер,  
**Я хочу** указать результат связи с клиентом при переводе заявки в согласование,  
**Чтобы** другие менеджеры понимали статус коммуникации.

**Acceptance Criteria**:
```
Given я нахожусь в деталях заявки со статусом "Новая"
When выбираю статус "Согласование сметы"
Then открывается форма с полями:
  - Результат связи (select: Дозвонились/Перезвонить/Не ответили/Оставили сообщение, опционально)
  - Предпочтительная дата связи (date picker, опционально)
When нажимаю "Сохранить"
Then статус меняется на "Согласование сметы"
And запись добавляется в историю с заполненными полями (или пустыми если не заполнял)
```

#### US-2: Назначение замера
**Как** менеджер,  
**Я хочу** указать адрес замера при переводе заявки,  
**Чтобы** бригада знала куда ехать.

**Acceptance Criteria**:
```
Given я нахожусь в деталях заявки со статусом "Согласование сметы"
When выбираю статус "Замер"
Then открывается форма с полями:
  - Адрес объекта * (text, min 10 символов, обязательно)
  - Дата замера (date picker, опционально)
  - Комментарий к замеру (textarea, опционально)
When заполняю адрес и нажимаю "Сохранить"
Then статус меняется на "Замер"
And адрес сохраняется в истории и в отдельном поле Order.measurementAddress
When не заполняю адрес
Then кнопка "Сохранить" неактивна
And показывается сообщение "Адрес объекта обязателен"
```

#### US-3: Подтверждение результатов замера
**Как** менеджер,  
**Я хочу** указать результат замера при переводе в производство,  
**Чтобы** производство получило точные данные.

**Acceptance Criteria**:
```
Given я нахожусь в деталях заявки со статусом "Замер"
When выбираю статус "Производство"
Then открывается форма с полями:
  - Подтверждение сметы (checkbox: "Смета подтверждена", опционально)
  - Результат замера (textarea, опционально)
  - Скорректированная стоимость (number, опционально)
When нажимаю "Сохранить"
Then статус меняется на "Производство"
When указываю скорректированную стоимость
Then она сохраняется и отображается в деталях заявки
```

#### US-4: Отмена заявки
**Как** менеджер,  
**Я хочу** указать причину отмены при закрытии заявки,  
**Чтобы** руководитель мог анализировать причины отказов.

**Acceptance Criteria**:
```
Given я нахожусь в деталях заявки с любым статусом
When выбираю статус "Отменена"
Then открывается форма с полями:
  - Причина отмены * (select из списка)
  - Комментарий * (textarea, min 10 символов)
When выбираю причину "Другое"
Then поле комментария становится обязательным и подсвечивается
When заполняю поля и нажимаю "Сохранить"
Then статус меняется на "Отменена"
And причина отмены сохраняется в истории
```

#### US-5: Просмотр истории изменений статусов
**Как** менеджер или руководитель,  
**Я хочу** видеть полную историю изменений заявки,  
**Чтобы** понимать кто, когда и что делал с заявкой.

**Acceptance Criteria**:
```
Given я нахожусь в деталях заявки
When прокручиваю страницу вниз
Then вижу раздел "История изменений"
And каждая запись содержит:
  - Дата и время изменения
  - Кто изменил (имя менеджера)
  - Предыдущий статус → Новый статус
  - Все заполненные поля при смене статуса
When кликаю на запись истории
Then вижу развернутую информацию со всеми полями
```

#### US-6: Редактирование истории изменений
**Как** администратор,  
**Я хочу** редактировать любые записи в истории изменений,  
**Чтобы** исправлять ошибки в данных.

**Acceptance Criteria**:
```
Given я нахожусь в деталях заявки
And моя роль = ADMIN
When нажимаю "Редактировать" рядом с любой записью истории
Then могу изменить заполненные поля
When сохраняю изменения
Then запись в истории обновляется
And добавляется пометка "(отредактировано)" с датой редактирования
When моя роль ≠ ADMIN
Then кнопка "Редактировать" не отображается
```

## 3. Нефункциональные требования

### 3.1 Производительность
- Загрузка истории изменений: < 300ms
- Сохранение статуса с валидацией: < 500ms
- Поддержка до 1000 записей в истории одной заявки

### 3.2 Безопасность
- Только авторизованные менеджеры могут менять статусы
- Редактирование истории только для роли ADMIN
- Аудит всех изменений (кто, когда, что изменил)

### 3.3 Масштабируемость
- Индексы на полях: status, createdAt, userId в statusHistory
- JSONB индекс для поиска по statusHistory

### 4.2 API спецификация

#### PATCH /api/admin/orders/[id]/status
Изменение статуса заявки с заполнением обязательных полей.

**Request для NEW → ESTIMATE_APPROVAL**:
```json
{
  "status": "ESTIMATE_APPROVAL",
  "data": {
    "contactResult": "REACHED",
    "preferredContactDate": "2026-03-18"
  }
}
```

**Request для ESTIMATE_APPROVAL → MEASUREMENT**:
```json
{
  "status": "MEASUREMENT",
  "data": {
    "measurementDate": "2026-03-20",
    "measurementAddress": "г. Москва, ул. Ленина, д. 10",
    "measurementComment": "Дом за забором, звонить за 30 минут"
  }
}
```

{
  "status": "CANCELLED",
  "data": {
    "cancellationReason": "PRICE_TOO_HIGH",

### 4.3 Интерфейсы/типы данных

```typescript
// src/types/order.ts

export type ContactResult = 
  | 'REACHED'
  | 'CALLBACK'
  | 'NO_ANSWER'
  | 'LEFT_MESSAGE';

export type CancellationReason =
  | 'PRICE_TOO_HIGH'
  | 'FOUND_OTHER_CONTRACTOR'
  | 'CHANGED_MIND'
  | 'NOT_RESPONSIVE'
  | 'PROJECT_POSTPONED'
  | 'OTHER';

export interface StatusChangeData {
  // Для NEW → ESTIMATE_APPROVAL
  contactResult?: ContactResult;
  preferredContactDate?: string;

  // Для ESTIMATE_APPROVAL → MEASUREMENT
  measurementDate?: string;
  measurementAddress?: string;
  measurementComment?: string;

  // Для MEASUREMENT → PRODUCTION
  measurementConfirmed?: boolean;
  measurementResult?: string;
  adjustedCost?: number;

  // Для PRODUCTION → INSTALLATION
  productionReadyDate?: string;
  productionNotes?: string;

  // Для INSTALLATION → COMPLETED
  completionDate?: string;
  clientSatisfied?: boolean;
  photos?: string[];
  reviewLink?: string;

  // Для * → CANCELLED
  cancellationReason?: CancellationReason;
  cancellationComment?: string;
}

export interface StatusHistoryEntry {
  status: OrderStatus;
  changedAt: string;
  changedBy: string;
  changedByName: string;
  data: StatusChangeData;
  editedAt?: string;
  editedBy?: string;
}

export interface UpdateStatusRequest {
  status: OrderStatus;
  data: StatusChangeData;
}

export interface UpdateStatusHistoryRequest {
  data: Partial<StatusChangeData>;
}
```

| completionDate | Дата <= сегодня |

### 5.4 Обработка ошибок

- Обязательные поля подсвечиваются красной рамкой при попытке сохранить без заполнения
- Под полем показывается текст ошибки валидации
- Кнопка "Сохранить" неактивна пока не заполнены все обязательные поля
- При ошибке сервера показывается toast-уведомление с текстом ошибки

## 8. Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Менеджеры не заполняют важные поля | Средняя | Среднее | Подсказки в UI, напоминания |
| Ошибки в данных (неправильный адрес) | Средняя | Среднее | Возможность редактирования администратором |
| Миграция существующих данных | Низкая | Среднее | Скрипт миграции с сохранением существующей истории |
| Медленная загрузка истории при большом количестве записей | Низкая | Низкое | Пагинация истории, ленивая загрузка |
