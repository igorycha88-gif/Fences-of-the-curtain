# ЧТЗ: Временная остановка сайта на проде

**Дата:** 2026-08-31
**Маршрут:** 3 (Инфраструктурная задача → DevOps)
**Исполнитель:** DevOps

## Постановка

Пользователь запросил временную остановку сайта на проде до следующего дня («завтра запустим»).

## Решение

- Остановить контейнер приложения `fences-app` на VPS 37.143.13.196 (`docker stop fences-app`).
- НЕ удалять контейнер, образ, тома.
- НЕ трогать PostgreSQL, Redis (на хосте) и мониторинг (Grafana/Prometheus/exporters).
- Nginx остаётся работать — будет отдавать 502 пока app остановлен.

## Дополнение (2026-08-31, по запросу пользователя)

1. Дополнительно остановлен nginx на хосте VPS (`systemctl stop nginx`).
2. Обнаружен и остановлен легаси-инстанс `fences.service` (systemd, Next.js вне Docker, порт 3000, работал с 2026-04-22, enabled). Он был доступен снаружи напрямую (iptables policy ACCEPT) в обход nginx.

## Критерии приёмки

1. Контейнер `fences-app` в статусе `Exited`.
2. Nginx остановлен, порты 80/443 не слушаются.
3. `fences.service` остановлен, порт 3000 не слушается.
4. `https://zabor-i-naves.ru` и `http://37.143.13.196:3000` полностью недоступны.
5. Данные БД и конфигурация не изменены.

## Перезапуск (завтра)

```bash
ssh root@37.143.13.196 "systemctl start nginx && docker start fences-app"
# проверить: docker ps + curl -f https://zabor-i-naves.ru/api/health
```

⚠️ Примечание: `fences.service` НЕ запускать — это дублирующий легаси-инстанс;
основной app теперь в Docker (`fences-app`, порт 3001 за nginx). Рекомендуется
в дальнейшем `systemctl disable fences.service`, чтобы не путался под руками.
