## 2. Цели и задачи

### 2.1 Бизнес-цель
Создать справочник калиток для управления номенклатурой с возможностью указания технических характеристик, цен и периодов действия.

### 2.2 Пользовательская ценность
- Централизованное управление номенклатурой калиток
- Прозрачный расчет маржи для администраторов
- Управление периодами действия цен

### 2.3 Ключевые метрики успеха
- Справочник полностью функционален и доступен в админ-панели
- Все CRUD операции работают корректно
- Фильтрация и поиск работают

## 3. Требования к продукту

### 3.1 Функциональные требования

#### 3.1.1 Структура таблицы справочника

**User Story 1: Просмотр списка калиток**
*Как администратор, я хочу видеть список всех калиток с ключевыми характеристиками в таблице.*

**Acceptance Criteria:**
- Таблица содержит следующие колонки:
  - **Толщина металла (мм)** - числовое значение
  - **Сечение (мм)** - формат "ширина x высота"
  - **Высота (мм)** - высота калитки
  - **Длина (мм)** - ширина калитки
  - **Срок действия** - дата истечения или "Бессрочно"
  - **Цена закупки за ед. (₽)** - только для ADMIN, с индикатором маржи
  - **Активен** - переключатель (да/нет)
  - **Действия** - редактировать, удалить
- Сортировка по всем колонкам
- Поиск по названию
- Фильтр по статусу активности и сроку действия (аналогично Лагам):
  - "Все"
  - "Активные"
  - "Истек срок"
  - "Истекает скоро"

---

#### 3.1.2 Карточка номенклатуры (форма создания/редактирования)

**User Story 2: Создание новой номенклатуры калитки**
*Как администратор, я хочу создать новую номенклатуру калитки с указанием всех характеристик.*

**Поля формы:**

| Поле | Тип | Обязательно | Валидация |
|------|-----|-------------|-----------|
| Название | text | Да | min 2, max 100 символов |
| Описание | textarea | Нет | max 500 символов |
| Толщина металла (мм) | number | Да | 1.0 - 5.0, шаг 0.1 |
| Ширина сечения (мм) | number | Да | 20 - 200 |
| Высота сечения (мм) | number | Да | 20 - 200 |
| Высота калитки (мм) | number | Да | 500 - 2500 |
| Длина (мм) | number | Да | 500 - 2000 |
| Розничная стоимость (₽) | number | Да | ≥ 0 |
| Дата начала действия | date | Нет | Пусто = с момента добавления |
| Срок действия | date | Нет | Пусто = бессрочно |
| Цена закупки за ед. (₽) | number | Нет | ≥ 0, только ADMIN |
| Активен | checkbox | Да | По умолчанию true |

**Acceptance Criteria:**
- Все обязательные поля отмечены asterisk (*)
- Валидация на клиенте и сервере (Zod)
- Предзаполнение при редактировании
- Расчет маржи в реальном времени (только для ADMIN)
- Цветовая индикация маржи:
  - 🟢 ≥ 30%
  - 🟡 10-30%
  - 🔴 < 10%
  - ⚪ Не указана

---

#### 3.1.3 Период действия (аналогично Лагам)

**User Story 3: Управление периодом действия**
*Как администратор, я хочу указывать период действия для номенклатуры.*

**Acceptance Criteria:**
- Поле "Дата начала действия" (validFrom) - опционально
- Поле "Срок действия" (expirationDate) - опционально
- Пустое значение = бессрочно / с момента добавления
- Автоматическая деактивация при истечении срока (в 01:00 следующего дня)
- Фильтр в таблице: "Все", "Активные", "Истек срок", "Истекает скоро"
- Цветовая индикация:
  - Красный - истёк
  - Жёлтый - истекает в течение 7 дней
  - Серый - бессрочно

---

#### 3.1.4 Расчёт маржи (аналогично Лагам)

**User Story 4: Расчёт и отображение маржи**
*Как администратор (ADMIN), я хочу видеть расчёт маржи для оценки прибыльности.*

**Acceptance Criteria:**
- Маржа видна **только** для роли ADMIN
- Формула: `Маржа (%) = (Розничная - Закупка) / Розничная * 100`
- Абсолютная маржа: `Розничная - Закупка`
- Цветовая индикация в таблице (emoji)
- Tooltip при наведении показывает детализацию
- Расчёт в реальном времени при вводе цен в форме

---

#### 3.1.5 Контроль доступа

**User Story 5: Ограничение доступа к ценам закупки**
*Как система, я хочу скрыть цены закупки от пользователей с ролью MANAGER и CONTENT_MANAGER.*

**Acceptance Criteria:**
- Роль ADMIN:
  - Видит колонку "Цена закупки за ед."
  - Может редактировать цену закупки
  - Видит расчёт маржи
- Роль MANAGER:
  - **Не видит** колонку "Цена закупки за ед."
  - **Не видит** секцию ввода цены закупки в форме
  - Видит только розничную стоимость
- Роль CONTENT_MANAGER:
  - Аналогично MANAGER
- API:
  - GET запросы возвращают поле `purchasePrice` только для ADMIN
  - POST/PUT запросы с `purchasePrice` отклоняются для не-ADMIN (403)

```prisma
model WicketType {
  id                    String    @id @default(cuid())
  name                  String
  description           String?
  metalThickness        Float     // Толщина металла (мм)
  sectionWidth          Float     // Ширина сечения (мм)
  sectionHeight         Float     // Высота сечения (мм)
  wicketHeight          Float     // Высота калитки (мм)
  wicketLength          Float     // Длина/ширина калитки (мм)
  retailPrice           Float     // Розничная стоимость (₽)
  purchasePrice         Float?    // Цена закупки за ед. (₽) - только ADMIN
  image                 String?
  active                Boolean   @default(true)
  validFrom             DateTime?
  expirationDate        DateTime?
  createdAt             DateTime  @default(now())
  updatedAt             DateTime  @updatedAt
  
  @@index([active])
  @@index([validFrom])
  @@index([expirationDate])
  @@index([sectionWidth, sectionHeight, metalThickness, wicketLength])
}
```

## 5. API спецификация

### 5.1 GET /api/admin/wicket-types

**Query Parameters:**
- `page` - номер страницы (default: 1)
- `pageSize` - размер страницы (default: 20)
- `search` - поиск по названию
- `validityFilter` - фильтр по сроку: all | active | expired | expiring_soon

**Response 200 (для ADMIN):**
```json
{
  "wickets": [
    {
      "id": "wicket-id",
      "name": "Калитка 1x2",
      "description": "Стандартная калитка",
      "metalThickness": 2.0,
      "sectionWidth": 40,
      "sectionHeight": 40,
      "wicketHeight": 2000,
      "wicketLength": 1000,
      "retailPrice": 15000,
      "purchasePrice": 10000,
      "active": true,
      "validFrom": "2026-03-01T00:00:00.000Z",
      "expirationDate": null
    }
  ],
  "total": 50
}
```

**Response 200 (для MANAGER):**
```json
{
  "wickets": [
    {
      "id": "wicket-id",

```

### 5.2 POST /api/admin/wicket-types

**Request Body:**
```json
{
  "name": "Калитка 1x2",
  "description": "Стандартная калитка",
  "metalThickness": 2.0,
  "sectionWidth": 40,
  "sectionHeight": 40,
  "wicketHeight": 2000,
  "wicketLength": 1000,
  "retailPrice": 15000,
  "purchasePrice": 10000,
  "validFrom": "2026-03-01",
  "expirationDate": null,
  "active": true
}
```

**Validation Schema:**
```typescript
const wicketTypeSchema = z.object({
  name: z.string().min(2).max(100),
  description: z.string().max(500).optional(),
  metalThickness: z.number().min(1.0).max(5.0),
  sectionWidth: z.number().min(20).max(200),
  sectionHeight: z.number().min(20).max(200),
  wicketHeight: z.number().min(500).max(2500),
  wicketLength: z.number().min(500).max(2000),
  retailPrice: z.number().min(0),
  purchasePrice: z.number().min(0).optional().nullable(),
  validFrom: z.coerce.date().optional().nullable(),
  expirationDate: z.coerce.date().optional().nullable(),
  active: z.boolean(),
});
```

### 5.3 PUT /api/admin/wicket-types/:id

**Request Body:** (частичное обновление)
```json
{
  "retailPrice": 16000,
  "purchasePrice": 10500,
  "expirationDate": "2026-06-01"
}
```

### 5.4 DELETE /api/admin/wicket-types/:id

**Response 200:**
```json
{
  "success": true,
  "message": "Калитка успешно удалена"
}
```

### 5.5 PATCH /api/admin/wicket-types/:id (toggle active)

**Response 200:**
```json
{
  "success": true,
  "active": false
}
```
