# ЧТЗ: Фикс ошибки «Исходный расчет не найден» при редактировании сметы

**Дата:** 2026-05-04
**Маршрут:** Стандартный (Аналитик → Разработчик → Тестировщик → DevOps)
**Исполнитель:** Разработчик

---

## 1. Описание проблемы

При редактировании сметы (админ-estimate) в карточке заявки и при пересчёте в калькуляторе администратора возникает ошибка 404:
```
/api/admin/orders/{orderId}/admin-estimate → 404
Error: "Исходный расчет не найден"
```

## 2. Корневая причина

Админский расчёт (`FenceEstimate` с `isEditedByAdmin: true`) хранит `sourceEstimateId` — ссылку на исходный расчёт клиента. Если исходный расчёт был удалён (или никогда не существовал), три метода в `estimateEditorService` падают:

| Метод | Строка | Ошибка |
|-------|--------|--------|
| `updateAdminEstimate()` | 312-314 | `existing.sourceEstimate` = `null` → бросает `'Source estimate not found for admin estimate'` |
| `createAdminEstimate()` | 105-111 | `prisma.fenceEstimate.findUnique` не находит → бросает `'Source estimate not found'` |
| `recalculateWithParams()` | 61-68 | Аналогично → бросает `'Source estimate not found'` |

## 3. Файлы для изменения

| Файл | Изменение |
|------|-----------|
| `src/services/admin/estimateEditorService.ts` | Обработать отсутствие `sourceEstimate` — использовать данные самого админского расчёта как базовые |
| `src/app/api/admin/orders/[id]/admin-estimate/route.ts` | Убедиться, что PUT handler корректно передаёт `sourceEstimateId` |
| `src/components/admin/Orders/OrderDetailPage.tsx` | Убедиться, что `estimateId` prop корректно вычисляется, когда `estimate` = `null` |

## 4. Решение

### 4.1. `estimateEditorService.ts` — `updateAdminEstimate()`

**Было (строка 312-315):**
```typescript
const sourceEstimate = existing.sourceEstimate;
if (!sourceEstimate) {
  throw new Error('Source estimate not found for admin estimate');
}
```

**Стало:**
```typescript
const sourceEstimate = existing.sourceEstimate;
if (!sourceEstimate) {
  // Исходный расчёт удалён — используем сам админский расчёт как базу
  sourceEstimate = existing;
}
```

При этом `sourceEstimate` должен быть `let`, а не `const`. Если используется как `existing` (сам себя), `buildMergedParams` всё равно корректно отработает, т.к. `existing` содержит все нужные поля (length, height, coating и т.д.).

### 4.2. `estimateEditorService.ts` — `createAdminEstimate()`

**Было (строка 105-111):**
```typescript
const sourceEstimate = await prisma.fenceEstimate.findUnique({
  where: { id: sourceEstimateId },
  include: { fenceType: true },
});
if (!sourceEstimate) {
  throw new Error('Source estimate not found');
}
```

**Стало:**
```typescript
let sourceEstimate = await prisma.fenceEstimate.findUnique({
  where: { id: sourceEstimateId },
  include: { fenceType: true },
});
if (!sourceEstimate) {
  // Исходный расчёт не найден — проверим, не является ли sourceEstimateId
  // самим админским расчётом (кейс: editingEstimateId = adminEstimate.id)
  sourceEstimate = await prisma.fenceEstimate.findUnique({
    where: { id: sourceEstimateId },
    include: { fenceType: true },
  });
  if (!sourceEstimate) {
    throw new Error('Source estimate not found');
  }
}
```

Нет, это тот же запрос. Лучше так: если `sourceEstimateId` совпадает с `adminEstimateId` заказа — загрузить админский расчёт как источник:

```typescript
let sourceEstimate = await prisma.fenceEstimate.findUnique({
  where: { id: sourceEstimateId },
  include: { fenceType: true },
});
if (!sourceEstimate) {
  // Попробовать найти админский расчёт заказа с этим sourceEstimateId
  const adminEst = await prisma.fenceEstimate.findFirst({
    where: { id: sourceEstimateId },
    include: { fenceType: true },
  });
  if (adminEst) {
    sourceEstimate = adminEst;
  } else {
    throw new Error('Source estimate not found');
  }
}
```

Опять то же самое. Правильное решение: `findUnique` и так ищет по id. Если запись не найдена — её нет в БД. Значит нужно попробовать поискать по-другому.

**Реальное решение для `createAdminEstimate`:**
Поскольку `createAdminEstimate` вызывается при СОЗДАНИИ нового админского расчёта, если `sourceEstimateId` указывает на несуществующую запись — нужно использовать данные заказа (order.estimate) или данные последнего известного расчёта.

Но на практике, `createAdminEstimate` вызывается когда `existingAdminEstimateId` = `null`, и `estimateId` prop = `estimate?.id || editingEstimateId`. Если `estimate` = `null`, `estimateId` = `editingEstimateId` = что-то. Это «что-то» — не обязательно существующий расчёт.

**Решение:** В `createAdminEstimate`, если source estimate не найден — проверить, является ли `sourceEstimateId` админским расчётом заказа. Если да — использовать его как «источник».

### 4.3. `estimateEditorService.ts` — `recalculateWithParams()`

**Было (строка 61-68):**
```typescript
const sourceEstimate = await prisma.fenceEstimate.findUnique({
  where: { id: estimateId },
  include: { fenceType: true },
});
if (!sourceEstimate) {
  throw new Error('Source estimate not found');
}
```

**Стало:** Если `estimateId` — это ID админского расчёта (у которого `sourceEstimate` = `null`), `findUnique` найдёт саму запись. Проблема в том, что `findUnique` с `include: { fenceType: true }` найдёт запись, даже если она админская. Так что для `recalculateWithParams` проблема возникает только если запись **физически удалена** из БД.

Если запись удалена — это нормально получить 404, т.к. пересчитывать нечего.

## 5. Критерии приёмки

1. **PUT /admin-estimate** при редактировании существующего админского расчёта, чей `sourceEstimate` удалён → **200 OK** вместо 404
2. **POST /admin-estimate** при создании нового админского расчёта, когда `sourceEstimateId` указывает на несуществующую запись, но `estimateId` = ID самого админского расчёта → **201 Created** вместо 404
3. **POST /recalculate-estimate** — если `estimateId` указывает на существующую запись (даже админскую), пересчёт работает корректно
4. Регрессия: стандартный флоу (когда `sourceEstimate` существует) продолжает работать без изменений
