## 1. Контекст и цель

### 1.1 Контекст
В справочнике "Монтажная фурнитура" реализована привязка позиций к номенклатуре других справочников через таблицу `MountingHardwareRelation`. Однако обратная связь отсутствует — из карточки основной номенклатуры невозможно просмотреть связанную фурнитуру.

### 1.2 Цель
Обеспечить возможность просмотра связанных позиций монтажной фурнитуры из карточки основной номенклатуры без дублирования данных в БД.

### 1.3 Пример
- **Лага 40x20** → связанная фурнитура: **Заглушка 40x20**
- При просмотре карточки "Лага 40x20" администратор видит привязанную монтажную фурнитуру

---

## 2. Термины

- **Основная номенклатура** — позиция из справочников: Лаги, Столбы, Профнастил, Евроштакетник, Ворота, Калитки
- **Монтажная фурнитура** — позиция из справочника MountingHardware
- **MountingHardwareRelation** — промежуточная таблица связей (уже существует)

---

## 3. Функциональные требования (FR)

### FR-1. Хранение связей
- Использовать существующую таблицу `MountingHardwareRelation` без изменений структуры БД
- Не дублировать данные в основных справочниках

### FR-2. API для получения связанных позиций
- Создать endpoint для запроса фурнитуры по типу и ID номенклатуры
- Запрос: `referenceType` + `referenceId` → список MountingHardware

### FR-3. Отображение в карточке номенклатуры
- В карточках справочников (Лаги, Столбы, Профнастил, Евроштакетник, Ворота, Калитки) добавить блок "Связанная монтажная фурнитура"
- Блок отображается только если есть связанные позиции
- Блок виден только для роли ADMIN

### FR-4. Управление связями
- Связи создаются/удаляются только из карточки монтажной фурнитуры
- Из карточки основной номенклатуры — только просмотр

### FR-5. Контроль доступа
- Цены фурнитуры (purchasePrice, retailPrice) видны только ADMIN
- Для других ролей блок "Связанная фурнитура" скрыт полностью

---

## 4. Нефункциональные требования (NFR)

### NFR-1. Производительность
- Запрос связанных позиций < 300 мс
- Использовать индексы: `referenceType`, `referenceId`

### NFR-2. Надёжность
- Обработка случая отсутствия связей (пустой список)
- Обработка случая удаления фурнитуры (связь удаляется каскадно)

## 5. Техническая архитектура

### 5.1 Изменения БД
**Не требуются** — используется существующая таблица `MountingHardwareRelation`

### 5.2 API

#### GET /api/admin/mounting-hardware/by-reference

**Описание:** Получить связанную фурнитуру по номенклатуре

**Доступ:** ADMIN только

**Query Parameters:**
| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| referenceType | string | Да | LAG, POST, PROFNASTIL, PICKET, GATE, WICKET |
| referenceId | string | Да | ID номенклатуры |

**Response 200:**
```json
{
  "items": [
    {
      "id": "mh-1",
      "name": "Заглушка 40x20",
      "description": "Заглушка торцевая",
      "purchasePrice": 8.50,
      "retailPrice": 15.00,
      "active": true
    }
  ],
  "total": 1
}
```

**Response 200 (пусто):**
```json
{
  "items": [],
  "total": 0
}
```

## 8. План тестирования (Acceptance Criteria)

- **AC1:** API `/by-reference?referenceType=LAG&referenceId=xxx` возвращает корректный список
- **AC2:** API возвращает пустой список при отсутствии связей
- **AC3:** Блок "Связанная фурнитура" отображается в карточке Лаги при наличии связей
- **AC4:** Блок скрыт для ролей MANAGER / CONTENT_MANAGER
- **AC5:** Клик по позиции открывает карточку фурнитуры
- **AC6:** При удалении фурнитуры связь исчезает из карточки номенклатуры
