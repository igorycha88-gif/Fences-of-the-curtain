# ЧТЗ: Фикс очистки числовых полей в калькуляторе навесов (мобильная версия)

## Постановка проблемы
В клиентском калькуляторе навесов (`/calculator/canopy`) в полях **Высота**, **Длина**, **Ширина** пользователь не может полностью очистить поле — при удалении последней цифры в поле автоматически подставляется `0`, который невозможно убрать. Ожидаемое поведение: пользователь может полностью очистить поле и ввести новое значение с нуля.

## Причина
В `src/app/(public)/calculator/canopy/page.tsx` поля реализованы как контролируемые `<input type="number">` с привязкой напрямую к числовому полю state:

```tsx
value={formData.height}
onChange={(e) => setFormData({ ...formData, height: Number(e.target.value) })}
```

При очистке поля `e.target.value === ''`, а `Number('') === 0`, поэтому в state мгновенно записывается `0` и поле отображает `0`. Это мешает вводу.

- **Исполнитель:** Разработчик → Тестировщик → DevOps

## Файлы для изменения
- `src/app/(public)/calculator/canopy/page.tsx` — refactor полей Height/Length/Width

## Решение
Разделить «отображаемое значение» (строка) и «значение для расчёта» (число):

1. Ввести локальное строковое состояние для отображаемых значений трёх полей: `height`, `length`, `width`.
2. В `onChange` сохранять сырое строковое значение в строковое состояние, а в `formData` класть число (если строка пустая — `0`, если NaN — игнорировать).
3. В `value` инпута подавать строковое значение → это позволит полностью очистить поле.
4. Существующая логика расчёта (`calculate`) и отображения параметров не меняется — она работает с числами в `formData`.

## Критерии приёмки
1. ✅ Пользователь может полностью очистить любое из полей Высота/Длина/Ширина (поле становится пустым).
2. ✅ При пустом поле и нажатии «Рассчитать» показывается ошибка «Длина и ширина должны быть положительными числами» (существующая валидация).
3. ✅ После очистки пользователь может ввести новое значение и корректно произвести расчёт.
4. ✅ Поведение декриминальное: числовая валидация и `min`/`max`/`step` сохраняются.
5. ✅ Поведение одинаково на десктопе и мобильных.
6. ✅ Существующая функциональность калькулятора не сломана.
7. ✅ Добавлены автотесты (Jest + React Testing Library) на:
   - happy path (ввод значения и расчёт)
   - edge case: полная очистка поля → поле остаётся пустым, FormData получает 0
   - edge case: ввод дробного значения
   - error case: расчёт при пустом поле → показ ошибки
8. ✅ Прохождение `npm test && npm run lint && npx tsc --noEmit`.
