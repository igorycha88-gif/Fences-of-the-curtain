## 1. Цели и задачи

### 1.1 Бизнес-цель
Устранить утечку персональных данных (PII) и чувствительной информации через логи приложения для соответствия требованиям информационной безопасности и предотвращения компрометации данных пользователей.

### 1.2 Пользовательская ценность
- Защита конфиденциальности пользователей (email, данные сессий)
- Соответствие стандартам безопасности при деплое в production
- Снижение рисков при утечке логов

### 1.3 Метрики успеха
- 0 вхождений email в логах (проверка grep)
- 0 вхождений полных body запросов в логах
- Prisma query logging отключен в production

---

## 2. Функциональные требования

### 2.1 User Stories с Acceptance Criteria

#### US-001: Безопасное логирование аутентификации
**Как** администратор безопасности  
**Я хочу** чтобы логи аутентификации не содержали email и результаты проверки пароля  
**Чтобы** предотвратить утечку учётных данных

**Acceptance Criteria:**
```gherkin
GIVEN пользователь пытается войти в систему
WHEN происходит процесс аутентификации
THEN в логах не должно быть email пользователя
AND в логах не должно быть результата сравнения пароля
AND логи должны содержать только статус операции (success/fail)
```

#### US-002: Безопасное логирование admin API
**Как** администратор безопасности  
**Я хочу** чтобы admin API не логировал body запросов  
**Чтобы** предотвратить утечку бизнес-данных

**Acceptance Criteria:**
```gherkin
GIVEN администратор отправляет PUT/POST запрос
WHEN запрос обрабатывается сервером
THEN body запроса не должен попадать в логи
AND логи должны содержать только тип операции и ID сущности
```

#### US-003: Условное логирование Prisma
**Как** DevOps инженер  
**Я хочу** чтобы SQL запросы логировались только в development  
**Чтобы** в production не попадали SQL запросы с чувствительными данными

**Acceptance Criteria:**
```gherkin
GIVEN приложение запущено в production режиме
WHEN выполняются запросы к БД
THEN SQL запросы не должны логироваться
AND errors и warnings должны логироваться в любом режиме
```

## 3. Нефункциональные требования

### 3.1 Безопасность
- **NFR-SEC-001**: Все email должны маскироваться или исключаться из логов
- **NFR-SEC-002**: Body запросов не должен логироваться целиком
- **NFR-SEC-003**: Данные сессий (JSON.stringify(session.user)) не должны логироваться
- **NFR-SEC-004**: Результаты сравнения паролей не должны логироваться

### 3.2 Производительность
- **NFR-PERF-001**: Отключение Prisma query logging в production не должно влиять на производительность
- **NFR-PERF-002**: Уменьшение объёма логов положительно скажется на I/O

### 3.3 Сопровождаемость
- **NFR-MNT-001**: Логи должны оставаться информативными для debugging
- **NFR-MNT-002**: Формат логов должен быть структурированным: `[MODULE] Operation: status`

### 9.3 Пример маскирования email (если необходимо логировать)

```typescript
function maskEmail(email: string): string {
  const [local, domain] = email.split('@');
  const masked = local.length > 2 
    ? local[0] + '***' + local[local.length - 1] 
    : '***';
  return `${masked}@${domain}`;
}

// Использование:
console.log('[AUTH] User:', maskEmail(user.email));
// Вывод: [AUTH] User: i***r@example.com
```

### 9.4 Пример скрипта проверки PII (scripts/check-pii-logs.sh)

```bash
#!/bin/bash

# Скрипт проверки отсутствия PII в логах
# Exit code: 0 = OK, 1 = найдены нарушения

set -e

ERRORS=0

echo "=== Проверка PII в логах ==="

# 1. Проверка email в auth.ts
echo "1. Проверка email в src/lib/auth.ts..."
if grep -n "console.log.*credentials\.email\|console.log.*user\.email\|console.log.*session\.user\.email" src/lib/auth.ts 2>/dev/null; then
    echo "   ERROR: Найден email в логах auth.ts"
    ERRORS=$((ERRORS + 1))
else
    echo "   OK: Email не найден в логах"
fi

# 2. Проверка body в admin routes
echo "2. Проверка body в admin routes..."
BODY_VIOLATIONS=$(grep -rn "console.log.*body" src/app/api/admin/ 2>/dev/null || true)
if [ -n "$BODY_VIOLATIONS" ]; then
    echo "   ERROR: Найден body в логах:"
    echo "$BODY_VIOLATIONS"
    ERRORS=$((ERRORS + 1))
else
    echo "   OK: Body не найден в логах"
fi

# 3. Проверка JSON.stringify с session/user
echo "3. Проверка JSON.stringify(session/user)..."
JSON_VIOLATIONS=$(grep -rn "console.log.*JSON.stringify.*session\|console.log.*JSON.stringify.*user" src/ 2>/dev/null | grep -v node_modules || true)
if [ -n "$JSON_VIOLATIONS" ]; then
    echo "   ERROR: Найден JSON.stringify с session/user:"
    echo "$JSON_VIOLATIONS"
    ERRORS=$((ERRORS + 1))
else
    echo "   OK: JSON.stringify с session/user не найден"
fi

# 4. Проверка условного логирования Prisma
echo "4. Проверка условного логирования Prisma..."
if ! grep -q "NODE_ENV.*development" src/lib/prisma.ts 2>/dev/null; then
    echo "   ERROR: Prisma query logging не обёрнут в условие NODE_ENV"
    ERRORS=$((ERRORS + 1))
else
    echo "   OK: Prisma query logging условный"
fi

# Результат
echo ""
echo "=== Результат ==="
if [ $ERRORS -gt 0 ]; then
    echo "FAILED: Найдено нарушений: $ERRORS"
    exit 1
else
    echo "PASSED: PII в логах не найден"
    exit 0
fi
```
