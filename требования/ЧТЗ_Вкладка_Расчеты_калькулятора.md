## 1. Цели и задачи

### 1.1 Бизнес-цель
Предоставить менеджерам и администраторам инструмент для анализа расчетов, выполняемых пользователями в калькуляторе заборов. Позволит отслеживать интерес клиентов, анализировать популярные конфигурации и конверсию в заявки.

### 1.2 Пользовательская ценность
Менеджеры смогут видеть, какие варианты заборов пользователи рассчитывают чаще всего, идентифицировать потенциальных клиентов и связываться с ними.

### 1.3 Ключевые метрики успеха
- Время доступа к истории расчетов пользователя: < 5 сек
- Покрытие всех расчетов из БД: 100%

## 2. Исходные данные

### 2.1 Существующая модель БД (FenceEstimate)

| Поле | Тип | Описание |
|------|-----|----------|
| id | String | Уникальный ID расчета |
| fenceTypeId | String | Тип забора |
| length | Float | Длина забора (м) |
| height | Float | Высота забора (м) |
| lagRows | Int | Количество рядов лаг (2 или 3) |
| coating | String | Тип покрытия |
| hasGate | Boolean | Наличие ворот |
| gateType | String? | Тип ворот |
| gateLength | Int? | Длина ворот (мм) |
| gateNomenclatureName | String? | Название ворот |
| hasWicket | Boolean | Наличие калитки |
| wicketWidth | Int? | Ширина калитки (мм) |
| wicketNomenclatureName | String? | Название калитки |
| postsTotal | Float | Стоимость столбов |
| lagsTotal | Float | Стоимость лаг |
| profnastilTotal | Float | Стоимость профнастила |
| mountingHardwareTotal | Float | Стоимость монтажной фурнитуры |
| gateTotal | Float | Стоимость ворот |
| wicketTotal | Float | Стоимость калитки |
| gateInstallationTotal | Float | Стоимость установки ворот |
| wicketInstallationTotal | Float | Стоимость установки калитки |
| installationTotal | Float | Общая стоимость работ |
| materialsTotal | Float | Общая стоимость материалов |
| grandTotal | Float | Итоговая стоимость |
| items | Json | Детализация позиций |
| userId | String? | ID пользователя (если авторизован) |
| sessionId | String? | ID сессии |
| userAgent | String? | User-Agent браузера |
| ipAddress | String? | IP-адрес |
| createdAt | DateTime | Дата создания |

### 2.2 Связанные таблицы
- **FenceType** — название типа забора
- **User** — email, name, phone пользователя (если авторизован)

## 3. Функциональные требования

### 3.1 User Stories

#### US-1: Просмотр списка расчетов
**Как** менеджер,  
**Я хочу** видеть список всех расчетов калькулятора,  
**Чтобы** анализировать интерес пользователей к различным конфигурациям заборов.

**Acceptance Criteria**:
```
Given я нахожусь в админ-панели
When открываю раздел "Расчеты"
Then вижу таблицу с расчетами
And колонки: ID, Дата, Тип забора, Длина×Высота, Стоимость, Устройство, Город, Пользователь
And пагинация по 20 записей
And сортировка по дате (новые сверху)
```

#### US-2: Фильтрация расчетов
**Как** менеджер,  
**Я хочу** фильтровать расчеты по различным параметрам,  
**Чтобы** быстро находить нужные записи.

**Acceptance Criteria**:
```
Given я нахожусь на странице "Расчеты"
When применяю фильтры
Then список обновляется согласно фильтрам

Фильтры:
- Период: дата с...по...
- Тип забора: выпадающий список
- Стоимость: от...до...
- Наличие ворот: да/нет/все
- Наличие калитки: да/нет/все
- Тип устройства: десктоп/мобильный/все
And кнопка "Сбросить фильтры"
```

#### US-3: Детальный просмотр расчета
**Как** менеджер,  
**Я хочу** видеть все параметры конкретного расчета,  
**Чтобы** понимать потребности клиента.

**Acceptance Criteria**:
```
Given я нахожусь в списке расчетов
When кликаю на строку расчета
Then открывается модальное окно с деталями

Детали включают:
- Основные параметры: тип забора, длина, высота, покрытие, лаги
- Ворота: тип, длина, стоимость (если есть)
- Калитка: ширина, стоимость (если есть)
- Детализация стоимости по категориям
- Таблица позиций (items)
- Метаданные: дата, IP, User-Agent, город
- Контактные данные пользователя (если авторизован)
```

#### US-4: Экспорт в Excel
**Как** менеджер,  
**Я хочу** выгрузить расчеты в Excel,  
**Чтобы** работать с данными оффлайн или передать руководству.

**Acceptance Criteria**:
```
Given я нахожусь на странице "Расчеты"
When нажимаю кнопку "Экспорт в Excel"
Then скачивается файл .xlsx
And файл содержит отфильтрованные расчеты
And заголовки на русском языке
```

#### US-5: Определение города по IP
**Как** система,  
**Я хочу** определять город пользователя по IP,  
**Чтобы** менеджер видел географию интересов.

**Acceptance Criteria**:
```
Given пользователь выполнил расчет
When сохраняется FenceEstimate
Then определяется город по ipAddress
And город сохраняется в БД
And отображается в списке расчетов
```

#### US-6: Контактные данные пользователя
**Как** менеджер,  
**Я хочу** видеть контактные данные авторизованного пользователя,  
**Чтобы** связаться с потенциальным клиентом.

**Acceptance Criteria**:
```
Given расчет выполнен авторизованным пользователем
When я просматриваю детали расчета
Then вижу email и телефон пользователя
And если пользователь не авторизован — вижу "Гость"
```

## 4. Нефункциональные требования

### 4.1 Производительность
- Время загрузки списка расчетов: < 500ms
- Время открытия детали расчета: < 200ms
- Экспорт до 1000 записей: < 5 сек

### 4.2 Безопасность
- Доступ только для ролей: ADMIN, MANAGER
- Логирование действий (просмотр, экспорт)

### 4.3 Масштабируемость
- Пагинация обязательна (не более 100 записей на страницу)
- Индексы на полях: createdAt, fenceTypeId, userId

## 10. Риски и зависимости

### 10.1 Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Лимит API геолокации | Средняя | Низкое | Кэширование + fallback на null |
| Большой объем данных | Низкая | Среднее | Обязательная пагинация, индексы |
| Нет email у пользователя | Высокая | Низкое | Показывать "Гость" |

### 10.2 Зависимости
- Наличие Redis для кэширования геолокации
- Библиотека xlsx для экспорта в Excel
