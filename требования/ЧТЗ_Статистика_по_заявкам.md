## 1. Цели и задачи

### 1.1 Бизнес-цель
Предоставить руководству и менеджерам комплексную аналитику по работе с заявками для принятия data-driven решений. Визуализировать ключевые метрики эффективности работы отдела продаж и качества обслуживания клиентов.

### 1.2 Пользовательская ценность
- **Руководитель**: Видит общую картину работы отдела, может принимать решения на основе данных
- **Менеджер**: Отслеживает личную эффективность, понимает зоны роста
- **Система**: Автоматически собирает и агрегирует данные для отчетности

### 1.3 Метрики успеха
- Время загрузки дашборда статистики: < 1 сек
- Использование статистики для принятия решений: > 80% руководителей
- Точность прогнозов на основе данных: > 75%

## 2. Анализ лучших практик отображения статистики

### 2.1 Принципы UX/UI для статистических дашбордов

#### Иерархия информации
```
┌─────────────────────────────────────────────────────────────────┐
│ УРОВЕНЬ 1: Ключевые метрики (KPI Cards)                         │
│ - Самые важные цифры на верху экрана                            │
│ - Цветовая индикация: зеленый (хорошо), желтый (внимание),      │
│   красный (проблема)                                             │
│ - Тренд относительно прошлого периода                            │
├─────────────────────────────────────────────────────────────────┤
│ УРОВЕНЬ 2: Графики и диаграммы                                   │
│ - Воронка продаж                                                 │
│ - Динамика по периодам                                           │
│ - Распределение по категориям                                    │
├─────────────────────────────────────────────────────────────────┤
│ УРОВЕНЬ 3: Детальные таблицы                                     │
│ - Списки с пагинацией                                            │
│ - Детальная информация для глубокого анализа                     │
└─────────────────────────────────────────────────────────────────┘
```

#### Лучшие практики (Industry Standards)

**1. Принцип 5-секундного теста**
- Пользователь должен понять главную информацию за 5 секунд
- Ключевые метрики: жирный шрифт, большой размер
- Поддерживающие метрики: меньший шрифт, серый цвет

**2. Визуальное кодирование**
```typescript
// Цветовая схема для метрик
const METRIC_COLORS = {
  positive: 'text-green-600',      // Рост показателя
  neutral: 'text-gray-600',        // Без изменений
  negative: 'text-red-600',        // Падение показателя
  warning: 'text-yellow-600',      // Требует внимания
};
```

**3. Контекст и сравнение**
- Всегда показывать сравнение с предыдущим периодом
- Визуальный тренд: ↗ +15% vs прошлый месяц
- Средние значения по отделу/компании

**4. Фильтрация и drill-down**
- Глобальные фильтры вверху экрана
- Возможность углубиться в конкретную метрику
- Export детальных данных

**5. Responsive Design**
- Desktop: 4 колонки KPI + 2 колонки графиков
- Tablet: 2 колонки KPI + 1 колонка графиков
- Mobile: 1 колонка KPI + вертикальные графики

### 2.2 Типы визуализаций

| Тип данных | Рекомендуемая визуализация | Пример использования |
|------------|---------------------------|---------------------|
| Динамика во времени | Line chart, Area chart | Количество заявок по дням |
| Распределение | Pie chart, Donut chart | Распределение по статусам |
| Сравнение | Bar chart, Column chart | Заявки по типам заборов |
| Воронка | Funnel chart | Воронка конверсии заявок |
| KPI | Card с числом и трендом | Общая выручка |
| Тренд | Sparkline | Тренд конверсии |
| Heatmap | Heatmap table | Активность по дням недели |

### 2.3 Ключевые метрики для CRM систем

**Метрики конверсии:**
- Lead → Order conversion rate
- Order completion rate
- Average time to close

**Метрики качества:**
- Cancellation rate by reason
- Client satisfaction rate
- Return customer rate

**Метрики эффективности:**
- Orders per manager
- Average deal size
- Revenue per manager

**Метрики процесса:**
- Time in each status
- Bottleneck identification
- Queue length

## 3. Функциональные требования

### 3.1 User Stories

#### US-1: Просмотр сводки KPI
**Как** руководитель,  
**Я хочу** видеть ключевые метрики работы отдела на одной странице,  
**Чтобы** быстро оценить текущую ситуацию.

**Acceptance Criteria**:
```
Given я нахожусь в админ-панели
When открываю вкладку "Статистика" под "Расчеты"
Then вижу 6 карточек KPI:
  - Всего заявок (с трендом vs прошлый период)
  - В работе (количество + среднее время в работе)
  - Завершено (количество + общая сумма)
  - Конверсия (% + тренд)
  - Средний чек (сумма + тренд)
  - Отменено (% + топ причина)

And каждая карточка содержит:
  - Иконку метрики
  - Название метрики
  - Значение (крупно)
  - Тренд (↗ +15% vs прошлый месяц)
  - Цветовую индикацию (зеленый/желтый/красный)
```

#### US-2: Анализ воронки продаж
**Как** руководитель,  
**Я хочу** видеть воронку конверсии по статусам,  
**Чтобы** идентифицировать проблемные этапы.

**Acceptance Criteria**:
```
Given я нахожусь на вкладке "Статистика"
When прокручиваю вниз
Then вижу воронку конверсии:
  NEW: 100 заявок (100%)
    ↓ 80% конверсия
  ESTIMATE_APPROVAL: 80 заявок (80%)
    ↓ 70% конверсия
  MEASUREMENT: 56 заявок (56%)
    ↓ 85% конверсия
  PRODUCTION: 48 заявок (48%)
    ↓ 90% конверсия
  INSTALLATION: 43 заявки (43%)
    ↓ 95% конверсия
  COMPLETED: 41 заявка (41%)
  
And на каждом этапе показан % конверсии
And этапы с конверсией < 70% выделены желтым
And этапы с конверсией < 50% выделены красным
```

#### US-3: Динамика заявок по периодам
**Как** менеджер,  
**Я хочу** видеть график количества заявок по дням/неделям/месяцам,  
**Чтобы** анализировать сезонность и тренды.

**Acceptance Criteria**:
```
Given я нахожусь на вкладке "Статистика"
When вижу раздел "Динамика заявок"
Then вижу line chart с:
  - Ось X: даты
  - Ось Y: количество заявок
  - Линия "Новые заявки" (синяя)
  - Линия "Завершенные заявки" (зеленая)
  - Линия "Отмененные заявки" (красная)

When выбираю период в фильтре
Then график обновляется:
  - День: последние 30 дней
  - Неделя: последние 12 недель
  - Месяц: последние 12 месяцев

When навожу курсор на точку графика
Then вижу tooltip с датой и значениями
```

#### US-4: Анализ причин отмен
**Как** руководитель,  
**Я хочу** видеть распределение причин отмен заявок,  
**Чтобы** понимать основные проблемы и улучшать сервис.

**Acceptance Criteria**:
```
Given я нахожусь на вкладке "Статистика"
When вижу раздел "Причины отмен"
Then вижу donut chart с распределением причин:
  - Цена слишком высокая: 35%
  - Выбрали другого подрядчика: 25%
  - Передумал: 20%
  - Не выходит на связь: 15%
  - Другое: 5%

And легенда с количеством заявок по каждой причине
And возможность кликнуть на сегмент для детализации
When кликаю на сегмент
Then вижу модальное окно со списком отмененных заявок этой категории
```

#### US-5: Статистика по менеджерам
**Как** руководитель,  
**Я хочу** сравнивать эффективность менеджеров,  
**Чтобы** мотивировать лучших и помогать отстающим.

**Acceptance Criteria**:
```
Given я нахожусь на вкладке "Статистика"
When вижу раздел "Эффективность менеджеров"
Then вижу таблицу:
  | Менеджер | Заявок | В работе | Завершено | Конверсия | Ср. чек | Выручка |
  |----------|--------|----------|-----------|-----------|---------|---------|
  | Иван П.  | 45     | 12       | 28        | 62%       | 125 000 | 3.5М    |
  | Мария С. | 38     | 8        | 25        | 66%       | 98 000  | 2.45М   |
  | ...      | ...    | ...      | ...       | ...       | ...     | ...     |

And сортировка по выручке (по умолчанию)
And возможность сортировать по любой колонке
And возможность экспорта в Excel
```

#### US-6: Фильтрация статистики
**Как** пользователь,  
**Я хочу** фильтровать статистику по периодам и параметрам,  
**Чтобы** анализировать конкретные срезы данных.

**Acceptance Criteria**:
```
Given я нахожусь на вкладке "Статистика"
When использую фильтры в верхней панели
Then могу выбрать:
  - Период: сегодня / неделя / месяц / квартал / год / кастомный диапазон
  - Тип забора: все / профнастил / евроштакетник / ...
  - Менеджер: все / конкретный менеджер
  - Статус: все / конкретный статус

When применяю фильтры
Then все графики и метрики обновляются
And URL обновляется с параметрами фильтров (для шаринга)
When делюсь ссылкой с коллегой
Then коллега видит ту же фильтрованную статистику
```

#### US-7: Экспорт отчетов
**Как** руководитель,  
**Я хочу** выгружать статистику в Excel/PDF,  
**Чтобы** использовать данные в презентациях и отчетах.

**Acceptance Criteria**:
```
Given я нахожусь на вкладке "Статистика"
When нажимаю кнопку "Экспорт"
Then вижу выпадающее меню:
  - Скачать Excel
  - Скачать PDF
  - Отправить на email

When выбираю "Скачать Excel"
Then скачивается файл со статистикой:
  - Лист 1: Сводка KPI
  - Лист 2: Динамика заявок
  - Лист 3: Причины отмен
  - Лист 4: Эффективность менеджеров

When выбираю "Скачать PDF"
Then скачивается PDF с визуализациями графиков
And данные отфильтрованы согласно текущим фильтрам
```

#### US-8: Среднее время по статусам
**Как** менеджер,  
**Я хочу** видеть среднее время нахождения заявки в каждом статусе,  
**Чтобы** оптимизировать процесс работы.

**Acceptance Criteria**:
```
Given я нахожусь на вкладке "Статистика"
When вижу раздел "Время по статусам"
Then вижу bar chart:
  - NEW: среднее 2 дня
  - ESTIMATE_APPROVAL: среднее 5 дней
  - MEASUREMENT: среднее 3 дня
  - PRODUCTION: среднее 7 дней
  - INSTALLATION: среднее 4 дня
  - Итого: среднее 21 день от NEW до COMPLETED

And статусы с временем выше нормы выделены красным
And норма времени настраивается в настройках системы
```

## 4. Нефункциональные требования

### 4.1 Производительность
- Время загрузки дашборда: < 1 сек
- Время обновления при смене фильтров: < 500ms
- Поддержка до 100 000 заявок в БД
- Кэширование агрегированных данных на 5 минут

### 4.2 Безопасность
- Доступ только для ролей: ADMIN, MANAGER
- Менеджеры видят только свою статистику (опционально)
- ADMIN видит статистику по всем менеджерам
- Логирование экспорта данных

### 4.3 Масштабируемость
- Materialized Views для агрегированных данных
- Background jobs для пересчета статистики
- Индексы на полях: status, createdAt, userId, serviceType

## 8. Риски и зависимости

### 8.1 Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Медленная агрегация больших данных | Средняя | Высокое | Materialized Views, кэширование |
| Нет данных для сравнения | Высокая | Среднее | Показывать "нет данных" вместо ошибки |
| Сложность расчета времени по статусам | Средняя | Среднее | Парсинг statusHistory JSON |

### 8.2 Зависимости

- Библиотека для графиков: Recharts или Chart.js
- Библиотека для Excel: xlsx
- Библиотека для PDF: puppeteer или jspdf
- Redis для кэширования (опционально)
