# ЧТЗ: Починка Графаны локально, русификация метрик, новые бизнес-метрики и мониторинг сервисов

## Контекст

Графана не работает локально из-за конфликта портов (порт 3000 занят приложением fences-app-dev). Дашборды содержат дублирующиеся события на английском. Нет мониторинга жизненного состояния отдельных сервисов.

## Проблемы

### П-1: Графана не запускается локально
- **Корневая причина:** В `docker-compose.monitoring.standalone.yml` Grafana маппится на порт 3000, который уже занят контейнером `fences-app-dev`
- **Доп. проблема:** Prometheus в `prometheus.yml` скрейпит nextjs-app на порту 3001, а приложение работает на 3000
- **Доп. проблема:** Redis-exporter подключается к `localhost:6379` без пароля, но Redis требует аутентификацию

### П-2: Дубли событий в аналитике
- `EVENT_NAMES` в `src/types/analytics.ts` содержит 14 событий, но в дашборде `user-analytics.json` отображаются все комбинации `event_name × page`, что создаёт визуальные дубли
- Легенды на английском

### П-3: Нет мониторинга состояния сервисов
- Нет дашборда, показывающего alive/dead статус каждого сервиса (app, db, redis, prometheus, grafana, exporters)

## Задачи

### TASK-MON-001: Починка docker-compose.monitoring.standalone.yml (INF)
- Изменить порт Grafana с 3000 на 3001 (хост) → 3000 (контейнер)
- Исправить переменные окружения: `GF_SERVER_HTTP_PORT=3000` (оставить как есть, внутри контейнера)
- Исправить healthcheck Grafana на порт внутри контейнера (3000)
- Исправить Redis exporter: добавить пароль из `REDIS_PASSWORD` env var
- Исправить Prometheus datasource URL в `grafana/provisioning/datasources/prometheus.yml` — для standalone mode Prometheus доступен на `host.docker.internal:9090` или через network
- Создать отдельную Docker-сеть для мониторинга, либо использовать `host.docker.internal` для доступа к хост-портам
- Настроить `extra_hosts: ["host.docker.internal:host-gateway"]` для контейнеров, которым нужен доступ к хосту

### TASK-MON-002: Исправить prometheus.yml (INF)
- Изменить порт nextjs-app с 3001 на 3000
- Для локального standalone режима: использовать `host.docker.internal:3000` вместо `127.0.0.1:3001`
- Для прод режима: оставить `127.0.0.1:3000` (через host network)
- Создать `prometheus.dev.yml` для локальной разработки с правильными адресами

### TASK-MON-003: Переделать дашборд бизнес-метрик (FRT)
- Переработать `user-analytics.json`:
  - Убрать дубли: сгруппировать события по `event_name` без дублирования по страницам
  - Все названия событий на русском языке через value mappings
  - Актуальные события из `EVENT_NAMES`:
    - `page_view` → "Просмотр страницы"
    - `calculator_open` → "Открытие калькулятора"
    - `calculator_fence_type_select` → "Выбор типа забора"
    - `calculator_configure` → "Настройка параметров"
    - `calculator_calculate` → "Расчёт стоимости"
    - `calculator_export` → "Экспорт расчёта"
    - `portfolio_view` → "Просмотр портфолио"
    - `portfolio_item_click` → "Клик по работе"
    - `contacts_view` → "Просмотр контактов"
    - `contact_form_submit` → "Отправка заявки"
    - `services_view` → "Просмотр услуг"
    - `phone_click` → "Клик по телефону"
    - `session_end` → "Завершение сессии"
  - Оставить только релевантные графики, убрать невалидные (session_duration — нет данных)

### TASK-MON-004: Добавить новые бизнес-метрики (BCK)
- Добавить метрики в `src/lib/prometheus.ts`:
  - `estimate_requests_total` — "Количество запросов сметы" (label: status)
  - `phone_clicks_total` — "Клики по телефону" (label: page)
  - `form_submissions_total` — "Отправки форм" (label: form_type, status)
  - `calculator_completions_total` — "Завершённые расчёты калькулятора" (label: fence_type)
  - `top_fence_types_total` — "Популярные типы заборов" (label: fence_type)
- Обновить `getMetricsString()` для сбора этих данных из Redis
- Обновить дашборд с новыми панелями

### TASK-MON-005: Создать дашборд "Состояние сервисов" (FRT)
- Новый дашборд `service-health.json`:
  - Статус-панель для каждого сервиса (app, PostgreSQL, Redis, Prometheus, Grafana, Node Exporter, Postgres Exporter, Redis Exporter)
  - `up` метрика из Prometheus — `up == 1` (зелёный), `up == 0` (красный)
  - Uptime каждого сервиса
  - Время ответа healthcheck

### TASK-MON-006: Русификация всех дашбордов (FRT)
- `system-overview.json`: перевести заголовки панелей на русский
- `redis-metrics.json`: перевести заголовки на русский
- `postgres-metrics.json`: перевести заголовки на русский
- Все новые дашборды — изначально на русском

- AC-4: Все названия событий отображаются на русском языке

- AC-7: Все системные дашборды переведены на русский
