## 2. Цели и задачи

### 2.1 Бизнес-цель
Обеспечить отображение названия номенклатуры монтажной фурнитуры в результатах расчёта калькулятора для прозрачности сметы.

### 2.2 Пользовательская ценность
- Пользователь видит, какая именно фурнитура попала в расчёт
- Прозрачность сметы — понятно, за что платит клиент
- Упрощение верификации расчёта менеджером

### 2.3 Ключевые метрики успеха
- Название фурнитуры отображается в результатах расчёта
- Название соответствует записи из справочника "Монтажная фурнитура"
- Форматирование единообразно с другими материалами

---

## 3. Требования к продукту

### 3.1 Функциональные требования

#### 3.1.1 Отображение названия фурнитуры

**User Story 1: Просмотр названия фурнитуры в смете**

*Как пользователь калькулятора, я хочу видеть название каждой позиции монтажной фурнитуры, попавшей в расчёт.*

**Acceptance Criteria:**
- [ ] В результатах расчёта каждая позиция монтажной фурнитуры отображается с полем `name` из справочника MountingHardware
- [ ] Название берётся из поля `MountingHardware.name`
- [ ] Название отображается в том же формате, что и другие материалы (Столбы, Лаги, Профнастил)
- [ ] Если фурнитура не найдена — отображается дефолтное значение "Монтажная фурнитура"

---

#### 3.1.2 Структура ответа API

**User Story 2: Получение названия фурнитуры через API**

*Как калькулятор, я хочу получать название фурнитуры вместе с расчётом.*

**Acceptance Criteria:**
- [ ] API `/api/estimate` возвращает для каждой позиции монтажной фурнитуры поле `name`
- [ ] Структура ответа включает: `name`, `quantity`, `unit`, `price`, `total`
- [ ] Поле `name` соответствует `MountingHardware.name`

---

### 3.2 Нефункциональные требования

#### 3.2.1 Производительность
- Получение названия не должно увеличивать время расчёта более чем на 50мс

#### 3.2.2 Надёжность
- Обработка случая, когда фурнитура была удалена из справочника
- Fallback на дефолтное значение при ошибке
