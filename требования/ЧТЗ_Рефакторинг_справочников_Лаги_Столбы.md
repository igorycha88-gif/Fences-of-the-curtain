## 2. Цели и задачи

### 2.1 Бизнес-цель
Реализовать систему управления сроками действия номенклатуры с автоматической деактивацией и возможностью создавать номенклатуры с одинаковыми параметрами для разных временных периодов и цен.

### 2.2 Пользовательская ценность
Администраторы получают возможность:
- Управлять периодами действия номенклатуры (дата начала и окончания)
- Создавать номенклатуры с одинаковыми параметрами для разных периодов и цен
- Автоматически деактивировать номенклатуры по истечении срока
- Видеть уведомления о пересечении периодов действия одинаковых номенклатур

### 2.3 Ключевые метрики успеха
- Автоматическая деактивация работает корректно (cron в 01:00)
- Нельзя создать номенклатуру с одинаковыми параметрами, ценой и пересекающимся периодом
- Дата начала действия: если не указана = момент создания
- Поля sortOrder полностью удалены из БД
- Фильтр "Истек срок" работает корректно

#### 3.1.5 Проверка пересечения периодов для одинаковых номенклатур

**User Story 5: Добавление номенклатуры с одинаковыми параметрами**
*Как администратор, я хочу создать номенклатуру с теми же параметрами (сечение, толщина, длина), но с другой ценой и для другого периода.*

**Требования:**

| ID | Требование | Обоснование |
|----|------------|-------------|
| REQ-5.1 | Проверять существующие номенклатуры с такими же параметрами | Контроль |
| REQ-5.2 | Параметры для Лаги: width, height, metalThickness, length | Идентификация |
| REQ-5.3 | Параметры для Столбов: sectionWidth, sectionHeight, wallThickness | Идентификация |
| REQ-5.4 | Если найдены дубликаты параметров → показать уведомление | Предупреждение |
| REQ-5.5 | Проверить: Розничная цена должна отличаться | Условие |
| REQ-5.6 | Проверить: периоды не должны пересекаться | Условие |
| REQ-5.7 | Если у существующей номенклатуры нет expirationDate → установить | Автоматизация |
| REQ-5.8 | Новая номенклатура начнет действовать после окончания старой | Последовательность |

**Логика пересечения периодов:**
```
Периоды пересекаются, когда:
NOT (newValidFrom >= oldExpirationDate OR newExpirationDate <= oldValidFrom)

То есть:
- Новая номенклатура не должна начинаться до окончания старой
- Новая номенклатура не должна заканчиваться после начала старой
```

**Сценарий добавления с дубликатом параметров:**

1. Пользователь создает номенклатуру с существующими параметрами
2. Система находит дубликаты и показывает уведомление:
   ```
   ⚠️ Номенклатура с такими параметрами уже существует:
   
   Профиль 40x20x2.0 (длина 2.5м)
   • Розничная цена: 150 ₽
   • Период: с момента добавления - бессрочно
   • Статус: Активна
   
   Для добавления новой номенклатуры:
   1. Розничная цена должна отличаться
   2. Период действия не должен пересекаться
   
   [Автоматически установить срок действия для существующей] 
   [Отмена]
   ```
3. Если пользователь подтверждает:
   - У существующей установить expirationDate = validFrom новой - 1 день
   - Создать новую номенклатуру

**Acceptance Criteria:**
- [ ] Проверка дубликатов параметров работает
- [ ] Уведомление показывает список существующих номенклатур
- [ ] Проверка на отличие розничной цены
- [ ] Проверка на пересечение периодов
- [ ] Автоматическая установка expirationDate для существующей
- [ ] Новая номенклатура создается после подтверждения

### 4.2 Cron Job для деактивации

**Файл:** `src/app/api/cron/deactivate-expired/route.ts`

```typescript
import { NextResponse } from 'next/server';
import { prisma } from '@/lib/prisma';

export async function GET(request: Request) {
  // Проверка авторизации cron (по секретному ключу)
  const authHeader = request.headers.get('authorization');
  if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
    return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });
  }

  const now = new Date();
  
  try {
    // Деактивация истекших Лаг
    const lagsResult = await prisma.lagType.updateMany({
      where: {
        expirationDate: { lt: now },
        active: true
      },
      data: { active: false }
    });

    // Деактивация истекших Столбов
    const postsResult = await prisma.postType.updateMany({
      where: {
        expirationDate: { lt: now },
        active: true
      },
      data: { active: false }
    });

    console.log(`[CRON] Deactivated ${lagsResult.count} lags, ${postsResult.count} posts`);

    return NextResponse.json({
      success: true,
      deactivated: {
        lags: lagsResult.count,
        posts: postsResult.count
      },
      timestamp: now
    });
  } catch (error) {
    console.error('[CRON] Error:', error);
    return NextResponse.json({ error: 'Internal error' }, { status: 500 });
  }
}
```

### 4.3 Сервис проверки дубликатов

**Файл:** `src/services/admin/duplicateCheckService.ts`

```typescript
interface LagDuplicate {
  id: string;
  name: string;
  basePricePerMeter: number;
  validFrom: Date | null;
  expirationDate: Date | null;
  active: boolean;
}

export async function findLagDuplicates(params: {
  width: number;
  height: number;
  metalThickness: number;
  length: number;
  excludeId?: string;
}): Promise<LagDuplicate[]> {
  const lags = await prisma.lagType.findMany({
    where: {
      width: params.width,
      height: params.height,
      metalThickness: params.metalThickness,
      length: params.length,
      ...(params.excludeId && { id: { not: params.excludeId } })
    },
    select: {
      id: true,
      name: true,
      basePricePerMeter: true,
      validFrom: true,
      expirationDate: true,
      active: true
    }
  });

  return lags;
}

export function checkPeriodOverlap(
  newValidFrom: Date | null,
  newExpirationDate: Date | null,
  existingValidFrom: Date | null,
  existingExpirationDate: Date | null
): boolean {
  // Если у существующей нет expiration - считаем бессрочной
  const existingEnd = existingExpirationDate || new Date('2099-12-31');
  const newStart = newValidFrom || new Date();
  const newEnd = newExpirationDate || new Date('2099-12-31');

  // Периоды НЕ пересекаются если:
  // newStart >= existingEnd ИЛИ newEnd <= existingValidFrom
  // Пересекаются если НЕ (не пересекаются)
  return !(newStart >= existingEnd || newEnd <= (existingValidFrom || new Date(0)));
}
```

```json
{
  "warning": {
    "type": "duplicate_params",

    "duplicates": [
      {
        "id": "existing-id",
        "name": "Профиль 40x20x2.0",

        "active": true
      }
    ],
    "suggestions": {
      "setExpirationForExisting": "2026-03-31T00:00:00.000Z"
    }
  },
  "canProceed": true
}
```

**Response 400 (цена не отличается):**
```json
{
  "error": "Розничная цена должна отличаться от существующих номенклатур с такими же параметрами",
```

```json

  "conflictingPeriod": {

    "expirationDate": null

}
```

## 9. Риски и зависимости

### 9.1 Технические риски

**Risk 1: Breaking change - удаление sortOrder**

**Category:** Technical  
**Probability:** High  
**Impact:** Medium

**Description:**
API перестанет возвращать sortOrder, что может сломать существующих клиентов.

**Mitigation:**
- Проверить все использования sortOrder в коде
- Убедиться, что фронтенд не зависит от этого поля
- Документировать breaking change

---

**Risk 2: Cron job не сработает**

**Category:** Operational  
**Probability:** Low  
**Impact:** High

**Description:**
Если cron job не сработает, истекшие номенклатуры останутся активными.

**Mitigation:**
- Настроить мониторинг cron job
- Добавить проверку expirationDate при GET запросе (fallback)
- Логировать результаты выполнения
