# Версионирование приложения

## Автоматическое управление версиями

Проект использует автоматическое управление версиями через GitHub Actions. Версия автоматически увеличивается и деплоится при слиянии PR в ветку `master`.

## Как работает

### Полный процесс

При слиянии PR в `master` автоматически запускается следующая цепочка:

1. **Bump Version** workflow:
   - Определяет тип изменения по названию PR
   - Увеличивает версию в `package.json`
   - Создает Git тег (например, `v1.1.0`)
   - Создает GitHub Release

2. **Deploy to VPS** workflow:
   - Запускается только после успешного завершения Bump Version
   - Деплоит изменения на VPS
   - Перезапускает приложение

### Автоматическое определение типа версии

Bump Version workflow определяет тип изменения по названию PR:

- `feat:` - новая функциональность → **minor** версия (1.0.0 → 1.1.0)
- `fix:` - исправление ошибки → **patch** версия (1.0.0 → 1.0.1)
- `feat!:` или `BREAKING CHANGE` - критические изменения → **major** версия (1.0.0 → 2.0.0)
- Если тип не определен → **patch** версия по умолчанию

### Примеры названий PR

```bash
feat: add mounting hardware management   # → 1.0.0 → 1.1.0 (minor)
fix: correct database connection error    # → 1.0.0 → 1.0.1 (patch)
feat!: breaking API changes              # → 1.0.0 → 2.0.0 (major)
refactor: improve code structure        # → 1.0.0 → 1.0.1 (patch, по умолчанию)
```

## Ручное управление версиями

Вы можете вручную запустить bump-version workflow:

1. Перейдите в GitHub Actions → Bump Version
2. Нажмите "Run workflow"
3. Выберите тип изменения версии:
   - **patch** - мелкие исправления
   - **minor** - новые функции
   - **major** - критические изменения

## Текущая версия

Версия хранится в `package.json` в поле `version`.

```json
{
  "version": "1.0.0"
}
```

## Деплой на VPS

Деплой на VPS происходит автоматически после успешного завершения Bump Version workflow. Также можно запустить деплой вручную через GitHub Actions → Deploy to VPS → Run workflow.

## Конвенция коммитов

Рекомендуется следовать [Conventional Commits](https://www.conventionalcommits.org/) для предсказуемого управления версиями:

- `feat:` Новая функциональность
- `fix:` Исправление ошибки
- `docs:` Изменения в документации
- `style:` Изменения в стиле кода (форматирование, точки с запятой и т.д.)
- `refactor:` Изменения в коде, которые не исправляют ошибку и не добавляют новую функциональность
- `test:` Добавление тестов
- `chore:` Обновление задач сборки, конфигураций и т.д.

Только `feat:` и `fix:` влияют на автоматическое определение версии.
