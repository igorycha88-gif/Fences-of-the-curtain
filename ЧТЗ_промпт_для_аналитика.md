# Лучшие практики написания промптов для аналитика

## 1. Основные принципы

### 1.1 Ясность и конкретность
- Используйте точные формулировки без двусмысленности
- Избегайте жаргона, если он не общепринят в контексте
- Определяйте все ключевые термины и понятия

### 1.2 Структурированность
- Разбивайте сложные задачи на логические блоки
- Используйте нумерацию и маркированные списки
- Группируйте связанные требования

### 1.3 Контекст
- Предоставьте необходимый背景 (background)
- Укажите цель анализа и ожидаемый результат
- Определите аудиторию отчёта

## 2. Структура эффективного промпта

### 2.1 Ролевая модель
```
Ты — аналитик с экспертизой в [область].
Твоя задача: [конкретная задача].
```

### 2.2 Контекст и ограничения
- Данные: какие данные доступны
- Ограничения: время, ресурсы, инструменты
- Формат: в каком виде нужен результат

### 2.3 Критерии успеха
- Что считается успешным выполнением
- Как будет оцениваться качество
- Приоритеты при конфликте требований

## 3. Ключевые элементы промпта

### 3.1 Входные данные
- Описание источника данных
- Формат и структура данных
- Объём и период анализа

### 3.2 Методология
- Требуемые методы анализа
- Метрики и показатели
- Глубина анализа

### 3.3 Выходные данные
- Формат отчёта
- Структура презентации
- Уровень детализации

## 4. Паттерны эффективных промптов

### 4.1 Chain-of-Thought (Цепочка рассуждений)
```
Проанализируй данные пошагово:
1. Сначала определи...
2. Затем оцени...
3. После чего сделай выводы...
```

### 4.2 Few-Shot (Примеры)
```
Пример анализа:
[пример входных данных]
[пример результата]

Теперь проанализируй:
[твои данные]
```

### 4.3 Self-Consistency (Самосогласованность)
```
Предложи 3 варианта анализа.
Сравни их преимущества и недостатки.
Выбери оптимальный и объясни выбор.
```

## 5. Специфика аналитических задач

### 5.1 Типы аналитики
- **Описательная** — что произошло
- **Диагностическая** — почему произошло
- **Предиктивная** — что может произойти
- **Прескриптивная** — что делать

### 5.2 Типичные ошибки
- Слишком абстрактные запросы
- Отсутствие критериев качества
- Нереалистичные ожидания по глубине
- Игнорирование ограничений данных

## 6. Чек-лист для проверки промпта

- [ ] Чётко определена роль аналитика
- [ ] Указана конкретная цель анализа
- [ ] Описаны входные данные
- [ ] Задан формат результата
- [ ] Определены критерии успеха
- [ ] Указаны ограничения
- [ ] Приведены примеры (если нужно)
- [ ] Структурирован ход рассуждений

## 7. Примеры промптов

### 7.1 Анализ бизнес-показателей
```
Роль: Ты — бизнес-аналитик с опытом в e-commerce.

Задача: Проанализировать динамику продаж за Q4 2024.

Данные: 
- Выгрузка из CRM (10000+ транзакций)
- Данные о маркетинговых кампаниях

Требования:
1. Определи ключевые тренды
2. Выдели топ-5 факторов роста
3. Рассчитай ROI по каналам

Формат: Executive summary + детальный отчёт с визуализациями
```

### 7.2 Исследовательский анализ
```
Роль: Ты — data analyst.

Задача: Провести разведочный анализ данных о пользователях.

Подход:
1. Первичный осмотр данных (quality check)
2. Описательная статистика
3. Поиск аномалий
4. Выявление паттернов
5. Формулировка гипотез

Результат: Notebook с комментариями и выводами
```

## 8. Рекомендации по итерации

1. **Начни с простого** — базовый промпт, затем уточняй
2. **Тестируй** — проверяй на небольших данных
3. **Документируй** — сохраняй рабочие версии
4. **Уточняй** — добавляй context на основе результатов
5. **Модулизируй** — создавай переиспользуемые компоненты

## 9. Декомпозиция задач

### 9.1 Принципы декомпозиции
- Разбивай задачу на атомарные подзадачи
- Каждая подзадача должна иметь чёткий результат
- Подзадачи должны быть независимы или иметь явные зависимости
- Указывай приоритет и последовательность выполнения

### 9.2 Структура декомпозиции в промпте
```
Задача: [общая задача]

Декомпозиция:
1. [Подзадача 1]
   - Вход: ...
   - Выход: ...
   - Критерий готовности: ...

2. [Подзадача 2]
   - Зависит от: Подзадача 1
   - Вход: ...
   - Выход: ...
```

### 9.3 Декомпозиция аналитических задач
| Уровень | Пример подзадачи |
|---------|------------------|
| Сбор | Получить данные из источника |
| Очистка | Обработать пропуски, дубликаты |
| Преобразование | Агрегация, нормализация |
| Анализ | Расчёт метрик, поиск паттернов |
| Интерпретация | Формулировка выводов |
| Визуализация | Создание графиков, отчётов |

### 9.4 Декомпозиция тестирования

#### Уровни тестирования для анализа
1. **Unit-тесты данных** — проверка отдельных полей и значений
2. **Integration-тесты** — проверка связей между таблицами/источниками
3. **E2E-тесты аналитики** — проверка всего пайплайна от сырых данных до выводов

#### Промпт для декомпозиции тестирования
```
Задача: Разработать тест-план для аналитического решения.

Декомпозиция:
1. Определить критические пути данных
   - Выход: список ключевых трансформаций

2. Выделить граничные случаи
   - Выход: список edge-cases для проверки

3. Составить тест-кейсы валидации данных
   - Формат: GIVEN [состояние] WHEN [действие] THEN [результат]

4. Определить метрики качества тестов
   - Покрытие данных (%)
   - Покрытие сценариев (%)

5. Создать regression-тесты
   - Выход: набор тестов для CI/CD
```

#### Шаблон тест-кейса для аналитика
```
ID: TC-[номер]
Название: [что проверяется]
Приоритет: High/Medium/Low
Тип: Валидация данных / Логика / Производительность

Предусловия:
- [условие 1]
- [условие 2]

Шаги:
1. [шаг 1]
2. [шаг 2]

Ожидаемый результат:
- [результат]

Тестовые данные:
- [пример данных или ссылка на датасет]
```

### 9.5 Чек-лист декомпозиции задачи

- [ ] Задача разбита на подзадачи (3-7 элементов оптимально)
- [ ] Каждая подзадача атомарна и измерима
- [ ] Указаны зависимости между подзадачами
- [ ] Определены критерии готовности для каждой подзадачи
- [ ] Выделены риски и неопределённости
- [ ] Спланированы тесты для каждой подзадачи
- [ ] Определены точки интеграции подзадач

### 9.6 Пример полной декомпозиции с тестированием
```
Задача: Анализ оттока клиентов за Q4 2024

Декомпозиция:

1. Сбор данных (Приоритет: High)
   - Выгрузить транзакции из БД
   - Выгрузить логи активности из analytics
   - Тест: проверить полноту данных (row count, date range)

2. Подготовка данных (Приоритет: High)
   - Объединить источники по user_id
   - Обработать missing values
   - Тест: validate schema, check null percentages

3. Определение оттока (Приоритет: High)
   - Сформулировать критерий оттока (нет активности 30+ дней)
   - Разметить пользователей
   - Тест: sample check 100 случайных пользователей вручную

4. Анализ факторов (Приоритет: Medium)
   - Рассчитать корреляции с оттоком
   - Построить сегментацию
   - Тест: cross-validation на train/test split

5. Визуализация и отчёт (Приоритет: Medium)
   - Создать дашборд
   - Написать рекомендации
   - Тест: review stakeholders, A/B презентации
```
