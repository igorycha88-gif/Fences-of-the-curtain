## 🚨 КРИТИЧЕСКИЕ ПРОБЛЕМЫ (P0 — блокируют продакшн)

### P0-1: Пароли хранятся в открытом виде

**Файл:** `src/lib/auth.ts`, строка 32

```typescript
// ТЕКУЩИЙ КОД — ОПАСНО!
const passwordMatch = user.password === credentials.password;
```

**Проблема:** Пароли сравниваются как plain text. Это означает, что пароли также хранятся в БД в открытом виде. Любая утечка дампа базы — полная компрометация всех аккаунтов.

**Исправление:** Использовать `bcrypt` или `argon2`:
```typescript
import bcrypt from 'bcryptjs';
const passwordMatch = await bcrypt.compare(credentials.password, user.password);
// При создании пользователя: await bcrypt.hash(password, 12)
```

**Риск:** КРИТИЧЕСКИЙ. Нарушает базовые требования информационной безопасности.

---

### P0-2: Отсутствует Next.js Middleware для защиты роутов

**Файл:** `middleware.ts` — **файл отсутствует!**

**Проблема:** Страницы `/admin/*` не защищены на уровне сервера через Middleware. Защита реализована только на стороне клиента (client-side redirect), что обходится прямым fetch-запросом к API.

**Исправление:** Создать `src/middleware.ts`:
```typescript
import { withAuth } from 'next-auth/middleware';
import { NextResponse } from 'next/server';

export default withAuth(
  function middleware(req) {
    const token = req.nextauth.token;
    if (req.nextUrl.pathname.startsWith('/admin') && !token) {
      return NextResponse.redirect(new URL('/admin/login', req.url));
    }
  },
  { callbacks: { authorized: ({ token }) => !!token } }
);

export const config = { matcher: ['/admin/:path*', '/api/admin/:path*'] };
```

**Риск:** КРИТИЧЕСКИЙ. Все API-эндпоинты `/api/admin/*` доступны без аутентификации через прямые HTTP-запросы.

### P0-3: Калькулятор использует захардкоженные цены

**Файл:** `src/services/calculator/fenceCalculator.ts`

```typescript
// ТЕКУЩИЙ КОД — захардкоженные данные!
materials.push({
  name: 'Профнастил С8',
  pricePerUnit: 450, // <-- жёстко задана цена
  ...
});
```

**Проблема:** Несмотря на наличие полноценных справочников в БД (`ProfnastilType`, `PostType`, `LagType` и др.) с системой управления ценами через админ-панель, основной калькулятор (`fenceCalculator.ts`) не использует данные из БД. Все изменения цен в админ-панели **не влияют на расчёты**.

**Исправление:** Переписать `fenceCalculator.ts` для получения цен из БД через Prisma, аналогично тому, как уже сделано в `fenceTypeCalculatorService.ts` (с кэшированием через Redis).

**Риск:** КРИТИЧЕСКИЙ для бизнеса. Клиенты получают некорректные расчёты.

## ⚠️ ВЫСОКИЙ ПРИОРИТЕТ (P1 — требуют решения до релиза)

### P1-1: Утечка информации в логах авторизации

**Файл:** `src/lib/auth.ts`, строки 22, 34, 37

```typescript
console.log('[AUTH] Looking up user:', credentials.email);
console.log('[AUTH] Password match:', passwordMatch);
console.log('[AUTH] Invalid password');
```

**Проблема:** Логи выводят чувствительные данные: email пользователя, результат проверки пароля. Это помогает атакующему при брутфорсе и утекает в системные логи (Docker logs, Nginx logs).

**Исправление:** Удалить все `console.log` с чувствительными данными, заменить на структурированное логирование без PII (Personal Identifiable Information).

---

### P1-2: Дублирование миграций в БД

**Директория:** `prisma/migrations/`

```
20260311162729_rename_base_price_to_retail_price_lag_type
20260311162736_rename_base_price_to_retail_price_lag_type   ← дубликат!
```

**Проблема:** Две миграции с одинаковым именем созданы с разницей в 7 секунд. Это свидетельствует о конфликте при разработке. На продакшн-среде одна из миграций может не примениться или применится дважды, что сломает схему БД.

**Исправление:** Проверить содержимое обеих миграций, объединить в одну, пересоздать с корректным именем и проверить целостность схемы через `prisma migrate status`.

---

### P1-3: Дублирование моделей данных (FenceMaterial vs. специфические типы)

**Файл:** `prisma/schema.prisma`

**Проблема:** В схеме присутствуют две параллельные системы хранения материалов:
- **Старая:** `FenceMaterial` (универсальная модель с `FenceMaterialCategory`)
- **Новая:** `ProfnastilType`, `PicketType`, `PostType`, `LagType`, `GateType`, `WicketType` (специализированные модели)

Обе системы активно используются в коде, что создаёт путаницу, дублирование данных и несогласованность состояния.

**Исправление:** Принять решение о переходе на новую модель, разработать план миграции данных и депрекейшн старой `FenceMaterial`.

---

### P1-4: Слабый пароль БД в docker-compose

**Файл:** `docker-compose.yml`, строка 44

```yaml
POSTGRES_PASSWORD=password  # ← слишком слабый!
```

**Проблема:** Пароль "password" — один из первых в любом словаре брутфорса. Порт PostgreSQL (5433) открыт наружу.

**Исправление:** Использовать сильный пароль (минимум 32 случайных символа), вынести в `.env`, закрыть порт БД от внешнего доступа (убрать `ports` для `db` в docker-compose).

---

### P1-5: Отсутствует Rate Limiting на API

**Проблема:** Redis подключён (`src/lib/redis.ts`), но rate limiting ни на одном API-эндпоинте не реализован. Калькулятор, форма контактов, авторизация — все открыты для флуда.

**Исправление:** Реализовать middleware с rate limiting для:
- `/api/auth/*` — max 5 попыток/минуту на IP
- `/api/calculator/*` — max 30 запросов/минуту
- `/api/contact` — max 3 запроса/час на IP

## 🏗️ СИЛЬНЫЕ СТОРОНЫ АРХИТЕКТУРЫ

Несмотря на критические проблемы, проект имеет хорошую структурную основу:

1. **Чёткое разделение слоёв** — Services / Validators / API Routes / UI Components реализованы правильно.
2. **Zod валидация** — все API-запросы валидируются через схемы, что предотвращает большинство injection-атак.
3. **RBAC система** — система ролей `ADMIN / MANAGER / CONTENT_MANAGER` спроектирована корректно.
4. **Аудит изменений** — `ReferenceChangeLog` и `AdminActionLog` обеспечивают полную историю действий.
5. **Redis кэширование** — правильная интеграция в `fenceTypeCalculatorService.ts` с TTL и fallback-логикой.
6. **Система приоритетов** — drag-and-drop сортировка справочников через `@dnd-kit` реализована продуманно.
7. **Docker-based деплой** — контейнеризация с Nginx, PostgreSQL и Redis организована правильно.
8. **Типобезопасность** — TypeScript + Prisma + Zod дают полную типовую цепочку от БД до UI.
