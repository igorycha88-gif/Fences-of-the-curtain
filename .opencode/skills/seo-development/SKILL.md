# 📕 SEO-разработка по книгам — обязательные правила

> Источник: аудит 2026-10-20 по 4 книгам (флешка KINGSTON, папка проекта):
> 1. **Косарев А.** «SEO-продвижение. 36 фильтров Google» (2019)
> 2. **Молочков В.** «Создание сайта, его SEO-продвижение и монетизация» (2022)
> 3. **Бардин С.** «Толковое руководство по SEO-продвижению» (2020)
> 4. **«SEO в эпоху ИИ»** (2024)

## 0. Когда применять (триггеры)

Любая задача, которая затрагивает: страницы (`page.tsx`), метаданные, URL/маршруты, тексты посадочных, гео-города, изображения в публичной части, sitemap/robots, JSON-LD, скорость загрузки, аналитику. Если в задаче есть слово «SEO» — скилл обязателен для Аналитика, Разработчика и Тестировщика.

---

## 1. Десять железных правил (нарушение = баг)

1. **Лимиты метатегов**: title ≤ 74 симв., description ≤ 160 симв. Константы `SEO_CONFIG.TITLE_MAX_LENGTH` / `DESCRIPTION_MAX_LENGTH` (`src/lib/seo/constants.ts`). Проверяется автотестом.
2. **Честный lastmod**: в sitemap ЗАПРЕЩЕН `new Date()`. Статика — из `SEO_CONFIG.CONTENT_LAST_UPDATED` (обновляется при контентном релизе), динамика — реальные `updatedAt` из БД.
3. **Один H1 на странице**, содержит ключ. H2 — разделы, H3 строго после H2, без пропуска уровней (Бардин, Молочков).
4. **alt изображений осмысленный**: 4–6 слов, что на фото + ключевое слово. ЗАПРЕЩЕНЫ alt «фото 1», «миниатюра 2». Пример: `Забор из профнастила С8 — работа в Балашихе, фото 2`.
5. **`next/image` в публичной части** (`fill` + `sizes`, priority только первому экрану). `<img>` допустим ТОЛЬКО для noscript-счётчиков 1×1 и в админке.
6. **Детерминированная вариативность** гео/шаблонного контента: выбор варианта по хэшу slug, ЗАПРЕЩЕН `Math.random()` (ломает ISR-кэш).
7. **Canonical на каждой индексируемой странице** через `generatePageMetadata()`. Пагинация/фильтры — canonical на базовую либо noindex.
8. **Уникальность гео-страниц**: города не клоны. Минимум: варьируемые FAQ/прайс/заголовки + локальный контент. Проверка: все title/description/FAQ городов уникальны (тест).
9. **SSL + скорость**: страницы отвечают < 3 сек (Косарев: пессимизация при 2–3 с). Новые публичные компоненты не тянут тяжёлые библиотеки в первый экран.
10. **Перелинковка**: каждая новая страница ссылается с релевантных существующих (анкоры с ключами, не «нажмите здесь» — Косарев, фильтр Gluing).

## 2. Чек-лист новой/изменяемой страницы

- [ ] URL: короткий, ЧПУ, с ключевым словом (`/otkatnye-vorota`, НЕ `/services?id=42`)
- [ ] Метатеги: title ≤ 74 (ключ ближе к началу), description ≤ 160 (цена/выгода + CTA)
- [ ] Один H1 с ключом; H2 по разделам; абзацы 3–7 строк (Молочков)
- [ ] Canonical + OG/Twitter-карточка (`generatePageMetadata`)
- [ ] JSON-LD по типу страницы (см. §4)
- [ ] Хлебные крошки (визуальные + BreadcrumbList)
- [ ] alt у всех изображений, next/image
- [ ] Ссылки на связанные страницы (внутренняя перелинковка)
- [ ] Внешние ссылки на авторитетные источники, где уместно (TrustRank, Косарев стр. 103)
- [ ] Включена в `sitemap.ts` с корректным lastmod
- [ ] Если страница служебная — `noindex`

## 3. Контент-требования (Panda, Косарев)

- **Уникальность > 90%** (Молочков). Никаких копий с других сайтов и между своими страницами (риск Omitted results / Panda на весь сайт).
- **Плотность ключей 3–5% максимум** — 1 ключ на ~100 слов в title/H1/начале/подписи к фото (фильтр Over Optimization).
- **LSI-слова**: синонимы и сопутствующие термины (для «забора»: столбы, лаги, профлист, погонный метр, калитка).
- **Цифры вместо прилагательных**: «обслужили 200 клиентов», а не «быстро развивающаяся компания». Штампы и клише («команда профессионалов») — минус к весу страницы.
- **Объём**: текст должен отвечать на запрос полнее конкурентов из топ-5. «Мало текста» = слабая страница.
- **Грамотность**: без орфографических/фактических ошибок.
- **Вопросные формулировки** (эпоха ИИ): FAQ-блоки под запросы «как», «сколько», «почему» — с разметкой FAQPage.
- **E-E-A-T**: реальный опыт (фото работ, цифры, кейсы), экспертиза (реквизиты, производство), то, что не сгенерирует ИИ.

## 4. JSON-LD разметка (schema.org)

| Тип страницы | Разметка |
|---|---|
| Все страницы | Organization/LocalBusiness (NAP: имя, адрес, телефон, ИНН, часы, geo — консистентно везде) |
| Услуга/посадочная | Service + Offer (цена/priceRange) + provider через `@id` |
| Гео-город | Service с `areaServed: City` |
| FAQ-блок | FAQPage (вопросы = реальные запросы) |
| Каталоги | ItemList + Product |
| Статья/блог | Article (datePublished, author, publisher) |
| Навигация | SiteNavigation, крошки — BreadcrumbList |

Запрещено дублировать LocalBusiness — только node reference по `@id`.

## 5. Гео-страницы (Pigeon/Possum — критично для локального бизнеса)

- NAP (имя/адрес/телефон) **идентичны** на сайте, в Яндекс.Бизнесе, картах — расхождения роняют локальный рейтинг.
- Телефон кликабельный (`tel:`), виден без скролла на мобильном.
- Страница города = УНИКАЛЬНЫЙ контент: локальный контекст, районы, доставка/расстояние, отзывы клиентов из этого города, кейсы по географии. Косарев стр. 150–151: «лучше одна сильная страница на город, чем множество коротких клонов».
- Ссылки на соседние города (перелинковка направлений).
- Отзывы: постоянный поток (не всплеск!), ответы на все — негативные и позитивные.

## 6. Технические требования

- **Sitemap** (`src/app/sitemap.ts`): все индексируемые URL; lastmod честный (см. правило 2); динамика из БД.
- **Robots** (`src/app/robots.ts`): `Disallow: /admin`, `Disallow: /api`; директива `Sitemap:`.
- **Редиректы**: смена URL — только 301 в `next.config.js redirects()`.
- **Скорость**: AVIF/WebP через next/image, immutable-кэш статики, TTFB < 500 мс.
- **Мобильность**: без горизонтального скролла, кнопки под большой палец (Mobilegeddon).
- **Валидность**: HTML без ошибок (W3C, фильтр 36).
- **Безопасность**: HTTPS, HSTS (рейтинговый фактор).

## 7. AI-SEO / AEO (цитируемость в ChatGPT, Perplexity, Google AI Overviews)

> По marketingskills/ai-seo (Princeton GEO, KDD 2024): статистика с источниками +37–40% к цитируемости; keyword stuffing −10%; структура важнее позиции — цитируют и со 2-й страницы выдачи.

Обязательно для статей, посадочных и гео-страниц:

1. **llms.txt и ceny.md актуальны** при каждом контентном релизе: новые страницы/цены → обновить `public/llms.txt` и `public/ceny.md` (машиночитаемый прайс для ИИ-агентов).
2. **Freshness**: `dateModified` в Article JSON-LD + видимая дата «Обновлено: …» на статьях. Не актуализировал контент — не меняй дату.
3. **Статистика с источниками**: конкретные цифры + ссылка на первоисточник (СП 20.13330 для снеговых нагрузок, ГОСТ для материалов). «Мы лучшие» не цитируют; «180 кг/м², III район по СП 20.13330» — цитируют.
4. **Answer-блоки 40–60 слов**: каждая секция начинается с прямого ответа, работающего без контекста страницы. Заголовки = формулировки реальных запросов.
5. **Сравнения — таблицами**, процессы — нумерованными списками (извлекаемость для ИИ).
6. **AI-боты в robots.ts — осознанная политика** по группам: search-discovery (OAI-SearchBot, PerplexityBot, Claude-SearchBot), user-triggered (ChatGPT-User, Claude-User, Perplexity-User), training (GPTBot, ClaudeBot). Не блокировать discovery-ботов без решения владельца.
7. **ЗАПРЕЩЕН отдельный «контент для ИИ»** и дробление страниц под ИИ (Google: scaled content abuse). Один контент — людям и ИИ.
8. **E-E-A-T для ИИ**: первый опыт (реальные фото/кейсы), реквизиты, консенсус третьих лиц (отзывы на картах совпадают с формулировками сайта).

## 8. Анти-паттерны (ЗАПРЕЩЕНО)

| Запрет | Фильтр/причина |
|---|---|
| `Math.random()` в генерации контента | нестабильный ISR-рендер |
| `new Date()` как lastmod в sitemap | обесценивание lastmod |
| Keyword stuffing («SEO-каша») | Over Optimization, фильтр —30 |
| Клон-страницы городов/услуг с подстановкой слова | Panda, Omitted results |
| alt «фото N» | Бардин: alt = описание |
| `<img>` в публичной части | скорость/LCP |
| Битые ссылки на проде | Broken Links (фильтр 7) |
| Реклама/баннеры в первом экране | Top Heavy, Page Layout |
| Штампы «команда профессионалов с большим опытом» | Panda: пустые фразы |
| Скрытие адреса компании | Pigeon: «есть что скрывать» |

## 9. SEO-чек-лист Тестировщика (помимо стандартного)

1. Автотест: лимиты title/description по ВСЕМ записям `PAGE_METADATA` + генераторам.
2. Автотест: уникальность генерируемого контента (Set по всем городам = 100%).
3. Автотест: детерминированность (повторный вызов = идентичный результат).
4. Визуально: H1 один, alt осмысленные, canonical присутствует.
5. `curl` прода: sitemap lastmod ≠ сегодня (для статики), robots закрывает /api, `/llms.txt` и `/ceny.md` отвечают 200 и содержат актуальные цены/ссылки.
6. Lighthouse/PageSpeed ключевых страниц (опционально, для новых посадочных).
7. AEO: Article содержит `dateModified`, на статьях видна «Обновлено», статистика в тексте — со ссылкой на источник.

## 10. Организационные меры (вне кода — напоминает Аналитик в ЧТЗ)

- После деплоя: пересдать sitemap в Яндекс.Вебмастере и GSC, переобход ключевых страниц.
- Мониторинг: Вебмастер → «Исключённые страницы» (не растут ли дубли), Метрика → поисковые фразы.
- Отзывы на Яндекс.Картах/Бизнесе — регулярно запрашивать у клиентов.
- Контент-план: новые статьи под информационные запросы из Wordstat (freshness — TrustRank).
